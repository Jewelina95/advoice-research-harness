# Evidence Governance 会议意见回应框架

## 1. 会议意见实际上提出了什么

会议意见不是要求再画一张相关矩阵，也不是要求先证明“约 100 个特征是正确的”。它提出了六个需要分别验证的问题：

1. **证据集合是否必要且不过度重复**：为什么选择这些特征；是否存在公式重复、同源重复、统计重叠或临床含义重叠；删除冗余后是否损害性能与医学覆盖。
2. **Evidence Governance 是否真的改变判断**：治理是否能阻止重复计票、错误证据、不可观察证据和低质量证据进入结论，而不仅是把输入重新排版。
3. **稳定性、准确性与证据忠实性是否同时成立**：无关措辞变化时结果是否稳定；真实证据改变时结果是否相应改变；相对标签或临床参照是否正确。
4. **所谓“大模型内部过程”能够被证明到什么程度**：闭源模型只能通过输入干预和输出变化证明行为依赖，不能把模型生成的解释当作内部思维轨迹；若研究神经内部表示，需要另用开放权重模型。
5. **跨数据库、跨语言、少样本与数据污染是否得到控制**：随机划分不能证明基础模型预训练时未见数据，需要留一数据库、时间外或私有前瞻数据验证；会议中的“64”必须先确认指 64 个特征还是 64 个治理案例。
6. **Trace Map 是否是实际执行记录**：报告结论必须能追溯到状态、指标、片段和源文件；删除或修正源证据后，所有依赖节点必须重算或失效。

## 2. 工作为什么要分成两部分

### A. 不依赖 Agent 结果的理论与数据层研究

这部分研究证据体系本身，当前即可完成：

- 历史 179 个名称、当前 37 个运行指标和编码器高维表示的边界与来源映射；
- 公式恒等、互补关系、同源路径、仿射等价和分层高相关分析；
- 声学、语言、对话、互动和任务表现构念的覆盖审计；
- 不同数据库、语言和任务中的可观察性检查；
- 有效秩、特征选择稳定性、特征数量—性能—校准曲线；
- 数据泄漏、缺失值、角色信息、任务模板和预训练污染的验证协议；
- Evidence Governance 的可执行规则和 Trace Map 数据结构。

这部分可以回答“证据集合是否合理”“为什么不能简单恢复一百多个特征”“哪些构念缺失”“哪些指标只是同一信息的不同写法”。它不能回答治理是否提高 Agent 的诊断结果。

### B. 必须依赖固定 Agent 与运行日志的验证

这部分必须等 Agent 版本、提示、技能、模型参数和测试集冻结后执行：

- 同一病例在无治理、结构化证据包、权限治理和完整重算治理下的成对比较；
- 改写、重排、重复、插入无关证据、删除关键证据和纠正错误证据的干预实验；
- 判断稳定性、诊断准确性、校准、拒判和证据忠实性；
- 跨模型与跨语言输出漂移；
- 留一数据库外部验证与固定预算少样本学习曲线；
- 从真实日志生成 Trace Map，并验证撤销传播和完整重算一致。

这部分才能回答“LLM 是否听从 Evidence Governance”“稳定性是否以灵敏性下降为代价”“治理是否提高准确率”“未见数据库上是否仍然有效”。

## 4. 当前结果的实际用途

特征数量曲线的用途不是给出一个新的固定数字，而是否定“特征越多越全面”这一未经验证的假设。它与映射、重叠和有效维数分析组合后，提供三个工程决策：

1. 把公式互补和同源指标合并为信息家族，避免重复计票；
2. 按图片描述、结构化访谈、复杂认知任务和自由讲话分别选择证据，而不是使用统一数量；
3. 保留临床覆盖需要但预测边际贡献较低的指标，同时限制其风险权重和报告权限。

因此，本轮结果建立的是 Agent 实验之前的证据输入基线。如果不先完成这一步，后续即使 Agent 准确率提高，也无法判断增益来自治理、重复特征、任务泄漏还是数据协议。

## 5. 下一阶段需要验证的核心主张

下一阶段不再继续用静态相关性替代治理验证，而是检验四个可证伪主张：

- **非重复性**：复制同一证据不应显著改变风险或报告强度；
- **必要性**：删除真正关键证据时，相关状态和判断应按预期减弱；
- **修订一致性**：纠正源指标后，增量更新应与从头重算得到相同结果；
- **跨域保持性**：上述性质应在留出的数据库、语言和任务中保持，并与准确率、校准和拒判同时报告。

语言漂移也要拆成两类。特征层语言漂移可以在 Agent 之前检查，例如同一构念在英语、普通话和西班牙语中是否可计算、分布是否改变。表达层与判断层语言漂移必须在固定 Agent 上，通过等义跨语言病例和证据包进行成对测试。
