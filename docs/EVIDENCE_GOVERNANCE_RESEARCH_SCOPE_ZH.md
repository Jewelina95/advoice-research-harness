# Evidence Governance：研究范围与可验证性分析

日期：2026-09-17。

本备忘录原始范围：背景研究、当前实现核查和研究设计建议。不训练、不修改预测实现、不生成新性能结果、不绘图。首次核查基于 `audit/system-reliability` 的 `fd9f757` 附近实现。后续独立审查在 `main` 的 `c194ec0` 重新核查了重叠、撤销、QC 残差化与预测路径问题；本轮研究分支为 `research/evidence-governance-overlap`。进一步实测与计划见 [研究计划](EVIDENCE_GOVERNANCE_STUDY_PLAN_ZH.md)，不把工作区的新工具误当已经接入生产的方法。

## 1. 核心判断

项目应研究的不是“解释是否足够详细”，而是：**在任务、语言、录音条件和模型变化时，认知筛查结论是否真正受到可核验、不过度重复、允许修正的患者证据约束。**

Evidence Governance 在这里应有明确的操作定义：管理证据的来源、适用范围、依赖关系、使用权限和修订传播，并检验这些管理动作是否改变实际计算。它不是给一段提示词换名称，也不是把证据 ID 放进报告就完成了论证。

必须分开五种主张：

| 主张 | 真正需要的证据 | 不能用什么替代 |
| --- | --- | --- |
| 来源可追溯 | 找到原始音频、时间段、角色、提取器、参考集和版本 | 有一张漂亮的 trace map |
| 规则可执行 | 禁止的证据不能经过其他路径影响获准的输出；撤销动作可重放 | Agent 说“我已忽略” |
| 模型使用忠实 | 对证据进行受控干预，观察实际状态、预测和报告如何响应 | LLM 自己写的推理解释、注意力权重 |
| 判断稳定 | 无关表述变化不引发不合理变化；相关事实变化仍能改变判断 | 总是输出同一类别，或全部回退给监督模型 |
| 临床有效 | 独立标签、适当终点、外部病例、校准和最终使用效果 | 稳定性、合规率、解释完整度 |

本项目目前可以论证部分来源与规则检查，不能据此直接宣布后三项已经成立。特别是“语音筛查标签预测正确”不等于“已证明 AD 病理诊断”。

## 2. 背景研究：哪些工作真正相关

### 2.1 许胥海相关工作

用户提供的论文第一作者是 Xuhai “Orson” Xu。已通过其个人主页及实验室出版物页核对身份；下面区分正式研究、设计观点和界面研究，不把它们都描述成 Nature 的内部机制实验。

| 工作 | 研究证据与边界 | 本项目可借鉴的方向 |
| --- | --- | --- |
| [Divergent impacts of explainable AI for dermatological diagnosis on clinicians versus lay people，Nature Medicine，2026](https://www.nature.com/articles/s41591-026-04553-w) | 623 名普通用户、153 名基层医生参与两项研究。LLM 解释对不同人群效果不同，错误建议可能诱发过度依赖；研究对象是人机协作，不是神经元内部机制。 | 报告是否可信不能只看说服力。区分 AI 正确/错误时用户是否适当采纳，区分医生端和患者端。 |
| [A framework for longitudinal health AI agents，Nature Health，2026](https://www.nature.com/articles/s44360-026-00141-x)；[可读作者预印本](https://arxiv.org/html/2604.12019v3) | 设计观点提出一致性、连续性、适应性和自主权四个层面，不是 AD 准确率实验。 | 保留事实与解释的区别、假设修订历史和责任边界。不能把一次录音中的片段轨迹当成纵向随访证据。 |
| [MIND，CHI 2026](https://arxiv.org/abs/2601.14641) | 5 名临床人员参与共创，16 人用户研究；叙述与底层图表联动，主要证据是临床人员感知的支持效果。 | 让报告主张直接定位到数据，而不是另附一张无关轨迹图；不能把可用性改善写成诊断准确率改善。 |

Nature Medicine 研究的普通用户与医生任务并非完全相同，不能把两组差异简单归因于专业程度。它对本项目的启发是需要评估解释的使用后果，而不是已证明某种 Evidence Governance 有效。当前没有医生评估数据，就把人机协作列为后续验证，不能用 Agent 评分冒充医生结果。

### 2.2 内部解释与因果使用的依据

- [Concept Bottleneck Models，ICML 2020](https://proceedings.mlr.press/v119/koh20a.html)：通过中间概念预测标签，并允许修改概念后传播到输出。它支持“状态可干预”的设计，但其概念监督与实验不能直接视为我们已有的状态验证。
- [Towards Faithfully Interpretable NLP Systems，ACL 2020](https://aclanthology.org/2020.acl-main.386/)：解释看起来合理与忠实描述模型行为是不同标准。我们的报告可读性和模型证据使用必须分别测量。
- [Language Models Don't Always Say What They Think，NeurIPS 2023](https://proceedings.neurips.cc/paper_files/paper/2023/file/ed3fea9033a80fea1376299fa7863f4a-Paper-Conference.pdf)：输入偏置可以影响答案，而生成的解释不一定承认这些影响。不能用 LLM 自述当内部过程记录。
- [Circuit Tracing，2025](https://www.transformer-circuits.pub/2025/attribution-graphs/methods.html) 与 [On the Biology of a Large Language Model](https://www.transformer-circuits.pub/2025/attribution-graphs/biology.html)：在可访问模型内部的条件下建立归因图并做干预。它提供局部机制研究方法，而非完整读取模型思维的保证。

建议主线研究系统级可执行证据路径；开放权重模型的激活探测和干预可以成为后续机制子研究，不应成为本轮工程的前置条件。探针能解码某个状态，只说明信息可读出，不证明模型决策使用了它。

## 3. 当前系统：实际核查结果

当前主要计算链是：任务/角色/语言处理 → 指标及证据对象 → 训练折内参考校准与状态 → 监督预测 → 首轮不见监督概率的 Agent 证据评分和状态审查 → 校准/门控决定是否接受修正 → 锁定结果后生成报告。不是所有运行入口都完全一致，正式研究必须冻结唯一入口及依赖版本。

### 3.1 “100 个 feature”还不是统一口径

| 实际检查对象 | 本轮统计 | 解释 |
| --- | ---: | --- |
| 历史 `clinical_metric_dictionary_clean_2026-06-18.csv` | 180 行、179 个不同 metric_name | 历史候选字典，不等于当前模型输入 |
| 当前 `configs/metrics/audio_metrics.yaml` | 37 个定义 | 7 个 QC、13 个 clinical_support、13 个 model_auxiliary、4 个 cautious_support |
| 当前知识 `EVIDENCE_REGISTRY.csv` | 38 行 | 知识登记表，不等于运行特征表 |
| 当前状态配置 | 14 个状态定义 | 不等于每个病例能观察到 14 个状态 |
| 当前按数据配置筛选后的基础指标 | 每任务配置 26–33 个 | 包含 QC；不包含完整任务展开、MFCC、所有辅助表示维数；不代表每项都非缺失 |

核查来源：[运行指标](../configs/metrics/audio_metrics.yaml)、[知识登记表](../skills/ad_evidence_diagnostic/EVIDENCE_REGISTRY.csv)、[状态配置](../configs/states/audio_states.yaml)、[配置加载](../src/advoice/config.py)。统计使用 CSV/YAML 解析器，不是从 HTML 中推断数量。

按当前配置：ADReSS 32、ADReSSo diagnosis 28、ADReSSo progression 28、Pitt 33、PublicFigures 30、IAEAV 33、NCMMSC 28、PREPARE 33、PROCESS-2 32、TAUKADIAL 26。这里是可配置定义数，不是独立统计信息数，也不是某次训练的最终列数。

当前特征提取还生成 MFCC 等辅助数值，任务展开也会增加列数。因此不能把 37 写成系统全部输入数，更不能把 179 写成全部已启用指标。后续需要建立“候选定义 → 可计算 → 当前任务启用 → 实际进入模型 → 可进入报告”五级台账。

### 3.2 已发现可明确解释的重叠

[features.py 第 280 行附近](../src/advoice/features.py) 使用 `silent = ~voiced`，同一帧集合上的 `silence_fraction + voiced_fraction = 1`。这不是两种独立信息。它们可以有不同展示用途，但不能作为相互独立的佐证。

[audio_states.yaml](../configs/states/audio_states.yaml) 中，`long_pause_rate_min` 同时进入 S01 和 S03，`voiced_fraction` 同时进入 S02 和 S03。共享测量不一定错误，但证据图应标明共同来源；不能把多个状态都异常等同于获得了多份独立患者证据。

[models.py 的 `_branch_specifications`](../src/advoice/models.py) 对重复列名去重，[diagnostic_agent.py 的 `_deduplicate_evidence_registry`](../src/advoice/diagnostic_agent.py) 对 `(evidence_id, evidence_type)` 去重。这两种操作均不等于消除了互补公式、相关指标或同一事件跨状态复用的重复信息。

### 3.3 “正交化”现有实现的真实含义

[QCOrthogonalizer](../src/advoice/models.py) 在训练折内用 Ridge 拟合 QC 与状态的关系，再取状态残差。这是控制部分 QC 可预测成分，不是证明所有指标互相正交，不保证非线性独立，也不能证明设备混杂已完全消除。

部分“质量”变量也可能携带真实的任务或患者行为信息。例如当前音频可靠度启发式使用发声占比；发声少既可能是录音不足，也可能是患者行为。它的作用需要单独审查。机械地减掉全部相关成分可能同时减掉有用信号，不能把统计残差直接命名为纯疾病成分。

### 3.4 状态撤销尚未形成完整的预测重算

[cognitive_agent.py 的 `_state_update_factor`](../src/advoice/cognitive_agent.py) 把 keep/downweight/invalidate 等动作转成修正权限因子。现有审查确认，这不会重新执行已经计算的状态监督预测。代码做的是约束 Agent 修正路径，不是删除旧先验中已经使用的相关信息。

[Skill 的回退协议](../skills/ad_evidence_diagnostic/COGNITIVE_ROLLBACK_PROTOCOL.md) 已经描述了重算受影响状态的目标。**设计说明写到了，不代表执行链已经做到了。** 这是当前最直接影响可证明性的缺口，详见 [SYSTEM_REVIEW.md](SYSTEM_REVIEW.md)。

### 3.5 权限定义不能当成已验证的医学正确性

配置中的方向、可靠度和临床角色是当前设定；不是由名称自动获得的金标准。`manifest.json` 仍将知识库标为 initial，并注明需逐指标核验原始文献。研究中需分别验证：测量是否准确、是否反映目标构念、该构念是否有增量预测价值、报告表述是否超过证据。

## 4. Proof generation 应该生成什么

建议用“可核验的证据与决策记录”，而不是承诺生成“患者患 AD 的数学证明”。能确定性验证的是来源、运算、依赖和权限；从语音行为到疾病标签仍是统计推断。

每次运行生成一个机器可读记录，至少有：

1. **输入身份**：病例匿名 ID、源文件哈希、任务、语言、角色、片段时间范围、可观测条件。
2. **测量记录**：指标定义及单位、提取器版本、原始值、测量误差/缺失、同源证据组。
3. **参考记录**：参考对象 ID 集的哈希、任务/语言适用范围、训练折、校准版本。
4. **推断边**：何种指标经哪项公式进入哪个状态，哪些是实算边、统计预测边或待检验的解释。
5. **候选与审查**：Agent 引用了什么、提出什么状态修改、反证有哪些、检查器接受/拒绝了什么以及原因。
6. **重放结果**：被修改节点及全部受影响后代、重算前后状态和预测、保持不变的分支、失败/回退原因。
7. **报告映射**：每一句实质性临床主张对应已授权证据；不允许报告模型另加无法定位的疾病依据。

数值、ID、权限、版本检查由确定性程序完成，不只依赖另一个 LLM 表示赞同。语义蕴含和临床适当性不可能仅靠 JSON 校验完成；这部分必须单列评估，不能标成已经形式化证明。

### 示例：撤销一项错误停顿证据

以下为流程示例，不是新跑出的患者结果。

一段图片描述中，检测器把工作人员等待及提示时间计入患者停顿。系统得到异常静音比例，并将其用于 S01、S02/S03 的相关测量。Agent 检查说话人及时间证据后，提出“该段不是患者停顿”的修改。

可核验流程应是：确认角色工具的依据 → 修改受影响帧的适用范围 → 重新测量静音/发声及有关时长 → 重算所有依赖状态 → 执行冻结的状态预测器与融合 → 记录概率向量变化 → 根据新结果生成报告。

不应强制最终类别一定变化：其他证据可能足够强。但必须证明修改已实际传递，而不是只改报告措辞。

还必须区分两类干预：

- **局部状态干预**：只改状态，冻结音频/文本表示，用于隔离状态分支效应。
- **源证据纠正**：若删除一段音频或纠正角色，就重算依赖这段源数据的所有表示、指标和状态。否则深度表示分支仍可能保留同一信息。

后一项尤其重要：只删 StateCard 的引用，不能声称整个系统不再使用了该音频证据。若保留黑箱辅助分支，必须明确其贡献不被临床证据解释完全覆盖；不能为了“完整可解释”而隐藏它。

## 5. 如何研究 LLM 内部，而不把解释当事实

系统内部与基础模型内部是不同层面。

**系统层面可以直接做**：固定模型、版本、输入数据及监督先验，干预证据包，记录候选评分、工具调用、状态修订、门控与最终输出。它研究“系统行为是否受证据控制”。

**普通闭源 API 层面不能直接做**：读取所有隐藏激活、删除某个神经回路，或者证明真实内部推理链。输出 token 概率、模型自己写的理由、热力图均不能单独填补这一缺口。

**开放权重的后续子研究可以做**：在证据字段对应的输入位置和特定层记录激活，对匹配病例进行激活替换或局部消融，检查被探测的状态信息是否实际影响判断。需随机层/位置、无关概念、同义表述等对照；局部机制结果不能外推为全部模型或闭源 GPT 的机制。

主论文不应以“解释 GPT 脑内全过程”为交付目标。更可执行的目标是：让获准决策经过显式证据接口，并用干预验证接口的实际作用，同时承认尚未解释的辅助部分。

## 6. 稳定性与准确性必须一起检验

稳定性的合理定义是“对无关改变稳定，对相关证据改变敏感”，不是所有输入都输出相同结论。

| 扰动/实验 | 保持什么不变 | 观察什么 | 失败意味着什么 |
| --- | --- | --- | --- |
| 描述改写、顺序改变 | 患者事实、数字、权限、参考集 | 概率差异、类别翻转、证据主张变化 | 表述驱动判断 |
| 重复证据加入 | 同一源事件及实际信息量 | 评分和置信度是否被重复放大 | 重复计票 |
| 不允许的 QC 证据 | 患者相关事实不变 | 是否被升级为疾病依据 | 权限约束无效 |
| 可靠度改变 | 指标值不变，改变有依据的测量质量 | 信任范围、拒判和修正幅度 | 无视质量，或机械改变疾病方向 |
| 真实证据纠正 | 预先规定的其余证据固定 | 后代重算、预测及报告一致性 | 状态维护只是文字 |
| 重要证据缺失 | 缺失状态清晰标注 | 是否承认不可观察，而非视为正常 | 缺失导致假阴性或伪确定性 |
| 无效/矛盾证据 | 请求内容可解析但无临床支持 | 拒绝、定位冲突、保留有效部分 | 格式通过被误当语义正确 |

“语言漂移”还要分两种：给证据包换表述，与患者真的换一种语言表达。前者可做同一信息的稳定性测试；后者涉及分词、句法、任务参考和群体差异，不能混在同一个指标里。

不要让 LLM 重写患者原始转录后再要求预测不变。词汇选择、重复、修正和句法本来就是研究信号；这样的改写可能改变临床相关内容。ASR 错误或背景噪声也应作为测量鲁棒性实验，不是假定无影响的改写。

最少同时报告：类别翻转率、概率向量变化、错误主张率、失效证据残留率、重放一致率、拒判/回退比例，以及 accuracy、类别召回、AUROC、Brier/log-loss。概率变化可用总变差距离 `0.5 * sum(abs(p_original - p_variant))`，以病例为统计单位。

重复运行的多个版本不是独立患者。置信区间需以患者成组计算。报告全部病例与“Agent 实际参与修正”病例的结果，避免高回退率让系统看似稳定。更高拒判率也不能不加覆盖率说明就宣称更安全。

## 7. 为什么选这些特征，而不是必须选 100 个

目标应是找到**适用条件明确、测量可靠、信息不过度重复的紧凑证据集合**。不同任务可以使用共享核心和有限扩展，不要求所有任务采用完全相同的列。

完全正交不是合理的硬目标。认知困难可能同时影响停顿、词汇提取和对话支持需求；删掉所有相关性会破坏有价值的联合模式。PCA 或残差化制造的数学正交也不自动等于临床维度独立。

建议按以下顺序分析，不以任意相关阈值直接大规模删列：

1. **定义级审查**：统一公式、单位、分母和事件来源。先找完全重复、互补、同一事件的多个别名；把同源复用显式连接。
2. **任务/语言内的统计重叠**：训练分区内检查相关聚类、非线性依赖、缺失模式；不要让跨数据集均值差异制造虚假相关。
3. **联合价值**：按相关组删除/加入并重新训练，检查条件增量价值。只做逐列删除可能因其他列补偿而误判“全无价值”。
4. **稳定选择**：重采样和内层验证中检查入选频率、类别召回、校准和复杂度曲线；对高度相关组优先报告组稳定性。
5. **外部验证**：冻结选择规则后验证新任务、语言或来源；若减到更少的特征无实质损失且更稳，就接受更小的集合。

可使用 [mRMR](https://pubmed.ncbi.nlm.nih.gov/16119262/) 作为低冗余候选选择基线，使用 [Stability Selection](https://arxiv.org/abs/0809.2932) 思路检查重复抽样稳定性，但二者都不是临床必要性的证明。所有参考拟合、去冗余、特征选择、降维和阈值选择必须放在训练边界内部。

“对 accuracy 没有提升”不等于完全没用。QC 指标可以只用于发现输入失效；报告索引可以只用于定位原音频。应删除或降级的是没有被验证的目标用途，而不是把所有非预测变量全部删除。

## 8. 预训练污染与少样本主张

独立受试者划分只证明项目训练过程没有使用那些受试者，不证明基础 LLM、ASR 或编码器从未见过相同音频、转录或其公开版本。也不能反过来在没有证据时断言它们肯定见过。

[Oren 等，ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/hash/46e624c244cff669223d488defd4e835-Abstract-Conference.html) 提出利用规范样本顺序与打乱顺序的似然差异检测污染。该方法有假设与访问要求，不是任何语音数据或 API 都能直接使用；检验阴性也不等于完全无污染。

本项目需要分别登记：受试者/来源交叉、预处理和参考拟合范围、基础模型训练数据透明度、公开数据发布时间、官方测试集被查看的历史。匿名化和删除诊断文件名只能减少显式线索，不能证明消除了记忆。

较强验证来自模型版本冻结后新采集、未公开且有明确授权的病例，并排除机构/受试者重叠。已多次查看的公开测试仍可作为回顾性 benchmark，不能包装成从未使用的确认集。

少样本优势应画学习曲线，而非选择一个最好的小样本结果。比较同一模型、同一患者划分下结构化输入与治理机制在不同样本预算的表现，重复抽样；区分 in-context 示例数、监督训练病例数、校准病例数。是否更省 token、成本或延迟也必须实测，证据包装本身可能增加开销。

## 9. 建议的最小研究范围

主问题：**可执行的证据治理能否在不牺牲预测质量的条件下，降低无关表达扰动、重复信息和失效证据导致的判断偏移，并提高证据纠正的有效性？**

主研究保持现有编码器、参考数据、模型版本与终点不变，比较：

| 条件 | 用途 |
| --- | --- |
| 同模型 + 同批指标的非结构化输入 | 基础表达方式对照 |
| 同模型 + 结构化证据包，但无可执行治理 | 隔离结构化格式的作用 |
| 同模型 + 证据包 + 可执行验证及重放 | 测治理机制增量 |
| 同上 + 训练内筛选的精简证据集 | 测复杂度是否确有必要 |
| 冻结监督预测 | 检查 Agent 的实际增益与回退掩盖 |

需要控制可见事实、工具权限、候选动作、参考数据和预算，防止某条件只是获得了更多数据或更多调用机会。上述条件用于机制研究，不替换既有 B1/B2/B3 的完整性能评估。

先用少量开发病例验证实验本身能检测已知失效，再冻结正式协议。开发病例覆盖当前真实存在的任务、语言和标签组合，不人为制造缺失的组合；小规模结果仅用于可行性。正式样本量取决于希望检测的翻转率/准确率差异与事件发生率，不能默认几十例足够。

SpeechCARE 可保留为同协议预测比较，但不是 Evidence Governance 内部机制的唯一或充分对照。其方法包含 LLM 辅助预处理，不能写成“完全没有 LLM”；核心分类是多模态编码及自适应门控。与其分数接近并不能证明我们治理有效，超过其分数也不能代替上述机制验证。[SpeechCARE 原文](https://www.nature.com/articles/s41746-025-02026-x)

## 10. 未来图的范围，暂不绘制

可将声学行为、语言表达、对话互动画成三条平行的数据分析分支，但它们不是三个统计独立的疾病证据源。词汇和对话也共享转录；没有工作人员角色和轮次的独白不具备完整互动观测。

建议将来画“可执行证据依赖图”：原音频/转录 → 共享测量节点 → 状态节点 → 推断/修订 → 报告主张。不同线型区分计算依赖、统计关联和待验证解释；被撤销的节点应展示真实重算影响。边宽只能来自定义明确、可复现的量，不能拿 gate weight 直接充当因果贡献。

这是系统信息流图，不是 LLM 神经回路图。雷达图只能作为病例认知表现概览，不能证明维度独立；不可观察维度不能填成正常 0 分，正常参考必须与任务、语言及校准来源匹配。

## 11. 下一步交付顺序

1. 统一特征和证据台账：历史候选、当前实现、任务展开、模型实用列、报告权限一一对应，并标记同源组。
2. 在少量开发病例上建立可重放的撤销测试，先解决“证据变了但旧预测路径没重算”的缺口。
3. 建立改写/顺序/重复/失效证据/缺失的配对测试，明确哪些变化应不变，哪些变化应触发合理修订。
4. 用训练内特征选择与组级验证比较完整和精简证据集，保存失败候选，不根据公开测试成绩来删改。
5. 冻结协议后做跨基础模型、任务和语言验证，报告稳定性、准确性、覆盖率与成本，不只选改善的指标。
6. 依据实测依赖关系制作论文图和 trace map；临床用户评估作为有真实参与者后的独立阶段。

本备忘录中的实验设计为待验证方案。本轮核查得到的是配置数量、公式依赖和现有执行边界，没有生成稳定性、正交性、准确率改善或医生使用效果的新数据。
