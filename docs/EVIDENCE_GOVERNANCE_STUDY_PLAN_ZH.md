# Evidence Governance 底层研究计划

状态：已启动。代码基于 `main` 的 `c194ec0`，研究分支 `research/evidence-governance-overlap`。不改历史数据或正式预测实现，不根据官方测试结果筛选指标。

进度：候选台账、历史显式列引用、当前状态映射和四份特征表的训练分区描述性分析已完成；依赖图验证器和反例测试已实现。第二轮结构审计已运行仿射等价、相关连通簇、任务路由别名和有效维数。理论对象、治理不变量、条件命题和可证伪假设已形成 [理论框架](EVIDENCE_GOVERNANCE_THEORETICAL_FRAMEWORK_ZH.md)。179 项逐项定义等价审定、真实 pipeline 撤销重算、嵌套特征选择与 Agent 增益实验未完成。见 [初步结果](EVIDENCE_GOVERNANCE_INITIAL_FINDINGS_ZH.md)、[结构实证结果](EVIDENCE_GOVERNANCE_FEATURE_STRUCTURE_PILOT_ZH.md) 和 [会议意见研究协议](EVIDENCE_GOVERNANCE_MEETING_COMMENTS_PROTOCOL_ZH.md)。

## 要回答的主问题

我们是否把同一个患者信息重复当作多份支持？当证据发生纠正，实际计算是否同步改变？什么样的精简证据集合能保持预测质量并降低错误证据和措辞的影响？

“逻辑点阵”在本项目中先具体化为可检查的依赖网络，不声称具有数学格结构：源片段 → 测量 → 证据 → 状态 → 预测路径 → 报告主张。每条边有类型和来源，节点区分已计算、不可观察、辅助、禁止推断及被撤销等状态。不能把这些不同权限压成一个分数。

## 三条并行工作线

主工作线负责制定协议、编写可复现的研究代码、运行描述性分析并整合结果。独立 Agent A 核对历史指标、当前表结构与训练分区；独立 Agent B 检查逻辑和统计方法。Agent 意见是审查输入，不代替数据或医学专家验证。

## 阶段一：179 个候选指标的证据台账

交付：候选指标台账、当前运行定义、状态关联矩阵、同源关系表、数据可测覆盖表。

保留历史字典的 180 行和 179 个不同名称；不无声合并同名不同状态的行。记录每项的定义、单位/分母、任务、角色、参考、声学/语言/互动维度、当前状态关系与权限。

历史名称和运行名称只有完全匹配才能自动对应。看起来相似的名称列为人工复核候选，不由 Agent 猜测后当作已完成映射。只有原始公式、单位、阈值和角色范围一致，才可登记等价关系。区分“未映射”“未实现”“当前数据没有值”。

## 阶段二：分清三类 overlap

| 层面 | 研究方法 | 可以得到什么 | 不能得到什么 |
| --- | --- | --- | --- |
| 定义/公式重复 | 核对公式、事件、分母与变换；登记严格等价或互补 | 在给定实现范围内的恒等关系 | 两个不同临床概念完全相同 |
| 统计依赖 | 同数据集、同任务、同语言内，训练病例的秩相关、覆盖率、缺失与常量检查 | 重叠候选、适用分层、结构性缺失 | 相关即冗余、无相关即独立 |
| 推断路径复用 | 检查指标到状态的关联及源事件依赖；后续做同源组干预 | 哪些信息有多条进入决策的路径 | 仅凭路径数证明预测被放大 |

第一批代码只计算描述性结构及训练分区相关性，不计算临床优越性，不自动删除指标。不合并不同数据集。没有可信 split 或有重复 subject 的输入应拒绝；没有语言元数据则明确标注不能给出语言内结论。

独立审查补充：拒绝混合 `dataset_id`、空白或前后空格污染的身份键。有行级 `task_type` 时还按行任务分层；没有时，只有具名任务列能支持相应任务范围的描述，`overall` 和 `other` 块不得表述为任务内结论。表内身份键唯一不等于真实受试者独立，PREPARE 的录音 UID 与 NCMMSC 的文件名归组仍需单独核验。

统计结果记录成对有效病例数，不以插补值制造相关。少于 20 个共同观测或任一变量恒定时不作相关性解释；20 只是本轮可行性阈值，不是统计充分性证明。`|Spearman rho| >= 0.90` 仅用于形成复核清单。没有 p 值或显著性主张，也不把成千对探索性筛查包装成确认检验。

训练表中的 overall 与 task-specific 列分别分析。相同病例的不同任务不视为独立受试者；首轮按 task scope 分块，不把跨任务相关误当公式重复。标签、身份、split、来源、年龄等不进入指标相关矩阵；任务和语言是分层条件，不作为诊断依据。

## 阶段三：验证逻辑规则是否真的控制计算

提出以下可证伪的研究要求，而不是先宣布系统满足：

1. 来源一致性：每个 evidence ID 只能解析到同一病例内的已登记对象；缺少来源不能默许有效。
2. 重复不增益：重复提供相同证据不能因为重复出现而提高支持强度；同源多指标应显式标记依赖。
3. 撤销闭包：源证据纠正后，所有依赖它的测量、状态和表示必须重算或被标记失效；局部状态干预则明确冻结其他分支。
4. 缺失不等于正常：不可观察状态不提供正常证据。
5. 权限不升级：QC 或辅助指标不能通过改名、复制、跨状态转述成为临床证据。
6. 报告一致性：报告使用锁定结果与有效证据，不引用已经撤销的对象。

首轮建立一个依赖闭包验证器及合成契约测试。验证器只能确认所提供的图和重算日志是否一致，不能证明图完整或模型内部忠实。现有真实 pipeline 尚未接入的步骤明确标为未验证，不用合成测试通过替代真实运行。

独立审查补充：源删除必须同时提供修改前与修改后依赖图。受影响节点从旧图及结构变动追踪，在新图检查重算顺序、有效依赖和撤销祖先；不能通过删除图中的边来规避重算。读取已失效祖先的“重算”同样判失败，即使该输出未被标记为活动状态。真正接入执行器后，还要比较增量重算与从纠正后源数据完整重算的数值结果。

## 阶段四：证据是否必要和有用

在完成台账和基础完整性后，冻结相同编码器、患者划分与模型预算，比较完整集合、定义级去重集合、训练内选择的精简集合。

每一步预处理、参考校准、相关分组、选择和模型拟合都在内层训练分区完成。按同源/相关组做删除再训练，不能只逐列删除并以其他列补偿后的结果断言无价值。小样本优先正则化模型和组级稳定性，不默认需要复杂深度架构。

输出特征数量与准确率/类别召回/校准/成本曲线，记录每组入选频率、失败候选和外部适用性。允许结论是“179 个候选仅部分可验证”“精简后持平或下降”，不能预先要求全部指标独一无二或删减必然增益。

## 阶段五：治理对 Agent 的增量作用

同模型、同事实、同工具与调用预算，比较：非结构化输入、仅结构化证据包、加可执行治理、治理加精简证据集。保留冻结监督预测，用于检测 Agent 回退导致的假稳定。

使用成对的表达改写、顺序、重复、错误质量声明、真实证据纠正和缺失测试；不改写患者原始转录后假定临床信号不变。主要终点：错误证据采纳率、重放一致率、概率变化、类别翻转率、准确率/校准、拒判及 Agent 实际参与率。

核心对照应进一步隔离“结构化”和“执行治理”：相同证据包与候选修正，分别只格式化、检查权限、检查并重算。监督先验和 Agent 评分若来自同一组患者信息，不能默认条件独立并把相乘视作新增信息；须用折外校准和同源重复干预验证，避免把重复利用造成的置信度增大误称增益。

病例是独立分析单位，同一病例的多次调用不得扩大样本量。正式实验再预设主要终点、容忍界限、样本量与多重比较控制。开放权重激活干预为可选后续研究，不把闭源模型文字解释当作内部因果轨迹。

## 本轮与后续边界

- 本轮：实现阶段一、二的可复现研究工具并运行可用训练数据；完成阶段三的最小验证器和负例测试；整合两个独立审查意见。
- 后续：审定名称/公式等价映射，接入真实源证据重算，再做阶段四、五的训练与在线 Agent 实验。
- 不做：更换生产架构、重跑全部正式 benchmark、调用付费模型批量评分、宣称准确率提升、提前绘制机制成果图。

## 工程约定

代码、配置模板、测试及研究协议留在现有 Git 仓库。数据和个体结果留在本地 `.local/evidence_governance/`，输出不可覆盖已存在的研究目录。输入路径、文件哈希、Git 版本、分析参数和软件版本写入 manifest。报告只展示聚合结果，不输出患者 ID 或转录。

研究代码与临床训练 pipeline 分离，运行研究工具不触发模型训练。每个阶段有独立结果状态，不能把完成描述性分析写成完成整个研究。

方法背景与论文链接见 [研究范围备忘录](EVIDENCE_GOVERNANCE_RESEARCH_SCOPE_ZH.md)。

特征选择方法依据：[mRMR，Peng 等，2005](https://pubmed.ncbi.nlm.nih.gov/16119262/) 和 [Stability Selection，Meinshausen 与 Buhlmann](https://arxiv.org/abs/0809.2932)。这些方法为后续相关组筛选和入选稳定性提供参考，不是本轮已经运行的算法。状态干预与输出传播参考 [Concept Bottleneck Models，ICML 2020](https://proceedings.mlr.press/v119/koh20a.html)，不能据此声称我们的临床状态已获得概念金标准。
