# Evidence Governance：多模态临床智能中的可执行证据控制理论框架

状态：理论与方法工作稿。本文定义可检验的理论对象、系统不变量和研究假设，不把当前 pilot 结果写成已成立的临床结论。

本文解决“研究对象如何定义”。会议 comments 中关于 feature 数量、重叠、稳定性、LLM 忠实性和未见数据的完整论证方案，见 [理论研究与验证协议](EVIDENCE_GOVERNANCE_THEORY_RESEARCH_PROGRAM_ZH.md)。定义本身不构成这些研究问题的答案。

## 摘要

多模态临床智能的核心困难不只是如何提取更多特征，也不只是如何让大语言模型生成更完整的解释。真正缺失的是一层位于测量、预测和报告之间的可执行控制机制：系统必须知道一项观察来自哪里、在什么任务中成立、与哪些证据共享来源、允许支持什么层级的主张、发生纠正后哪些下游结果必须失效，以及最终报告中的每个主张能否回到仍然有效的源证据。

本文将 **Evidence Governance，证据治理** 定义为：一组作用于证据全生命周期的可执行规则和记录机制，用于控制证据身份、来源、适用语境、依赖关系、使用权限、修订传播和主张发布。它的目标不是让模型“解释得更像医生”，而是使系统在无关表示变化下保持稳定，在真实证据变化时能够响应，并使每个发布主张具有可核验的有效证据路径。

这个定义导出三个必须分开评价的目标：预测是否正确，称为准确性；无关扰动下结果是否保持，称为稳定性；判断是否真正依赖系统声明的证据，称为忠实性。证据治理可以由结构设计直接保证部分完整性性质，也可以通过实验改善稳定性和错误控制，但它不能在没有外部标签、临床参照和跨数据验证的情况下自动保证诊断准确率。

## 1. 理论问题

现有多模态模型通常把声学表示、语言表示和其他变量直接拼接或动态加权，再输出风险概率。此类方法可以提高预测性能，但模态权重不能回答以下问题：同一段停顿是否被多个指标重复计票；一个只适合质量控制的指标是否被升级成疾病证据；任务不适用或缺失的指标是否被误当作正常；源转录被修正后，状态、风险和报告是否同步更新；报告中的主张是否真的来自模型使用的证据。

检索增强生成、事后归因、概念瓶颈和审计日志分别解决了其中一部分问题，但没有单独覆盖完整证据生命周期。检索增强生成主要控制知识获取；事后归因描述模型敏感性；概念瓶颈提供可干预中间表示；审计日志记录已经发生的事件。证据治理要求这些对象同时满足准入、依赖、权限、修订和发布约束。

本文回答四个理论问题：

1. 什么对象才可以称为证据，而不是原始数值或模型表示？
2. 证据之间的重复、依赖、互补和冲突应如何区分？
3. 哪些性质可以由系统结构直接保证，哪些必须通过数据和实验检验？
4. 如何证明系统既不会因无关变化而漂移，也不会因过度稳定而忽略真正的证据修正？

## 2. 基本对象

证据治理采用分层对象，而不是把所有内容都称为 feature 或 evidence。

### 2.1 原始观察

原始观察记为 \(o\)。它可以是音频片段、转录文本、说话人轮次、任务提示、回答时间戳或采集元数据。原始观察保留患者、任务、语言、角色、时间和采集条件，但尚未包含临床含义。

### 2.2 测量

测量记为 \(m_i=f_i(o;\theta_i)\)。它是从原始观察按照明确算法得到的值，例如静音比例、每分钟词数或词汇多样性。一个完整测量至少包含：算法名称和版本、单位、分母、有效范围、缺失原因、输入来源和计算时间。

测量值本身不是临床证据。若不知道说话人角色、任务要求、语言、采集质量或参考范围，同一个数值可能没有可比较的临床含义。

### 2.3 证据对象

证据对象记为：

\[
e_i=(id_i, v_i, \pi_i, c_i, g_i, r_i, a_i, q_i, u_i, \nu_i)
\]

其中：

- \(id_i\)：稳定且唯一的证据身份；
- \(v_i\)：测量值或结构化观察；
- \(\pi_i\)：来源，包括片段、转录、算法及其版本；
- \(c_i\)：适用语境，包括任务、语言、角色和时间；
- \(g_i\)：来源组，用于标记共享同一底层事件的证据；
- \(r_i\)：可靠度及其依据，不是模型置信度的同义词；
- \(a_i\)：允许用途集合，例如质量控制、模型辅助、临床状态支持或报告引用；
- \(q_i\)：质量与混杂信息，例如噪声、设备、转录缺失或任务偏差；
- \(u_i\)：可观察状态，包括已观察、不可观察、受污染和被撤销；
- \(\nu_i\)：版本与修订状态。

把 metric 转换为 evidence 的关键不是增加描述文字，而是给测量增加可执行的身份、适用性、依赖和权限。

### 2.4 共同认知状态

共同认知状态记为 \(s_k\)。它是跨数据通道具有一致临床含义的可观察构念，例如词汇提取困难、停顿与流畅性负担、输出效率或信息密度。状态不是所有相关指标的平均值，而是一个受任务可观察性、证据可靠度、来源依赖和缺失机制约束的中间对象：

\[
s_k=F_k(E_k^+, C, G_E)
\]

其中 \(E_k^+\) 是通过治理后可用于该状态的证据，\(C\) 是病例语境，\(G_E\) 是证据依赖图。

“共同”不表示所有任务使用相同权重。它表示状态语义跨任务保持一致，而测量方法、可观察范围和融合参数可以按图片描述、结构化访谈、认知任务或自由讲话分别校准。

### 2.5 预测、主张与报告

预测是模型对诊断类别、风险或认知状态的估计。主张是允许进入临床报告的陈述。两者不能等同。预测可以使用只允许模型辅助的信号，但报告主张必须满足更严格的证据权限、来源和不确定性要求。

每个报告主张 \(h_j\) 需要一个支持集合和一条有效路径：

\[
P(h_j)=\{o \rightarrow m \rightarrow e \rightarrow s \rightarrow h_j\}
\]

若路径中任何必要节点被撤销、语境失效或权限不足，主张必须被重新计算、降级或删除。

### 2.6 病例证据、医学知识与模型输出

病例证据、医学知识和模型输出是三种不同对象。医学知识记为 \(K\)，包括 AD 相关临床知识、任务解释规则和报告规范。它可以解释病例证据，但不能增加患者实际观察到的证据数量。每条知识也需要来源、适用人群、发布日期和版本。

监督模型概率记为 \(p_0(y\mid x)\)。它是基于病例输入计算出的候选预测，不是新的独立病例证据。Agent 可以把它作为统计先验或冲突对象读取，但不能同时读取产生该概率的证据，再把概率作为另一份独立支持重复计票。最终记录必须区分“病例观察支持”“外部知识解释”和“模型候选判断”。

## 3. 证据治理核

证据治理核记为 \(\Gamma\)，由六个可执行算子构成：

\[
\Gamma = (\Gamma_{id}, \Gamma_{ctx}, \Gamma_{dep}, \Gamma_{perm}, \Gamma_{rev}, \Gamma_{rel})
\]

1. \(\Gamma_{id}\) 解析证据身份、版本和来源，防止同一对象通过改名或复制成为多份支持。
2. \(\Gamma_{ctx}\) 判断证据在当前任务、语言、角色和时间点是否适用。
3. \(\Gamma_{dep}\) 建立同源、派生、互补、冲突和统计依赖关系，不把相关性误写成独立性。
4. \(\Gamma_{perm}\) 限定证据允许进入的状态、预测路径和报告主张。
5. \(\Gamma_{rev}\) 在源数据或测量修正时传播失效和重算要求。
6. \(\Gamma_{rel}\) 在发布前检查支持路径、未决冲突、缺失、权限和版本一致性，并决定发布、降级或拒判。

治理后的证据集合表示为：

\[
(E^+,E^-,L)=\Gamma(E,C,G_E)
\]

其中 \(E^+\) 是允许使用的证据，\(E^-\) 是被拒绝或降级的证据，\(L\) 是不可覆盖的决策记录。监督模型和 Agent 都只能读取其权限范围内的 \(E^+\)，不能绕过治理层直接使用被拒绝对象。

## 4. 完整决策流程

系统包含三条相互连接但不可混同的链：

1. 测量链：原始观察进入角色识别、任务路由、声学与语言测量，再形成证据对象。
2. 预测链：受治理的证据形成共同认知状态和预测表示，由监督模型产生候选风险。
3. 主张链：单一诊断 Agent 读取受治理的证据包、认知状态、候选风险、医学知识和权限规则，提出病例判断及报告主张；发布算子检查后输出或拒判。

Agent 的作用不是复制监督概率，也不是自由生成诊断。它执行受约束的病例级证据综合，能够指出冲突、请求缺失信息、下调不可靠证据并形成可审查主张。监督模型提供统计先验，Agent 提供受证据约束的病例级推理，两者必须在发布层接受同一治理规则。

这是一种“可修正认知状态”设计：系统维护的是当前证据支持下的状态，而不是不可更改的一次性解释。新证据进入或旧证据撤销时，相关状态、预测和主张按照依赖图更新。

## 5. 证据重叠不是一个单一问题

“证据相互之间不应该 overlap”过于强，也会误删有价值的互补测量。完全正交既不是临床构念的必要条件，也通常不可能。需要控制的是不当重复计票和未声明依赖。

本文把重叠分成五层：

| 层面 | 定义 | 处理原则 |
| --- | --- | --- |
| 身份或公式等价 | 相同证据复制、严格恒等、互补恒等或可逆仿射变换 | 规范化为同一身份或同一等价组，不重复增益 |
| 来源依赖 | 多个指标来自同一停顿、同一片段、同一转录或同一编码器 | 保留不同测量，但共享来源组并限制合并强度 |
| 统计依赖 | 在特定数据、语言或任务中高度相关 | 训练内估计，作为精简和稳健性依据，不自动删除 |
| 构念重叠 | 多个指标测量同一临床状态的不同侧面 | 允许互补，但必须说明测量差异和状态内作用 |
| 路径重叠 | 同一源信息通过多个状态或分支再次进入最终判断 | 用依赖图和删除干预检查是否发生重复放大 |

因此，证据关系至少需要下列标签：`equivalent`、`derived_from`、`shared_source`、`complements`、`correlated_in_context`、`supports_same_state`、`contradicts` 和 `independence_unknown`。没有观察到相关不等于独立，模型学到不同权重也不证明信息不重复。

## 6. 为什么不能用“100 个 feature”描述证据充分性

证据数量应被写成复杂度剖面，而不是一个总数：

\[
\mathcal{C}=(N_{definition},N_{observed},N_{source},r_{eff},N_{active},N_{claim})
\]

- \(N_{definition}\)：登记的指标定义数；
- \(N_{observed}\)：当前病例实际可计算的指标数；
- \(N_{source}\)：去除同源和严格等价后的来源组数；
- \(r_{eff}\)：给定数据与任务中的有效信息维数；
- \(N_{active}\)：治理后进入预测的证据数；
- \(N_{claim}\)：最终报告实际使用的证据数。

这个剖面回答“系统定义了多少”“病例观察到多少”“去重后有多少来源组”“数据中有多少有效维度”“预测用了多少”和“报告引用了多少”。来源组表示同源关系已被控制，不等于这些来源在统计或因果上相互独立。该剖面避免把历史候选 179 项、当前运行 37 项、高维编码器表示和单病例有效证据混成同一个数字。

增加 feature 并不保证信息增加。严格重复可能放大置信度，噪声变量可能损害校准，小样本高维表示可能增加方差。反过来，边际预测贡献较低的指标也不一定应删除，因为它可能承担质量控制、冲突检测或报告解释功能。特征精简必须同时评价预测、校准、稳定性、治理覆盖和报告效用。

## 7. 治理不变量

以下性质是系统设计要求。只有接入真实执行日志并通过反例测试后，才能声称实现满足它们。

### G1 来源完整性

任何活动证据必须解析到明确的病例、原始观察、测量算法和版本。来源缺失不能默许为有效。

### G2 语境适用性

证据只在登记的任务、语言、角色和时间范围内生效。跨任务使用必须经过显式映射或重新校准。

### G3 重复幂等性

重复提交同一证据、等价证据或同一来源组的复制项，不得仅因出现次数增加而增强支持。

### G4 缺失中性

不可观察、未计算或受污染的证据不提供“正常”支持。缺失可以增加不确定性，但不能被编码成健康证据。

### G5 权限不升级

变换、汇总、改名或 Agent 转述不得扩大源证据允许支持的主张集合。质量控制信号不能经由语言包装成为疾病机制证据。

### G6 修订闭包

源证据被修正或撤销后，所有依赖节点必须重算或失效。增量重算应与基于修正后源数据的完整重算一致。

### G7 冲突保留

相互冲突的有效证据不能通过平均或摘要被无声消除。系统必须保留冲突身份、来源和解决方式。

### G8 轨迹完整性

每个活动主张必须存在通向有效源证据的完整路径；每个被撤销源的后代不得继续作为活动支持。

### G9 发布一致性

报告只能引用与锁定预测、当前证据版本和发布策略一致的对象。未解决的关键冲突、证据不足或权限失败应触发降级或拒判。

## 8. 可由结构证明的命题

### 命题 1：重复幂等性

若证据准入先按稳定身份和严格等价关系进行规范化，聚合只对唯一来源组计算一次，则添加任意数量的相同复制项不会改变治理后的证据集合，也不会改变依赖该集合的确定性下游计算。

证明要点：复制项在 \(\Gamma_{id}\) 中映射到同一规范对象，唯一来源组集合不变，因此状态函数和后续确定性函数输入不变。若系统对行数计权、等价解析错误或 Agent 可以读取未规范化文本，该命题不成立。

### 命题 2：撤销闭包

若所有依赖关系均被完整登记，且撤销操作使被撤销节点及其全部后代失效，发布层拒绝包含失效祖先的路径，则撤销后不存在仍由该源证据支持的活动主张。

证明要点：对于依赖该源的任一主张，其相关支持路径包含该源或其后代。后代闭包全部失效后，任何包含该路径的主张均不能通过发布检查。这个命题证明的是给定图上的闭包，不证明依赖图本身完整。

### 命题 3：权限不升级

若每个证据携带允许用途集合，任何变换输出的权限不得超过所有必要输入权限按照预先登记规则得到的集合，发布层又只允许主张属于其支持路径权限，则中间变换和 Agent 不能合法地产生超出源证据权限的主张。

证明要点：权限是随数据流传播的约束，不是文本标签。每个变换都不能扩大允许集合，发布层再次检查，因此不存在合法的权限升级路径。若代码允许 Agent 自行重写权限或报告不执行检查，该命题不成立。

### 命题 4：受控表示不变性

若证据包在进入模型前完成稳定排序、身份规范化和等价项折叠，模型版本、采样参数及外部工具固定，则仅改变字段顺序或复制数量不应改变确定性系统输出。

对具有采样随机性的闭源 LLM，这只能转化为带容忍界限的经验假设，不能由接口结构完全证明。

### 命题 5：治理不蕴含准确率提升

即使 G1 至 G9 全部成立，也不能逻辑推出 AUROC、accuracy 或临床效用提高。治理约束可以减少重复、越权和陈旧证据，也可能因为拒判或删除不稳定捷径而降低覆盖率或表面性能。准确性必须由独立标签、外部数据和统计区间检验。

这个命题是理论边界，不是缺点。它防止把“可审计”偷换成“医学正确”。

## 9. 稳定性、准确性和忠实性

### 9.1 稳定性

设 \(\mathcal{T}_0\) 为不改变病例临床事实的扰动集合，包括证据顺序变化、等价复制、格式变化和无关信息加入。稳定性要求：

\[
d(f(x),f(t(x))) \leq \epsilon, \quad t\in\mathcal{T}_0
\]

其中 \(d\) 可以是概率差、类别翻转、状态差异或报告主张集合距离。稳定性必须按扰动类型报告，不能只给平均一致率。

### 9.2 准确性

准确性描述结果与外部参照的一致程度，包括区分能力、类别召回、校准、决策曲线和外部数据表现。它依赖标签质量、病例构成、划分协议和阈值，不能由 Trace Map 或 Agent 自述证明。

### 9.3 忠实性

设 \(\mathcal{T}_1\) 为改变有效临床证据的干预，包括删除支持证据、修正错误值、撤销污染转录或加入相反证据。忠实性要求受影响的中间状态和支持路径按照依赖关系变化：

\[
\Delta E_{valid} \Rightarrow \Delta(S, P(h), L)
\]

最终类别不一定每次翻转，因为其他证据可能抵消变化；但系统必须反映该证据已改变，并能解释为什么最终判断保持或改变。

一个始终输出同一结果的系统可能非常稳定，但既不准确也不忠实。因此治理评价必须同时包含无关扰动不变性和有效证据响应性。

## 10. 两层可解释性边界

证据治理提供的是系统级可解释性：它解释输入证据如何被准入、合并、抑制、修订并形成报告主张。Trace Map 是可执行证据流，不是神经网络内部电路。

若要回答“LLM 内部发生了什么”，必须使用可访问内部状态的开放权重模型，进行表示探针、激活替换、路径 patching 或 attribution graph 等实验。闭源模型只能进行接口层和行为层因果检验。模型生成的自然语言理由不能作为其真实内部计算轨迹。

因此，本文区分：

1. 证据流忠实性：实际输入、约束和重算是否与记录一致；
2. 行为依赖忠实性：删除或修正证据是否引起预期的输出变化；
3. 神经机制解释：模型内部哪些表示和计算路径导致变化。

当前项目具备研究前两层的工程和实验路径，但仍需接入真实执行日志并完成干预。第三层是开放模型上的独立实验，不能用前两层替代。

## 11. Proof Generation 的含义

本项目中的 proof generation 不表示生成“患者患有 AD”的数学证明。它生成三类可核验对象：

1. 完整性证明：身份、来源、版本、权限和依赖图满足规则；
2. 执行证明：输入哈希、代码版本、准入记录、状态计算、预测、Agent 行为和发布结果能够重放；
3. 经验证据：预测、稳定性、忠实性和临床可用性经过预注册实验与外部数据检验。

前两类可由系统日志和确定性检查器验证。第三类只能由数据和实验支持。三类合并后形成“可论证判断”，而不是不可反驳的诊断证明。

每次正式运行至少保存：病例匿名键、输入哈希、数据版本、测量版本、证据身份及状态、来源组、权限、认知状态输入、监督预测、Agent 候选判断、治理否决或修正、最终主张、拒判原因和软件版本。

## 12. 可证伪研究假设

| 假设 | 可证伪表述 | 主要终点 | 失败含义 |
| --- | --- | --- | --- |
| H1 重复幂等 | 注入等价复制不改变治理后分数和主张 | 最大概率差、翻转率、主张差异 | 身份解析或聚合仍按出现次数计票 |
| H2 无关扰动稳定 | 顺序、格式、无关内容变化对结果影响低于预设容忍界限 | 配对概率差、状态差、报告一致率 | 系统受包装形式而非证据内容驱动 |
| H3 有效修订响应 | 修正真实证据后，所有受影响节点更新且不受影响分支保持稳定 | 重算覆盖、增量与完整重算差异 | 证据链只是展示，未控制实际计算 |
| H4 权限忠实 | 仅 QC 或模型辅助证据不进入临床主张 | 越权主张率、无效引用率 | 报告层绕过治理规则 |
| H5 紧凑非劣 | 精简证据集在外部数据上不劣于完整集合，并改善至少一项稳定性、校准或成本 | 外部性能差及置信区间、ECE、成本 | 当前复杂度包含必要信息或精简不稳健 |
| H6 跨语境保持 | 治理收益在至少一个留出数据集、语言和任务中保持方向一致 | 分层效应与异质性 | 收益只是单数据集规则拟合 |
| H7 Agent 增量 | 相同证据和模型预算下，治理 Agent 降低无支持主张且不造成不可接受的性能下降 | 无支持主张率、准确率、校准、拒判 | Agent 只是语言包装或引入额外错误 |
| H8 Trace 完整 | 每个发布主张均可重放到有效源，撤销源无活动后代 | 路径完整率、陈旧证据残留率 | Trace Map 与生产执行不一致 |

H5 中的“非劣”界限、H2 的容忍界限和 H7 的不可接受下降必须在正式实验前预注册，不能根据测试结果倒推。

## 13. 评价矩阵

治理系统不应由单一 accuracy 排名。最小评价矩阵包括：

| 目标 | 指标示例 | 分析单位 |
| --- | --- | --- |
| 预测 | macro AUROC、accuracy、macro F1、类别召回、校准误差、Brier score | 独立病例 |
| 稳定性 | 配对概率差、类别翻转率、状态变化、主张 Jaccard、一致性区间 | 同病例配对扰动 |
| 忠实性 | 删除充分性、删除必要性、修订传播率、绕过路径率 | 证据组与病例 |
| 治理完整性 | 来源缺失率、越权率、陈旧证据率、重放成功率、拒判覆盖 | 执行事件与病例 |
| 复杂度 | 复杂度剖面、有效秩、来源组数、延迟、token 和计算成本 | 数据集与病例 |
| 临床使用 | 主张可理解性、证据定位时间、错误纠正率、适当依赖 | 临床读者与病例 |

LLM 多次采样不能作为新增病例。统计分析以患者为独立单位，重复调用只用于估计同一病例的系统波动。

## 14. 与相邻方法的边界

| 方法 | 主要回答 | 证据治理增加的部分 |
| --- | --- | --- |
| 特征选择 | 哪些变量提高预测或降低冗余 | 变量是否可用、允许支持什么、如何修订和发布 |
| 动态模态融合 | 每个样本更依赖哪个表示分支 | 同一信息是否重复、语境是否适用、权重能否形成临床主张 |
| 检索增强生成 | 生成时检索哪些外部知识 | 病例证据身份、依赖、权限、撤销和发布闭包 |
| 概念瓶颈 | 预测是否经过可解释概念 | 概念证据的来源、可观察性、任务条件和报告权限 |
| 事后归因 | 模型对哪些输入敏感 | 输入是否有资格成为证据，以及纠正后是否强制重算 |
| 校准和不确定性 | 概率是否与经验风险一致 | 产生概率的证据是否有效、重复或越权 |
| 审计日志 | 系统做过什么 | 系统在什么条件下必须拒绝、撤销或重新计算 |
| 输出安全过滤 | 哪些文本不能发布 | 从原始观察到主张的全链路控制 |

Evidence Governance 不是这些方法的替代物，而是规定它们的输出何时有资格进入临床判断。

## 15. 对 AD 语音项目的具体理论映射

本项目的声学、语言和互动指标不是三个彼此独立的“诊断模态”。它们是对同一说话行为的不同测量视角。共享底层事件是正常现象，治理需要避免把同一停顿同时通过静音比例、连续性、回答延迟和片段轨迹重复放大。

共同认知状态承担跨数据通道的语义接口。例如“词汇提取困难”在图片描述中可由命名停顿、泛化代词和修正行为支持，在结构化访谈中可由回答启动、替代表达和互动修复支持。状态语义保持一致，但观测项和权重按任务条件化。任务差异不应在进入融合前被平均抹平。

片段轨迹提供局部时间定位。它不是独立诊断分支，而是把病例级状态还原到发生位置，使状态变化、异常峰值和报告主张能够回到音频片段。若轨迹只用于展示而不进入依赖图，它不能作为治理证据。

Agent 接收的是治理后的结构化证据包、共同认知状态、监督模型候选风险、适用的 AD 医学知识和明确的报告权限。它可以综合、质疑、降级和拒判，但不能创建不存在的测量、修改来源、把模型辅助证据升级成临床事实，或把监督概率重新包装成另一份独立患者证据。

## 16. 理论贡献的允许表述

在完成实证前，当前工作可以提出以下理论与方法贡献：

1. 将多模态临床 AI 的 evidence 从“输入特征”重定义为具有身份、语境、依赖、权限和修订状态的可执行对象。
2. 提出证据治理核，把准入、依赖、权限、修订和发布统一到同一运行机制，而不是只在报告末端增加解释。
3. 提出稳定性与响应性的双重检验，防止把不响应真实证据的僵化系统误写成稳定系统。
4. 提出证据复杂度剖面和五层重叠分类，为“为什么需要这些指标”提供可检验的回答，而不是预设一个 feature 数量。
5. 区分系统证据流、行为因果依赖和神经机制解释，限定 Trace Map 和闭源 LLM 分析能够支持的结论。
6. 把 proof generation 定义为完整性记录、可重放执行和外部实证的组合，形成可证伪的临床 AI 论证链。

在完成正式实验前，不能声称：所有指标相互独立；治理必然提高准确率；Agent 已理解 AD 病理机制；Trace Map 揭示了 LLM 内部思维；随机划分证明基础模型从未见过数据；少量案例已建立跨语言通用模型。

## 17. 当前证据状态

当前 pilot 已支持“运行指标中存在严格关系和明显低维结构，因此 feature 数量不能等同于有效证据维数”这一研究动机。它尚未支持最优精简集合、临床构念正交性、治理提高诊断性能、真实执行图撤销闭包或 Agent 忠实性。

理论部分与实证部分的接口如下：

- 结构审计验证第 5、6 节中的等价、来源组和复杂度剖面；
- 真实 replay 验证 G1 至 G9 及命题 1 至 3 的工程实现；
- 成对 Agent 干预验证第 9 节的稳定性和忠实性；
- 嵌套选择与外部验证检验 H5 和 H6；
- 开放权重模型实验仅用于第 10 节第三层，不影响前两层结论成立与否。
