# Evidence Governance 理论研究方案：从定义走向可论证结果

日期：2026-09-17。性质：针对会议 comments 的理论研究与实证协议。本文纠正上一版偏重概念定义的问题。

## 1. 真正需要回答的不是“Evidence Governance 是什么”

会议意见要求回答的是五个研究问题：

1. 为什么需要约 100 个 feature，而不是 20 个、50 个或 179 个？
2. 哪些 feature 是重复的，哪些提供独有信息，哪些必须联合出现才有价值？
3. Evidence Governance 为什么可能提高稳定性，同时不牺牲准确性？
4. 大语言模型是否真正依赖允许的证据，还是只生成一段符合要求的解释？
5. 在公开数据库可能被基础模型见过的情况下，如何证明跨数据库、少样本和未见语境的泛化？

仅给出 evidence object、依赖图和权限定义，不能回答这些问题。定义只提供研究对象，后续必须用信息分解、特征选择、成对干预、外部验证和污染审计形成证据。

## 2. 当前能够回答到哪里

| 会议问题 | 当前已有证据 | 当前结论 | 尚缺什么 |
| --- | --- | --- | --- |
| 为什么约 100 个 feature | 历史字典 179 个不同名称；当前运行 37 项；两套体系仅 1 个完全同名 | 目前没有证据支持“100 最优” | 完整定义映射、嵌套组选择、外部非劣曲线 |
| 是否重复或正交 | 四数据集发现严格等价、同源复用、任务列副本和低有效秩 | 当前指标不是独立票；完全正交不是合理目标 | 179 项定义审定、来源组、条件互信息与协同信息 |
| 治理是否提高稳定性和准确性 | 有合成依赖图检查器；未完成真实 Agent 成对干预 | 尚未成立 | 固定模型的治理阶梯实验和外部预测验证 |
| LLM 内部是否遵循证据链 | 当前只有接口规则和展示 trace | 尚未证明 LLM 内部过程 | Agent 冻结后的行为干预；开放模型激活实验 |

因此，上一版理论汇报中最需要修正的是：不能把“提出九项治理不变量”写成已经回答了会议问题。它们只是待验证的机制。

## 3. 核心理论主张：大候选库，稀疏治理执行

本项目不应该论证“约 100 个 feature 同时进入一个模型是合理的”。更可检验的主张是：

> 为覆盖不同语言、任务、角色和采集条件，系统需要一个较大的候选证据库；但对任一病例，治理层只允许适用、可靠、非重复且具有明确用途的证据组进入计算。

这称为 **large registry, sparse governed execution**。需要同时报告六个数量：

\[
\mathcal{C}=(N_{definition},N_{observable},N_{source},r_{eff},N_{active},N_{claim})
\]

- \(N_{definition}\)：候选定义数量；
- \(N_{observable}\)：当前病例可计算数量；
- \(N_{source}\)：去除严格等价并合并同源后的来源组数量；
- \(r_{eff}\)：当前数据和任务中的有效信息维数；
- \(N_{active}\)：治理后进入当前预测的证据组数量；
- \(N_{claim}\)：最终报告实际引用的证据数量。

“100 个 feature”最多只能描述 \(N_{definition}\)，不能代表模型维数、独立证据数或单病例使用量。

当前 37 项 pilot 中，可变指标为 28 至 36 项，熵有效秩为 7.84 至 12.68，即有效秩与可变列数之比约为 0.28 至 0.38。允许进入报告的 14 至 16 项指标，其有效秩与列数之比约为 0.34 至 0.48。这表明列数显著高估观测结构维数，但不能据此选择最终指标数。

## 4. 如何真正回答“为什么是这些 feature”

### 4.1 不先规定数量

需要求解的不是固定 \(k=100\)，而是满足多重约束的最小证据组集合：

\[
S^*=\arg\min_S |S|
\]

约束包括：

\[
\Delta Performance(S) \ge -\delta_p
\]

\[
\Delta Calibration(S) \le \delta_c
\]

\[
Stability(S) \ge \tau_s
\]

\[
Coverage_{clinical}(S) \ge \tau_g
\]

\[
Traceability(S)=1
\]

也就是说，选取能够在外部数据上保持预测、校准、稳定性、临床状态覆盖和追溯完整性的最小集合。最终可能是 30、60、100，也可能因任务而不同。若实验不支持 100，就必须放弃“为什么是 100”的预设。

### 4.2 五步研究程序

1. **定义与来源去重**：人工核对公式、单位、分母、算法和源事件，先删除严格复制，登记同源但互补的指标。
2. **证据组而非单列分析**：按来源组、认知状态和用途角色形成组，避免从同一事件中只留下一个偶然代理量。
3. **条件增量信息**：在训练分区中计算候选组对标签的条件互信息，识别在已有证据后仍提供新增信息的组。Markov blanket 是理论目标，但小样本下只能作为候选发现工具，不能当作真因果结构。
4. **稳定选择**：按患者重采样，在每个内层训练折记录组入选频率。一次 split 入选不构成证据。
5. **外部 Pareto 曲线**：绘制证据组数量与外部 AUROC、类别召回、校准、扰动稳定性、追溯覆盖和计算成本的关系，选择满足预注册非劣界限的最小点。

### 4.3 “有用”不是单一含义

每个证据组应被分成四类，而不是只按分类贡献删除：

- 预测证据：在外部数据上提供稳定增量；
- 临床解释证据：能够支持认知状态和报告主张；
- 质量与安全证据：用于发现噪声、设备、角色和转录问题；
- 无效或未验证证据：严格重复、不可观察、算法未验证或跨语境不稳定。

一个 QC 指标即使不提高 AUROC，也可能对拒判和防止越权有价值。一个高维谱特征即使提高 AUROC，也可能没有报告权限。

## 5. 如何研究 overlap、独有信息和协同信息

“完全正交”不是合理目标。临床状态共享病理和行为来源，某些信息只有联合使用才出现。需要建立五层关系矩阵：

1. 定义等价：公式、单位和算法是否相同；
2. 来源依赖：是否来自同一片段、停顿、转录或编码器；
3. 统计冗余：在特定数据、任务和语言中是否高度相关；
4. 预测增量：控制已有证据后是否仍增加标签信息；
5. 协同信息：两个证据组联合时是否提供单独使用无法得到的信息。

对于多模态和多状态关系，采用信息分解而不是简单相关矩阵。部分信息分解可以把与目标有关的信息拆成冗余、独有和协同三部分。由于 179 维和小样本下直接估计不可靠，分析单位应先收缩到来源组或 14 个状态，而不是直接对 179 列做高维 PID。

证据组被视为“独有且有用”，至少需要满足以下之一：

- 与已有集合相比具有稳定的条件增量信息；
- 删除后造成可复现的外部性能、校准或某类召回下降；
- 对临床状态覆盖、冲突检测或质量安全具有不可替代作用；
- 与其他组形成稳定的协同信息，联合删除造成明显损失。

低相关不是独立证明，高权重不是独有信息证明，单数据集消融也不是跨域必要性证明。

## 6. 如何论证治理同时影响稳定性与准确性

需要固定同一数据、编码器、监督模型容量、Agent 模型和调用预算，运行四级治理阶梯：

| 条件 | 输入与规则 | 回答的问题 |
| --- | --- | --- |
| G0 非结构化 | 原始指标/文本直接输入 | 普通模型或 Agent 的基线波动 |
| G1 结构化 | 相同事实整理成 evidence package | 结构化本身是否有作用 |
| G2 执行治理 | G1 加身份、依赖、权限、缺失和发布检查 | 治理规则是否产生增量 |
| G3 精简治理 | G2 加训练内选择的紧凑证据组 | 去除冗余是否进一步改善泛化和成本 |

对每个病例生成两类干预：

- 无关干预：顺序、格式、等价复制和无关信息。理想结果是输出变化小。
- 有效干预：删除、修正或反转真正相关证据。理想结果是受影响状态和支持路径更新。

稳定性与准确性必须同时报告。治理成功的最低要求不是“更稳定”，而是：无关扰动下波动降低，同时外部准确率和校准不低于预注册界限，并且真实证据修正仍能引起适当响应。

## 7. 如何研究 LLM 是否真的遵循证据治理

闭源 LLM 的自然语言解释不能揭示内部计算过程。当前项目可以完成两层研究：

### 7.1 行为因果层

在 Agent 冻结后，对相同病例执行证据 ID 级干预：

- 删除一组支持证据；
- 加入与解释相矛盾的有效证据；
- 保留数值但降低可靠度或撤销报告权限；
- 复制同源证据；
- 改变表达和顺序但保持事实不变。

评价 Agent 的类别、概率、认知状态、引用证据和报告主张如何变化。FaithLM 的 contrary-hint 思路和语义删除/否定干预提供了可借鉴的评价方式，但必须改造成证据对象级干预，而不是自由文本提示攻击。

### 7.2 神经机制层

若要回答“模型内部哪条路径使用了治理证据”，必须换用开放权重模型，进行表示探针、激活替换、路径 patching 或 attribution graph。该实验回答的是开放模型内部机制，不能直接外推到 GPT 等闭源模型。

因此，最终 Agent 未冻结前不能完成 LLM 忠实性实验；但 feature overlap、最小充分证据集和外部选择研究不需要等待 Agent。

## 8. 如何处理“基础模型可能见过数据库”

本地 train/test split 只能控制本项目训练泄漏，不能证明基础 LLM 或编码器在预训练阶段没有见过公开数据库。

需要分别记录：患者重复、任务模板泄漏、检索示例泄漏、编码器预训练污染和 LLM 预训练污染。证据强度由低到高为：

1. 患者、站点和采集批次隔离；
2. 留一数据集外部验证；
3. 发布时间晚于模型知识截止的数据；
4. 受控私有或前瞻数据。

黑盒污染检测可以提供风险证据，但阴性结果不能证明模型从未见过数据。最终论文应把“本项目测试未参与本地训练”和“基础模型预训练未接触数据”分成两句话，后者在没有额外证据时标为未知。

## 9. 少样本为什么可能成立，以及如何验证

证据治理的大部分规则应该是标签无关的，例如身份解析、来源组、权限、缺失和撤销闭包。需要从病例学习的主要是参考校准、预测贡献和部分阈值。这提供了少样本迁移的理论基础，但仍需验证。

如果会议中的“64”表示 64 个治理示例，应预注册 0、4、16、32、64 个适配病例的学习曲线。每个预算重复患者级抽样，分别测量预测、稳定性、权限违规、拒判和成本。只有当治理条件相对于同预算基线持续改善，才能声称少量案例即可学习。

如果“64”指 64 个 feature 或另一项工作，必须先确认含义，不能把数字直接写入结论。

## 10. 哪些工作现在做，哪些等 Agent

### 现在可以完成

1. 179 个历史候选与当前 37 个运行指标的版本映射；
2. 定义、来源、统计和状态路径重叠分析；
3. 来源组和状态级条件信息、稳定选择与嵌套精简；
4. 留一数据集的监督模型外部验证；
5. 证据复杂度 Pareto 曲线；
6. 患者、任务、语言、站点和预训练污染风险台账。

### 必须等最终 Agent 和推断接口冻结

1. G0 至 G3 的 Agent 治理增量实验；
2. 重复、顺序、删除、反证和权限干预；
3. Agent 实际参与率、错误证据采纳率和拒判分析；
4. 预测与医生报告是否共享同一锁定轨迹；
5. 开放模型的内部激活实验。

若隔壁只修改 Agent，当前 feature 结构研究可以继续。若隔壁还会修改 metric 定义、提取算法、任务路由或 evidence ID，当前结果只能作为 pilot，正式结果必须在 schema freeze 后重跑。

## 11. 论文最终可形成的证据链

1. 结构层：当前候选库包含多少严格重复、同源组和有效维度。
2. 选择层：最小充分证据组在多少个外部数据集上保持性能与校准。
3. 治理层：重复不增益、权限不升级、修订可重放是否在真实执行中成立。
4. Agent 层：治理是否降低无支持主张，同时保持准确性和真实证据响应。
5. 泛化层：效果是否跨数据集、语言、任务、模型和少样本预算保持。

只有这五层都完成后，才能把 Evidence Governance 写成一个研究贡献，而不只是工程框架或概念定义。
