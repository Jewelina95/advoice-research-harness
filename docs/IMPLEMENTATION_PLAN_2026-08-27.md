# AD Voice 8.27 实施总方案

## 1. 本轮范围

本轮先固定工程方案和诊断 Skill，不运行训练。目标不是把 8.21 代码换一个目录，而是重新建立一条可复现、可审计的路径：

`原始数据 -> 数据路由与质量控制 -> 可解释指标与预训练表示 -> MetricEvidence -> StateCard -> 监督模块 A -> 单一诊断 Agent -> 监督模块 B 与确定性审查 -> 医生报告 -> Layer A/Layer B 评估`

8.20/8.21 与 system 8.13 只提供原始数据位置线索，以及最终 HTML 中已经形成的评估呈现习惯。8.27 不复制旧项目代码、参数、模型结果或中间产物；旧结果只能作为历史回归审计材料。

## 2. 研究定位

系统定位是语音认知筛查和转诊支持，不是 Alzheimer 病的生物学确诊工具。语音证据可以描述在特定任务中观察到的语言、言语和互动表现，但不能替代生物标志物、神经心理量表、病史、功能变化和医生鉴别诊断，也不能仅凭语音给出 AD 病理分期。

核心研究对象不是“哪个模态权重最高”，而是跨任务、跨语言、跨采集条件下，一个病例的可观察认知状态如何由原始证据形成、如何被修正、如何影响筛查判断，以及每个结论能否回到原始音频或转录片段。

## 3. 不可妥协的设计原则

1. **标签隔离**：测试标签、诊断文件名、源目录诊断字符串不得进入特征、病例证据包、Agent 上下文或报告。
2. **折内处理**：参考人群统计、缺失值处理、特征选择、任务适配器、监督模块、阈值和校准全部在训练折内拟合。
3. **角色与任务先行**：访谈者语音、提示语、任务切换和轮次等待先被识别，再计算患者证据。
4. **可观察性不等于权重**：任务是否能测某状态、该次测量是否可靠、模型学习到的预测贡献是三个独立变量。
5. **质量证据不直接支持疾病**：设备、噪声、时长、响度、ASR 质量和角色覆盖只能降低可信度或触发复测。
6. **低层表示不写成病理机制**：预训练音频/文本向量和低层谱特征可帮助预测，但不能被翻译成 AD 机制。
7. **Agent 修正受约束**：Agent 可以审查证据、更新认知状态假设和提出有限概率修正；不能绕过监督先验、校准器和确定性验证器。
8. **一次运行一个证据版本**：报告、图、指标和病例必须来自同一代码版本、配置哈希、数据清单和运行 ID。

## 4. 目标系统的工程模块

### 4.1 数据注册与不可变快照

为每个数据集建立 manifest，至少包含：病例 ID、任务 ID、语言、说话人角色、音频路径、转录路径、标签来源、官方 split、重复组、设备/来源组和授权状态。原始数据只读，派生数据写入带版本号的 artifact 目录。

首批注册对象沿用已有原始数据资产范围，但重新审计：IAEAV、ADReSS 2020、ADReSSo 2021 diagnosis、ADReSSo 2021 progression、PROCESS-2、PREPARE、TAUKADIAL、DementiaBank Pitt、DementiaNet、NCMMSC2021 AD。

训练协议分为三个互不混用的层次：

- **P1 数据集内基准**：每个数据集按其官方终点和 split 独立拟合 B1/B3，用于公平完成三条件比较。
- **P2 主共享诊断模型**：只合并终点可以严格统一为认知受损分类、且许可允许的训练数据；共享认知状态骨架，使用任务类型适配器和语言校准器，数据集 ID 不入模。
- **P3 泛化与特殊终点**：在同终点家族内做留一数据集、留一任务或留一语言外部验证；纵向进展、序数分级和连续认知分数使用独立 endpoint head，不与横断面 AD/HC 分类混训。

主科学模型是 P2；P1 是必需的公平基准，P3 回答泛化。若某数据集终点不能与 P2 统一，它只进入 P1/P3，不被强行池化。

### 4.2 路由、切分与 QC

路由输入由任务类型、语言、是否多轮、是否有说话人标记、是否纵向、可用模态构成。任务类型先收敛为图片描述、结构化访谈/多任务、自发叙述/公开视频、语言流畅性和纵向随访，不用数据集名称充当任务特征。

切分遵循 speaker/subject group split；纵向数据按患者成组；同源剪辑、同一长音频切片和近重复不得跨 train/test。5 秒窗口只用于预训练音频编码器表示，不替代临床事件片段。临床事件片段由患者轮次、句子边界、停顿事件、修正事件和任务边界产生。

### 4.3 双表示层

- 可解释通道：按任务计算停顿、输出效率、发声连续性、词汇提取、多样性、句法、不流利、互动等指标。
- 预训练表示通道：冻结的多语言文本编码器和音频编码器提取高维表示，仅供监督模块使用。

两条通道保持分离。预训练表示不得伪装成临床状态；可解释指标也不能因为可读就被假定为可靠。

### 4.4 MetricEvidence 与 StateCard

每个指标从单值升级为证据对象，记录原值、训练折参考、异常方向、可靠度分解、缺失、混杂、任务、片段和报告权限。StateCard 在任务可观察性约束下聚合同一临床构念的非重复证据，输出状态类别、严重度、置信度、支持证据、反证和原始片段。

### 4.5 两个监督学习模块

监督模块 A 是统计先验模型。它使用可解释状态、预训练表示、任务/语言上下文和可靠度，学习各分支对当前病例的贡献，输出折外校准前的类别分布。它不生成医学文本。

监督模块 B 是受限修正与校准模型。它使用模块 A 的双层折外输出、证据覆盖、状态冲突、Agent 选择的证据摘要及混杂负担，学习修正是否允许、最大修正幅度和最终概率校准。它不接受测试标签，也不能让一次 Agent 输出无限改写概率。

两个模块均采用嵌套交叉验证。外层折用于最终性能估计；在每个外层训练集内部，模块 A 再生成内层 OOF prior，Agent 只能看到该病例未参与拟合的 prior，模块 B 只用这些 OOF Agent 轨迹训练。外层测试病例只在模块 A、Agent、模块 B 全部冻结后进入一次。小样本数据优先使用正则化模型和固定状态定义，不训练高容量深层门控。

### 4.6 单一诊断 Agent

一个 Agent 完成五类内部动作：检查质量、检查状态、追溯指标/片段、比较任务或分支、形成并复核筛查假设。它加载静态 AD Skill，并接收动态病例证据包和模块 A 先验。

Agent 不是自由文本分类器。它必须输出结构化的候选类别分布、支持证据 ID、反证 ID、质量证据 ID、状态修正和认知回退轨迹。系统用确定性验证器检查引用、权限、概率边界和医学禁区，再由模块 B 决定是否接受有限修正。

### 4.7 Cognition-of-Thought 风格的回退

本项目借鉴的是“推理时显式监测、发现违反优先原则后回退重做”的思想，不声称复现原论文的 token-level Perceiver。项目中的优先级为：

`数据有效性 > 任务/角色适用性 > 原始证据可追溯 > 状态内部一致性 > 校准风险边界 > 报告措辞`

若 Agent 把 QC 当疾病证据、引用不存在的片段、忽略强反证、使用任务不可观察状态、推断生物学确诊/分期或超出允许修正幅度，验证器定位到违规证据或状态，撤销该步骤并要求重建假设。回退事件写入审计轨迹。

### 4.8 医生报告

最终报告只读取锁定后的决策对象，不重新推理。报告包含：筛查结论和不确定性、主要认知/语言发现、每个发现的原始值与参考、可播放/可定位片段、反证、采集限制和下一步临床复核建议。报告不显示内部字段堆栈，不把自动报告评分当医生验证。

## 5. Agent 实际收到什么

病例包必须是 label-free JSON，而不是把所有 CSV 拼成长 prompt。其内容包括：

- `case_context`：去标识病例、一个或多个任务、语言、角色、访视、可用模态和终点定义。
- `quality_summary`：音频、转录、角色覆盖和失败标记。
- `supervised_prior`：模块 A 针对分类、序数、连续或配对变化终点的折外输出、校准状态和不确定性。
- `state_cards`：可报告状态与模型专用状态分开。
- `metric_evidence`：每条状态可追溯的支持/反证对象。
- `segments`：时间范围、说话人、转录文本、音频引用。
- `decision_bounds`：允许修正幅度、必须回退的规则、允许动作。
- `skill_version` 与 `model_context_card`：规则版本和训练信息摘要，不含训练日志。

测试真实标签只在评估器中出现，永不进入该包。

## 6. 工程目录目标

确认方案后，8.27 将扩展为：

```text
8.27/
  configs/               数据、任务、指标、状态、模型、Agent、评估配置
  data_registry/         数据清单与许可元数据，不复制受限原始数据
  skills/                版本化 AD 证据诊断 Skill
  schemas/               所有跨模块数据契约
  src/advoice/           可测试流水线实现
  tests/                 单元、契约、泄漏、回退和最小端到端测试
  experiments/           运行配置，不手工编辑结果
  artifacts/<run_id>/    特征、证据、状态、模型、预测和审计轨迹
  reports/<run_id>/      系统报告、评估报告、病例报告和图
  reports/latest/        指向最近一次通过验证的运行
```

## 7. 实施顺序和硬门槛

### Phase 0：规格冻结

完成本目录中的 Skill、Schema、数据源清单、状态可观察性和评估规范。验收：静态验证通过；没有训练结果或未实现声明。

### Phase 1：数据审计与 manifest

逐数据集生成清单、角色/任务覆盖、语言、标签、split、重复、音频时长和缺失报告。验收：零跨 split 病例/源音频/近重复；所有 exclusion 有原因码。

### Phase 2：证据链重建

实现事件片段、指标、折内参考、MetricEvidence、StateCard 和完整 trace。验收：抽样病例能从状态回到指标和原始片段；QC 引用不能进入疾病支持列表。

### Phase 3：监督模块 A

按 `TRAINING_PROTOCOL_P1_P2_P3.md` 分别执行 P1 数据集内基准、P2 共享认知状态主模型和 P3 泛化/特殊终点。验收：pooling eligibility 已冻结；只使用训练折拟合；输出 OOF 与 held-out 预测；保存权重、门控、adapter、endpoint head、seed、环境和模型卡。

### Phase 4：Agent 推理与模块 B

先冻结 Skill 和 Agent schema，再在训练折生成 Agent 轨迹，训练受限修正/校准模块。验收：Agent 无测试标签；所有修正可追溯；违反规则可回退；修正模型必须通过非劣效门槛。

### Phase 5：完整评估

同协议比较 B1、B2、B3；每个数据集独立报告，另做预声明外部验证。验收：Layer A 和 Layer B 的全部指标、置信区间、失败审计和病例报告来自同一 run ID。

### Phase 6：发布与复现

建立单一命令、缓存、断点恢复、运行锁、哈希和 HTML 生成。验收：干净环境可从 manifest 重建到报告；失败步骤不会覆盖 `reports/latest`。

## 8. 方案确认后才执行的命令边界

本轮不会运行 Phase 1–6。确认后先实现 `validate-data`、`build-evidence` 和最小病例包，再训练模块 A；不会直接启动全数据深度编码和 Agent 批处理。

## 9. 明确非目标

- 不承诺 B3 必须在每个数据集超过 B1/B2/SpeechCARE；结果必须来自同协议实验。
- 不把 Agent 自动评分写成医生评价。
- 不用病例标签生成报告证据。
- 不用数据集 ID 作为预测特征。
- 不在无验证任务评分器时启用语义连贯性、内容单元或任务表现。
- 不在本轮声称完成 GPT 后训练。当前闭源 GPT 模型通过 Skill、工具、结构化输入和确定性验证使用；若未来做参数后训练，必须另建可训练模型和专家审核数据。
- 不承诺仅凭语音可靠区分 MCI、早期 AD、中期 AD 和晚期 AD；没有相应终点、临床参考和外部验证时不得生成该结论。

## 10. 训练前需要确认的预注册参数

以下数值必须在第一次训练前写入不可修改的 protocol 文件：主要终点、配对 bootstrap 次数、seed 数、模块 B 非劣效 margin、选择性预测覆盖门槛和多重比较方法。建议初稿为 10 个 seed、2000 次配对 bootstrap、AUROC 非劣效 margin 0.02、Brier 增幅上限 0.01、ECE 增幅上限 0.02；这些是工程提案，不是医学金标准，方案确认时需要单独批准。
