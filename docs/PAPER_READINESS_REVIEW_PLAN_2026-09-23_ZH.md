# ADvoice 论文准备阶段：系统复核与验证方案

日期：2026-09-23。本文为计划与初步核查，不代表已完成新的训练或正式评价。

## 1. 当前判断

系统已有可运行的研究原型、结构化证据、状态重放和融合接口；尚不足以证明临床状态测量有效、Agent 带来稳定独立增益，或超过 SpeechCARE。应保留现有架构，优先统一版本、纠正数学契约和验证测量链，不再以全量重跑替代定位问题。

“能运行”“预测有用”“Agent 有额外收益”“临床有效”是四个不同结论，分别需要工程、独立测试、配对消融和临床效度证据。

## 3. 底层原理：保留什么，修正什么

建议保留流程：原始语音与任务信息 → 可核查测量 → MetricEvidence → 任务条件化 StateCard → 监督预测和状态重放 → Agent 证据审查及独立意见 → 校准融合 → 可追溯结果。

### 测量与医学解释

Metric 是测量值，Evidence 是带来源与适用条件的测量，State 是由测量推断的状态。给指标命名或引用文献并不能自动证明 State 测量有效。

逐项登记：定义、单位、实现、分母、任务、语言、可观察条件、方向、参考人群、混杂因素、片段来源、报告权限、实现状态。参考分布及可学习变换必须在训练折内拟合。

当前配置需明确的边界：

| 状态 | 当前实际依据 | 应采取的行动 |
|---|---|---|
| S01 停顿负担 | 静音占比、长停顿率、均值、P90 | 分开频率、时长尾部与总负担，避免把相关等同于重复 |
| S02/S03 输出与连续性 | 共享 voiced_fraction、long_pause_rate 等 | 核查跨状态重复支持，追溯保留共同源头 |
| S04–S06 | 强度、基频、谱学 | 维持辅助角色，验证 Agent 无法将其直接升级为疾病机制结论 |
| S07 | 代词、内容词、图片不确定表达 | 作为词汇具体性/提取困难代理，核查任务与语言适用性 |
| S09 语义连贯性 | metrics 为空，planned | 保持未实现；不能算作已验证能力 |
| S11 句法复杂度 | 仅 mean_utterance_words | 收窄为话语长度代理；若扩充句法算法，单独验证准确性 |
| S13 互动与语用负担 | 仅 patient_turn_share | 收窄为轮次参与代理；不能独立推断提示依赖或语用障碍 |
| S10/S14 | 图片内容密度与覆盖 | 核查共享内容单元及任务特异性，不能移植为任意任务得分 |

可观察性 mask 不是风险权重：缺失、任务不支持、提取失败和真实正常必须分开。填充零仅是数值处理，mask 与原因应始终随状态传递。

声学、语言、对话分别有设备/噪声、ASR/分词、角色/轮次时间等误差源。应从少量片段核查分母和事件边界，不能只看分类准确率。

### 家族治理与融合

完全重复可以合并；互补统计量不能因为相关高就删除。当前 pause_burden 将多个统计量放入同一家族，是需要比较的建模假设。

验证候选限于三种：当前构建、家族代表、收缩聚合。选择只发生于训练内验证；样本少的任务共享参数并收缩，不为每个数据库新增自由权重。任务/语言作为适用条件，数据库 ID 主要用于分组评价与偏差检查。

代码当前通过居中 ordinal 分数及温度产生所谓 likelihood。它是未校准证据分数，不是已经估计的临床似然比。监督预测与 Agent 读取同一材料也不满足条件独立，不能宣称简单相乘等于严格贝叶斯更新。

### 当前融合数学问题

本轮修复前，authority_joint_fusion.py 的 staging 分支给 MCI/AD logits 添加相反修正，再对 HC/MCI/AD 一起 softmax，导致 HC 概率越权变化。当前实现已改为分层参数化，仍需在正式开发/测试协议中复验。

当前层级参数为：q=P(受损)，r=P(AD|受损)。先根据合法筛查证据更新 q；再根据分期证据更新 r；最后输出 HC=1-q、MCI=q(1-r)、AD=qr。契约测试已经覆盖仅修改 r 时严格保持 q。

MCI/AD 区别也不等于 AD 早中晚期。保留阶段扩展接口；只有数据具有相应可靠标签时才训练与报告更细阶段。疾病生物学诊断与临床分期有不同依据，语音代理不能自动成为病理金标准。

## 4. 执行顺序与验收标准

### P0：建立唯一可复现基线

1. 对齐两个工作树和未跟踪评估脚本，生成提交与结果清单。
2. 用缓存逐例解释九例 1.000 与 0.889 的差异，记录每个门控、参数和结果。
3. 区分训练、开发、已被反复查看的测试与真正未用的最终测试。已用于迭代决策的测试不得继续称独立确认集。
4. 核对跨数据集同一患者/访次/录音重复，尤其共享语料衍生数据。

产物：版本清单、逐例对照、患者划分清单。通过标准：每个汇报数值都可追溯并确定性复算，无未解释的版本差异。

### P1：证明测量链与数学契约正确

1. 完成 Metric→Evidence→State 映射审查，优先 S01/S02/S03、S11、S13。
2. 抽取各通道与语言的正常/缺失/噪声案例，检查音频事件、转录与角色。
3. 修复并测试分期与筛查解耦；覆盖极端概率、标签置换、平分、冲突、缺失、不可观察。
4. 比较当前与候选家族构建；用开发数据诊断 IAEAV 退化，测试标签不用于挑选模式。
5. 验证非法 Evidence ID、辅助证据越权及缺失值不会改变合法医学状态。

产物：状态语义表、测量审查表、契约测试和小型回归结果。通过标准：无已知权限或数学错误；未验证状态显式标记，不伪装成正常或已测量。

### P2：验证 Agent 的独立作用

保持相同编码器、监督预测、证据包、划分、预算，比较：

| 组 | 作用 |
|---|---|
| A 仅监督 | 锚定基本预测能力 |
| B 监督+Agent 证据修正后重放 | 衡量证据修正收益 |
| C 监督+Agent 盲态判断 | 衡量独立意见收益 |
| D 完整联合 | 衡量两种作用组合 |
| E 仅 Agent（诊断性对照） | 检查离开监督支持后的能力与失败类型 |

一次 Agent 调用同时保存审查提案和未见监督概率的独立证据分数，复用缓存计算各组，避免每组重新调用。只有提示/证据/模型变化才使缓存失效。保存完整脱敏证据包、版本、token 和成本。

仅在开发集用少量、正则化参数校准证据强度与温度，允许权重为零；不因监督不确定自动提高 Agent 权重，也不因希望有贡献强制权重大于零。

先用分层小规模开发样本检验接口、纠错类型和成本，不用其证明总体优越。重复调用子样本检查稳定性；证据乱序、等义表达、同源复制不应造成实质性改变，纠正或删除关键证据应有合理响应。

主要报告配对净纠错：原错变对减原对变错；同时给分母、accuracy、macro F1、AUROC、Brier、log loss 与区间。分任务/语言/类别报告，检验新模型是否通过损害 HC/AD 换取 MCI 改善。

通过标准：进入正式实验前流程无契约问题、开发集存在可复核互补信号且成本可接受。正式统计结论由预先冻结的指标、区间和容忍界限决定，不以挑选最高的一次运行决定。

### P3：完成未完成项和多通道检验

- PROCESS-2：先 profile 重复索引/复制，比较向量化与缓存后的数值一致性，再恢复运行。
- IAEAV：核对角色可观察性、家族压缩前后覆盖、参考分布、具体概率变化；AUROC 下降不能只以样本小解释。
- NCMMSC：只纳入既定长语音，检查中文分词、分母与任务路由，排除六秒重复片段造成身份泄漏。
- progression：独立的进展终点，不套用 HC/MCI/AD 分类语义。
- DementiaNet：样本与标签来源限制下用于鲁棒性/案例验证，不作为主性能证据。
- 覆盖图片描述、访谈、多任务、公开讲话；通道与数据库是两种概念，不能用数据库名称替代任务路由。

### P4：冻结正式比较与论文材料

PREPARE 与 SpeechCARE 比较需逐项核对数据版本、入排标准、任务、标签、患者划分、语言、编码器、随机种子和指标平均方式。论文报告值只能在协议对应时直接比较；不同条件单独注明。优先固定同编码器比较，隔离认知框架/Agent 的贡献，再把表征升级作为另一项实验。

Layer A：accuracy、macro/weighted F1、balanced accuracy、各类敏感度/特异度、各定义 AUROC、混淆矩阵与概率校准；清楚区分 micro/macro/weighted。

Layer B：合法引用、任务适用性、修正可执行性、证据干预响应、预测重放一致性、报告权限遵从、重复运行稳定性、token/延迟。未做医生评分不得称临床质量验证；自动检查不得称专家审核。

报告生成只在判断实验冻结后接入：结论、支持及反对证据、局限、建议、片段入口均引用同一个结果对象。先少量示例检查状态/概率/文字一致性，再扩展。

产物：方法展示 HTML、Layer A/B 评估 HTML、中文口播、逐项 claim→实验→结果表、独立复核意见。

## 5. 论文可论证的核心

核心假设是：任务条件化的证据表示和可执行状态修正，可以减少重复、不可观察与语境错误带来的错误判断，并允许 Agent 提供可验证的额外信息。该假设需要独立数据检验，不能由结构更细或模型更强直接推出。

优先证明测量与推理之间的可检查连接。即使 AUROC 相近，可追溯性、修正成功率和校准也是可评价贡献；但若宣称性能优越，仍必须提供匹配协议下的预测证据。

审查任务：01a0cb73-25ae-74b1-aff3-7c26e677e114，模型 Astra。只读审查，未执行训练或修改框架代码。
