# PREPARE 与 SpeechCARE 差距及 Agent 净增益审计

日期：2026-09-03

## 结论

ADvoice 9.2 与 SpeechCARE 使用同一批 PREPARE 官方测试病例（n=412；HC=229、MCI=51、AD=132），主要终点可数值对照。但两者训练协议不同：SpeechCARE 端到端微调 mHuBERT 与 mGTE，并报告 10 次训练均值；9.2 当前主要使用冻结表示、浅层融合和单次正式运行。因此，9.2 当前不能声称总体持平或优于 SpeechCARE。

9.2 的认知证据框架已经显示独立增益；当前单一诊断 Agent 的附加增益尚未建立。这是两个不同结论。

## 已成立的优势

相对于内部 B1，9.2 的 Accuracy 提高 0.1189，Macro AUROC 提高 0.0853。相对于内部 B2，Accuracy 提高 0.2451，Macro AUROC 提高 0.2295。相同冻结编码器的析因实验中，加入 MetricEvidence、StateCard 和任务路由后，Accuracy 提高 0.0752，Macro AUROC 提高约 0.060。

相对于 SpeechCARE released checkpoint，9.2 的 MCI recall 为 0.686，SpeechCARE 为 0.333，差值 0.353，分层配对 bootstrap 95% CI 为 [0.235, 0.490]。但 9.2 同时降低了 HC 和 AD recall，因此这是早期受损敏感性优势，不是总体性能优势。

把认知分支回顾性叠加到 SpeechCARE released checkpoint 后，Micro AUROC 从 0.8790 增至 0.8824，Micro AUPRC 从 0.7723 增至 0.7805。该结果提示认知表示具有互补信息，但大多数增量区间仍跨零，且 Accuracy 略降，不能作为独立优效结论。

## 尚未成立的部分

| 指标 | ADvoice 9.2 | SpeechCARE 论文十次均值 | 差值 |
|---|---:|---:|---:|
| Micro AUROC | 0.8462 | 0.8683 | -0.0221 |
| Micro F1 / Accuracy | 0.6723 | 0.7211 | -0.0488 |
| Micro AUPRC | 0.7011 | 0.7473 | -0.0462 |

相对于 SpeechCARE released checkpoint，9.2 的 Accuracy、Micro AUROC、Macro AUROC 和 Micro AUPRC 的配对差值置信区间均低于零。因此总体上既未超过，也不能声称持平。

## “Agent 净增益尚未成立”的含义

原始 9.2 运行中，Agent 修改了 178/412 个病例的概率，但只改变 2 个最终类别：修正 1 个病例，同时破坏 1 个原本正确的病例。Accuracy 变化为 0，Macro F1 变化为 -0.0006，Micro AUROC 变化为 +0.0003，Micro AUPRC 变化为 +0.0013。所有 Agent-on 与 Agent-off 差值的 95% 置信区间均跨过零。

因此，“尚未成立”不是“已经证明 Agent 无效”，而是当前数据不能排除这些微小差值来自抽样波动，而且类别层面的净修正数为零。

## 根因

1. **Agent 可见证据不足。** 当前可报告状态主要是停顿、输出效率、发声连续性和韵律；词汇提取、语义连贯性、信息密度、任务完成度、回忆遗漏与侵入等关键证据没有进入 Agent 的可用证据包。
2. **Agent 的独立证据判断没有学会三类映射。** Agent evidence likelihood 的 Macro AUROC 约为 0.479，接近随机；有效 classify 病例中几乎不选择 AD。继续放大其权重会放大错误。
3. **Agent 的状态修正没有进入预测计算。** `state_updates` 被验证和记录，但最终概率仅使用 `evidence_scores`；因此“保留、降权、失效、不可观测”等认知回退动作尚未形成可执行预测链。
4. **层级融合存在中性证据偏置。** 原代码把三分类中性意见 `[1/3,1/3,1/3]` 合并成健康 `1/3` 对受损 `2/3`，使无方向意见也自动推高受损风险。
5. **只能修正健康与受损，不能修正 MCI 与 AD。** 现有层级融合固定继承监督模型中的 MCI/AD 比例，Agent 无法处理主要的亚型边界错误。
6. **上游表示能力不同。** SpeechCARE 联合微调 mHuBERT、mGTE、自注意力编码器和自适应门控；9.2 的最终模型是浅层多项逻辑堆叠，动态门控因开发集表现较差而未被采用，冻结编码器也不能针对认知标签调整表示。
7. **任务与语言失衡仍未解决。** 9.2 在英语和西班牙语上均落后，西班牙语差距最明显。少量普通话和小任务上的较高准确率样本太小，不能支撑总体优效。

## 已完成的确定性修复

层级融合已经改为使用监督先验中的亚型条件分布对非健康证据进行边际化。修复后，中性 Agent 证据严格保持原先验不变。新增回归测试已通过；全套测试为 99 passed。

在不重新调用 Agent、直接重放同一批锁定决策的探索性计算中，修复后 Accuracy 从 0.6723 增至 0.6796，Macro F1 从 0.6189 增至 0.6246；5 个类别发生变化，4 个被修正、1 个被破坏。该结果只证明错误修复方向正确。因为 correction strength 原来是在旧公式下选择的，必须在开发集重新校准后才能形成正式测试结果。

## 下一轮架构

1. 将分类拆成两个监督头：健康/受损，以及受损条件下的 MCI/AD；二者均只用训练与开发数据学习。
2. Agent 不再直接凭弱证据生成三类概率，而是调用任务评分工具、审查证据适用性、执行状态保留/降权/失效/不可观测动作，并输出结构化证据图。
3. 用 Agent 审查后的状态重新运行两个监督头，使 `state_updates` 真正进入计算，而不是只进入日志。
4. 增加任务特异证据：图片内容单元、语义流畅性聚类与转换、故事回忆遗漏/侵入、叙事连贯性；这些证据可以参与模型计算，但报告权限仍单独控制。
5. 修正强度、拒判阈值、类别阈值和路由只在嵌套开发折内学习；正式测试集不再用于任何选择。
6. 固定同编码器三臂实验：E0 编码器融合、E1 加认知状态、E2 加 Agent；至少运行 10 个随机种子，并报告配对置信区间。

只有 E2-E1 的置信区间显示稳定正增益，才可以声称 Agent 有效；只有 ADvoice-SpeechCARE 的主要终点达到预设优效或非劣界值，才可以声称超过或持平。

## 9.2-v3 复核更新

必须把三种比较分开报告：

1. **独立 ADvoice 对 SpeechCARE：** 当前独立主干仍低于 SpeechCARE，不通过优效门禁。
2. **相同编码器的认知框架开/关：** 认知框架使 Accuracy 提高 0.0752、Macro AUROC 提高 0.0601，说明 MetricEvidence、StateCard 和任务路由本身提供增量信息。
3. **SpeechCARE 公开输出加固定认知残差：** 相对论文十次训练均值，Micro AUROC、Micro F1、Weighted AUROC、Micro AUPRC 和 Weighted AUPRC 五项均提高；相对单个公开检查点，排序、AUPRC 和 Macro F1 提高，但 Accuracy 少 1 个病例。该实验是同强主干的回顾性增量验证，不是独立 ADvoice 优效结论。

新一轮两阶段 Agent 在开发集首轮输出中，约 317 个已返回病例全部将 MCI/AD 分期标记为证据不足；HC/受损证据分的原始 AUROC 约为 0.531。这个结果达到预设停止条件：当前证据包不足以让通用 Agent 独立完成稳定分类，不能通过增大权重制造提升。

已完成以下代码修复：

- 将 Agent 输出拆为 HC/受损筛查和 MCI/AD 分期两组证据，分别门控、校准和融合。
- 分期证据不足时强制返回中性 `[0.5, 0.5]`，不得默认成 MCI。
- 取消冲突病例的 1.25 倍修正放大。
- 在开发集内用五折一维逻辑校准把 0–4 级序数证据转换为等先验证据似然，强度选择使用折外校准值。
- 将非零修正的最低开发集 Macro F1 增益提高到 0.01；未达到时相应阶段自动归零。
- 修复快速重跑脚本未传入 Agent 校准预测和工作区的接口断裂。
- 删除数值和可靠度完全相同的总体/任务状态副本；PREPARE 当前重复的是 S10 和 S14。
- 全套单元测试更新为 111 项并全部通过。

下一项真正可能改变 Agent 信息量的实验不是继续改提示词，而是建立训练折内的证据原型检索：只从同任务、同语言的训练病例检索匿名状态模式，使用外折病例验证 Agent 是否能从相似证据模式中获得增量信息。任务、语言和病例身份必须作为匹配约束，标签不能进入查询特征；若折外 HC/受损 AUROC仍不超过0.55，则Agent保持审计和报告角色。

## 9.2-v4 独立复核与当前边界

训练折内、类别平衡的认知状态原型已经完成五折开发集外审计（n=1,622）。健康/受损 AUROC 为 0.6269，MCI/AD AUROC 为 0.6047，三分类 Micro AUROC 为 0.7228。该结果说明状态参照含有弱但真实的判别信息，足以作为监督主干的补充证据，不足以作为独立分类器，也不能直接证明通用 Agent 的净增益。

新版证据接口把“可用于研究性推理”和“允许进入医生报告”拆成两个权限。可靠的语言、任务和互动指标可以进入盲化 Agent 推理，但只有具有临床报告权限的状态和证据才能进入医生报告。存在可靠任务特异参考时，总体参考被替换而非重复输入，避免同一测量相对总体和任务正常值产生相反方向。

开发门控现已成为正式测试 Agent 的前置条件。只有开发病例证明筛查或分期修正强度非零，正式测试病例才会调用 Agent；若宏 F1 增益和 AUROC 非劣门禁未通过，系统直接保留监督主干，不再生成没有预测作用的测试 Agent 决策。该行为由单元测试覆盖；当前全套测试为 122 项通过。

更深文本编码器、任务折内参照、层级损失和任务去重的候选模型在独立验证集上得到 Micro AUROC 0.8305，低于当前正式 9.2 的 0.8462，因此已拒绝，未替换现有主干。这说明差距不能通过单纯增加可训练参数解决。

当前可成立的最强结论仍是两条：同编码器析因中，认知框架带来 Macro AUROC +0.0601、Accuracy +0.0752；SpeechCARE 公开输出加固定 20% 认知残差后，五项论文均值终点均提高。后一项证明认知分支对强主干具有互补价值，但因为使用公开测试输出，只能称回顾性同主干扩展，不能称独立 ADvoice 优于 SpeechCARE。

独立复核同时修正了四项工程问题：测试 Agent 现在必须同时满足“开发校准完成、选择状态为 validated_joint_gain、修正强度非零”，配置中的固定非零值不能绕过门禁；Agent 批量响应只接受本次请求白名单中的病例 ID；认知原型距离会显式屏蔽缺失特征，避免 `NaN × 0` 污染整个病例；医生报告会同时过滤顶层和 StateCard 内嵌的推理专用指标。Condition C 的缓存键也已加入认知原型和证据校准源文件，修改这些模块后不会再复用旧工作区。全套单元测试为 126 项通过。

现有 `cognitive_agent_status.json` 属于旧单阶段测试运行，最新 `agent_correction_calibration.json` 属于两阶段开发校准，二者不能合并解释。报告生成器已增加代际一致性提示。现有 SpeechCARE 加认知残差结果在数值上超过五项论文均值，但该产物早于当前来源侧车规则；重建来源记录前只作为探索性结果展示。
