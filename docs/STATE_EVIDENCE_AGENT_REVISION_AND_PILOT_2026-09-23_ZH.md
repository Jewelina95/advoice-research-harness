## 1. 需要纠正的判断

之前确实实现过状态修正、screening/staging 分开加权、冲突门控和验证集权重注册。但“代码支持调比例”不等于“已完成可用的校准”。当前有多个串联限制：

- `authority_review_runtime.agent_evidence_strength` 同时要求 `incremental_for_agent` 为真且 `consumed_by_supervised` 为假。现有九个数据集的疾病指标均不满足。
- `configs/calibration/authority_registry.json` 的 `approved_artifacts` 为空。当前不存在可直接部署的已注册非零校准参数。
- `authority_joint_fusion.fuse_authority_joint` 还会在与基础预测一致、状态修正通道已激活等情况下关闭 Agent 路径；公开讲话被设为 report-only。
- 因此，不能把所有零贡献归因于一个字段，更不能用“Agent 模型不够强”解释结构性禁用。

共享原始证据不等于零增量。两个预测器可以从相同输入学习不同关系。真正应防止的是：把高度相关的判断假定为独立证据、未经校准重复累计置信度。相关性应进入融合训练和消融，不能通过全面禁止共享证据解决。

“相关残差专家”是候选的统计组合方法，不是对 Agent 职责的永久限制。Agent 可以独立判断、解释状态之间的关系和提出可执行修订；最终统计层验证这些判断在哪些情况下改善结果。若数据支持，Agent 可承担主要预测作用；不能预先规定必须占 10%、50% 或 90%。

与 SpeechCARE 持平或更好是明确的性能目标。没有超越不等于所有研究价值为零；但若准确性明显落后且不能证明更可靠、可干预、低成本等实际收益，就不足以支持替代它的主张。“与 SpeechCARE 相比的系统进步”和“Agent 相对相同系统的净增益”必须分别证明。

## 2. Jev 和既有研究提供什么

用户提供的 `thejevai.com` 页脚声明其独立运营、非 TypeSafe 官方。技术判断优先核对 [TypeSafe 官方文档](https://docs.typesafe.ai/introduction)。不把第三方页面作为已验证医学性能来源。

Jev 的 [state](https://docs.typesafe.ai/concepts/state) 是共享输入上下文；Choice、Score、Noul 是限定答案空间的问题。可借鉴的是：明确输入事实，拆分小判断，一次请求返回多个结构化结果，数值计算留给代码。这里的 state 不等于我们的临床 StateCard，独立执行问题也不意味着各答案统计独立。

官方 [feature discovery 示例](https://docs.typesafe.ai/cookbooks/autoresearch_feature_discovery) 展示将模型对文本的结构化回答转成特征，再训练监督预测器。它支持一种工程组合思路，不能外推为 AD 有效性证据。当前不增加 Jev 为必需供应商，也不宣称复现其 RLCD 训练。官方 [限制说明](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 列出数值、间接推理、冗长上下文和跨问题一致性等弱点；跨语言和临床效果必须单独测试。

[Cognition-of-Thought](https://arxiv.org/abs/2509.23441) 的可借鉴点是监测、显式原则、发现违反后回退并修订。原工作使用 Generator/Perceiver 的生成期监测。本项目借用“提案、校验、修订”的思想，采用单一 Agent 与确定性校验器，不声称照搬其机制或继承其效果。

[Concept Bottleneck Models](https://proceedings.mlr.press/v119/koh20a.html) 为中间概念可编辑、变化传播到预测提供先例。本项目仍保留基础预测路径，所以不是纯概念瓶颈。新的 [ICLR 2026 工作](https://arxiv.org/abs/2506.04877) 也提示：一个向量能预测某个概念，不代表其中只包含该概念；StateCard 的命名本身不能保证临床语义。

[Stacked Generalization](https://arxiv.org/abs/1105.5466) 提供联合学习预测器组合的方法；[ERASER](https://aclanthology.org/2020.acl-main.408/) 区分解释与人工证据的一致性、以及证据对模型预测的忠实性。我们的增量主张必须超过“有结构化输出、可保存日志、会组合模型”这些已有做法。

## 3. 目标架构与职责

```text
音频 / 转录 / 任务与角色元数据
  -> 分组身份与任务路由
  -> 声学、语言表达、对话事件测量
  -> MetricEvidence + 原始片段索引
  -> 条件化 StateCard(v0) + 来源依赖图
       |-> 训练内拟合的基础预测器 -> base scores
       |-> 单一盲判 Agent -> 状态/关系判断 + 修订提案
                              -> 校验与局部重算 -> StateCard(v1)
  -> 经开发集验证的联合决策器
  -> 锁定分类与概率 + 可重放 decision trace
  -> 正式部署时生成绑定同一版本的医生报告
```

盲判意为 Agent 首轮看不到基础预测概率、病例真值、数据库诊断目录名；它仍看到有任务参考的 StateCard，因此不宣称完全无先验。医学知识、工具规范和病例事实分开存储；患者转录中的指令不能变成系统指令。

### 3.1 任务与输入

- 数据集 ID、采集通道、实际任务、语言、说话人角色是不同字段。四类通道是组织方式，不强迫所有数据共用一套任务或权重。
- 同一患者的不同任务、访问、切片必须保持在同一训练/验证分区；Pitt 与 ADReSS 家族之间还须查来源重叠。
- NCMMSC 使用长录音，排除用户指定的原生 6 秒短样本；这与长录音在编码器内部切成短窗是两件事。
- 对照参考范围、分词器和字典都需要语言/任务适用范围。样本不足时共享统计并收缩；不能为每个稀疏任务语言组合独立拟合高自由度模型。

### 3.2 三类行为测量

| 维度 | 可测内容 | 当前要检查/补齐的内容 |
|---|---|---|
| 声学与语音行为 | 停顿、发声连续性、语速、韵律 | 停顿是否属于患者；任务等待与患者停顿能否分开；设备/降噪影响 |
| 语言表达与沟通内容 | 词汇提取、信息量、重复、任务相关性 | 中文/西班牙语分词与基线；信息单元模板匹配；S09 目前为空 |
| 对话与互动 | 提示依赖、回应相关性、轮替、修复 | S13 当前只有 patient_turn_share；需先核验双说话人和时间对齐 |

独白不能测真实轮替，不能补零冒充正常。S09、S13 的新增判断先标为候选，必须有定义、适用任务、可检验来源和小规模标注验证，才进入正式疾病主张。当前无医生标注，不得写成“专家已验证”。一般标注者可核验片段、角色、话题对应等行为事实；疾病阶段和临床效用需要相应专业证据。

### 3.3 MetricEvidence 与 StateCard

MetricEvidence 是可复算观测：指标 ID、值、单位、方向、任务/语言参考版本、来源角色与时间区间、测量质量、混杂、缺失原因、相关来源家族、推断/报告适用范围。

方向只说明某行为负担增加或减少，不直接等价于 AD。技术可靠度、临床相关性、统计预测增量分别记录；不能把“测得准”当作“诊断对”。

StateCard 是该病例某类功能表现的汇总：状态值/范围、可观察性、支持和反证、来源家族、任务间异质性、测量/推断版本。可观察性表示有没有适当条件测量，不是融合权重。缺失、不可观察、真实中性、证据冲突分别编码。

当前配置已有 S01-S14，不另造一百多个独立 state。固定权重是当前规则，不假装全部已训练。首轮保留已验证聚合，只新增质量与引用语义；有稳定开发标签后再比较状态内学习与固定聚合。

### 3.4 Agent 的具体工作

每个病例首轮一次请求，按实际可观察状态选择少量问题：

1. 支持片段是否真属于该患者与任务？
2. 某个停顿/修复是否更可能属于任务等待、正常自我修正或持续检索困难？
3. 不同任务或多个片段的表现是否一致？是否存在相反证据？
4. 哪些 StateCard 的解释应保留、降权或标记不可判定？
5. 现有证据对筛查类别的相对支持是什么？有哪些仍不支持的结论？

输出包括 `state_judgments`、`relation_judgments`、`support_ids`、`counterevidence_ids`、`proposed_operations`、screening/staging 的结构化评分和 `unknown_reason`。评分不是已经校准的概率或独立似然；应由统一适配器映射到开发校准器。

允许的动作是保留、标记无效/不适用、报告冲突、请求已有片段/重测工具。Agent 不能凭空改写音频测量值。重测必须由真实工具产生新版本；没有工具结果则保留未知。首轮最多一次必要片段补取或格式修复，所有尝试都计入成本。

程序验证实体与来源关系，语义真实性另由标注和干预实验检验。去掉“必须为另一疾病编造反证才能分期”的压力，允许返回分期未知；未知不使整个病例失去分类结果。

### 3.5 学习怎样组合判断

将三类问题拆开：

- 合法性：证据是否来自当前病例、是否可用、是否支持该类操作？由确定性规则检查。
- 表示质量：任务、参考范围、测量和缺失是否可信？保留质量特征，必要时限制权限。
- 预测效用：Agent 的判断在相同基础结果下是否减少错误？用开发标签学习。

使用低维、强正则的 stacking 作为首选实现；将残差形式作为其中可嵌套的参数化，而不是手工指定比例。对一个分类 head：

```text
z_final = a * z_base + b * agent_contrast
          + c * state_replay_delta + intercept
```

`z_base` 是基础对数几率，`agent_contrast` 是经过合法证据约束的相对类别评分，`state_replay_delta` 是修订前后状态模型对数几率的变化。开发样本足够后才加入预注册的任务/质量交互，不加入无依据的每-state大参数表。QC 不作为独立疾病加分项。系数收缩到 `(a,b,c)=(1,0,0)`，但不固定 `a=1`；Agent 有稳定增益时可降低基础模型占比。部署不用人工强制非零。

同输入的预测器相关是允许的；模型通过开发数据学习冗余。引用家族去重继续保留，但 `consumed_by_supervised` 只表示 overlap，不再作为所有统计组合的自动禁用条件。不能把 `agent_contrast` softmax 后改名为医学 likelihood。

对 HC/MCI/AD，采用两个分别校准的 head：

```text
u = P(cognitive impairment)
v = P(AD | cognitive impairment)
P(HC)=1-u; P(MCI)=u*(1-v); P(AD)=u*v
```

分期变化不应无故改变 HC 概率。两头是实验假设，须与同参数量多项逻辑组合对照；不能宣称因分层就必然更优。缺少阶段证据时 stage head 使用经校准基础输出。只有二分类标签时按该任务训练；AD 早/中/晚期只有具备相应标签与验证时才启用。认知负担分数不能直接命名为病理阶段。

拟合依赖 subject-disjoint OOF 预测：外折患者不能参与参考范围、特征选择、监督模型、检索范例或融合器拟合。开发样本的基础模型预测不能来自其见过该患者的训练模型。最终效应评估使用嵌套外折或单独锁定集，不能把拟合 stacking 的同一份 OOF 行的训练分数当作验证表现。

统计适配器的训练属于监督学习；冻结编码器、配置 skills、调用 GPT 并不等于 Agent 参数后训练。本阶段不做 LLM 微调或 RL。当前规则修正后，开发研究模式须能收集未部署的 Agent 候选输出并拟合校准器，避免“没有校准不能采集、没有采集不能校准”的死循环。部署模式仍要求注册与上下文哈希匹配。

## 4. Trace back 必须做到什么

```text
ReportClaim -> DecisionSnapshot -> DecisionComponent
            -> StateCard(version) -> MetricEvidence(version)
            -> measurement algorithm -> patient/task/segment/time/source
```

另外保存 `AgentOperation`、输入/输出 hash、模型精确版本、skill/schema/calibrator 版本、前后状态差、前后预测差和拒绝原因。修订采用不可变追加；接受修订后使所有受影响后代失效，重新生成状态、Agent相关判断、融合和报告锁。

三个结论必须分开：存在路径、路径语义成立、干预路径确实改变结果。合法 ID 只能支持第一项。自然语言理由不是模型内部思维的读出；本项目声称可重放证据和决策过程，不声称回溯隐藏 CoT。

示例仅用于说明设计：一段图片描述存在长停顿，S01 负担高；角色时间线显示部分时间是访谈员等待。Agent 引用相关片段提出重算，工具生成患者专属停顿指标并重建 S01。系统记录该改变究竟使预测下降多少，也允许预测不变。不能先编一个风险下降数值证明有效；下降并不自动代表医学正确。

同一来源家族的派生列、StateCard 和 Agent 文本必须一起更新。保留其他任务证据时，删除一条冗余证据可以不改变分类；期望方向只适用于预注册的局部有效对比。人为改符号只用于软件不变量测试，不当作生物学反事实。

保留 embedding 基础路径意味着整个系统不是完全语义透明。分别报告：

- 固定基础预测、只重放状态/Agent 部分：测量可解释分支对决策的影响。
- 在输入源上做可接受干预并重算所有受影响表示：测量完整流水线的敏感性；同时控制录音/ASR改变产生的额外混杂。
- 无法有效干预或不可解释的深层路径：明确标记，不能用几条 citation 声称覆盖全部预测。

## 5. 需要证明的研究主张

| 主张 | 对照与实验 | 不能用什么替代 |
|---|---|---|
| 性能竞争力 | 同 PREPARE cohort、任务、标签、输入权限、划分与指标对照 SpeechCARE | 小样本 9/9、另一个数据集的高 AUC |
| Agent 净增益 | 同编码器、基础预测和患者下比较无 Agent、Agent 判断、状态 replay、二者联合 | Agent 被调用、权重非零 |
| 证据治理有效 | 相同事实和模型，对比 flat / structured / governed，并做合法与非法干预 | 只有 parser 拦截率、哈希齐全 |
| State 有行为语义 | 行为片段标注一致性、任务适用性、跨语言误差、重复测量稳定性 | 给隐向量取临床名字、用疾病标签反向证明全部状态 |
| 可回溯且可执行 | 来源完整性、修订传播、重放一致性、成对有效/无关干预 | 展示长篇推理文字 |
| 模型升级可获益 | 固定工作流下，多模型与框架的交互实验 | 假定 Astra/Sol 名称代表临床能力 |
| 可扩展性 | 未见任务/语言测试，再换疾病适配器的独立标签验证 | 多个 AD 数据库等于跨疾病通用 |

证据治理不只是惩罚模型：可靠证据修正应产生适当响应，无关重复/排版扰动应保持稳定。过度限制使所有预测相同也是失败。

## 6. 对照臂与指标

主实验保留以下核心臂；Agent 输出可缓存复用，但输入或状态版本变化必须重新执行相关判断。

| 实验臂 | 内容 | 作用 |
|---|---|---|
| B | 相同基础预测器、无 Agent；同开发预算校准 | 判定是否值得增加 Agent |
| F | 相同患者事实和知识 skill 的普通 flat Agent | 检验组织方式而非额外知识 |
| S | 同一 Agent，结构化证据和 StateCard，独立预测 | 检验框架对 Agent 本身的作用 |
| J-A | B + Agent 结构化判断，开发集融合；禁止 state patch | Agent 判断效应 |
| J-S | B + Agent 合法 state patch 和 replay；无独立类别评分输入 | 状态修复效应 |
| J-AS | 判断与 replay 联合校准 | 总效应与两路冗余 |

增量主对比为 J-AS 对 B；结构化增量为 S 对 F；Agent 直接判断与状态修复的贡献由 J-A/J-S/J-AS 比较。增加容量对照：B 加同维度的确定性关系特征，检验收益是否只是多了参数。报告-only Agent 不改变预测，无须大量重复运行作准确率对照。

Layer A：Accuracy、micro/macro-F1、micro/macro-AUROC、micro/macro-AUPRC、balanced accuracy、各类 recall/precision、specificity、混淆矩阵、Brier、log loss、校准曲线。显式固定 class order 与 averaging。`help`、`harm`、`(help-harm)/N` 必须按 HC/MCI/AD 和语言报告。

Layer B：可定位到真实片段的比例、重复/跨病例/陈旧证据拦截、语义支持正确率、有效修订率、重放一致性、无关扰动稳定性、有效证据修订响应、失败与回退率、成本和时延。引用有效率与临床语义正确率不可合并。没有标注的语义指标写“未评估”，不以 Agent 自评冒充医生评分。

每个分母包括所有预先分配病例。模型错误、超时、不可解析输出不能静默删除；最终系统使用事先定义的基础回退并计入系统性能，另外报告纯 Agent 覆盖率与失败。纯 Agent 强制分类评测也保留失败为失败，不偷偷填上基础模型结果。医生输出未来可同时提供最可能类别与证据不足说明。

患者层配对 bootstrap 估计差值区间，分类准确率可辅以配对检验；多个任务为次要/探索性比较。训练种子变异、Agent重复调用变异和测试患者抽样变异分开报告。接近不是“无显著差异”：非劣界限必须在看正式结果前依据应用容忍度与功效确定，不能本轮随意取 1% 或 2%。

## 7. Pilot 与完整实验顺序

### P0：契约和测量审计，无新增模型调用

从现有缓存建立 24 个固定工程病例，覆盖中文、西班牙语、英文，图片/访谈/复杂任务/公开讲话；优先包含共享证据、角色混杂和冲突。历史测试病例只能做诊断性工程回放，不挪用为干净开发集。

必须覆盖：全部证据被基础模型用过但 Agent 仍能生成合法候选；监督不确定而 state delta 与 Agent 相反；screening 与 staging 冲突；重复家族；无对话角色；阶段未知；QC 冒充疾病证据；校准器错误版本；所有分支不可用；状态修订后的缓存失效。

验收是来源隔离和计算不变量正确、共享证据路径不再结构性永远为零、研究采集与部署校准可区分。用合成校准器证明路径可影响结果，仅算单元测试；不能强制实际病例非零来假装有益。

### P1：有限开发 pilot

目标从 PREPARE 官方训练/开发池中预先选 120 名互不泄漏的患者，用分组交叉验证进行探索性评估与低维校准。这个数字是初始预算，不是统计功效保证。按标签/语言/任务核查覆盖；稀疏单元不足就不作分层结论。若刻意均衡抽样，同时报告抽样设计，不把均衡样本 Accuracy 当作原队列 Accuracy。

先选其中 24 名作接口预算测量，随后按事先锁定的样本与运行规则完成 120 名，不能因为结果好才扩样或只保留合法输出。前 24 名若用于修改提示/规则，则转入工程集、从后续无偏效应估计中排除并补足样本。先用一个明确版本的强模型估计该方法的可用上限，再在同一 manifest 上比较一个较便宜版本；24 例模型对照仅作可行性，模型能力主张需扩至完整配对样本。

其他通道从各自 development pool 抽至多 12 名做迁移 smoke：ADReSS 图片描述、IAEAV 访谈、NCMMSC 中文长录音、PROCESS-2 复杂任务、DementiaNet 公开讲话。小样本数据若没有独立可用开发患者就只作工程检查，不强行凑数。这些 12 例不能支持跨语言或跨通道准确率结论。

冻结预算和停机规则后执行：来源污染、接口不可执行、无法保证身份隔离立即暂停；性能不佳按完整预定 pilot 汇总，不逐例窥视分数早停。所有修订只在开发侧，下一版本另行标记。

### P2：正式开发校准与 SpeechCARE 比较

P1 通过工程门槛后，在完整 development pool 做 subject-group OOF 和内层模型选择，冻结问题定义、测量、模型、融合器与所有阈值。保持零增益回退候选，但不能把同一 OOF 表上的拟合分数当成效应证据。

[SpeechCARE 原文](https://www.nature.com/articles/s41746-025-02026-x) 最佳 PREPARE 配置包含年龄；音频+文本与加年龄的结果不同。对照同时列出其最佳已发表结果和相同输入权限结果，不把无年龄系统偷偷与另一个条件混为同协议。核对官方参与者 ID、训练/验证/测试划分、任务组合、标签、转录、人口信息、微平均方式和十次重复。单标签多分类且全病例输出时 micro-F1 等于 Accuracy，但必须先确认实现与数据条件。

过去反复查看过的官方测试集可用于回顾性基准复现，不重新命名为从未触碰的确认集；需要另一个未用于开发的队列或预注册外部集承担确认性证据。与论文汇总值相减只给描述差，不能构造虚假的配对显著性。可复现 SpeechCARE 时才比较相同患者的配对预测。

### P3：模型能力与框架交互

预先固定至少两个、正式主张最好三个精确模型版本。选择依据是开发侧独立能力任务，不以名称或价格定义强弱。每个模型都运行 F、S、J-AS，固定患者、输入事实、检索预算、提示内容和编码器。

分别检验：

- 原样替换模型：冻结融合器，比较接口兼容、分类与校准漂移。这是“可直接升级”的主张。
- 替换后开发侧再校准：固定校准算法与预算，比较能力能否转化为系统收益。这是“可适配升级”的主张。

令 `G(m)=Perf(framework,m)-Perf(flat,m)`。更强模型下框架性能提高，与 `G(strong)>G(weak)` 是不同主张；后者需要模型×框架交互区间。框架收益不一定随模型单调增加。也要比较成本-效益曲线、反证识别、正确修订与误修订；不能只看引用更完整。

### P4：跨任务、语言和疾病

九个诊断数据集分别报告，不把不同类别/终点粗暴求总体平均。ADReSSo progression 单列纵向终点。数据内重训、目标域小样本适配、零样本迁移和留一数据集是四种不同协议。

同一框架支持多领域，依靠替换任务/语言测量规则、state 本体、标签及风险 head、知识 skill 和校准器。声学、表达内容、互动协议可复用；AD 权重和 HC/MCI/AD 标签不能搬到其他疾病。

跨疾病扩展先做一个带独立标签的言语/沟通障碍领域，例如经过数据许可和任务核验的帕金森言语或失语症队列。疾病专有状态和风险解释重新验证；此阶段尚未选择/下载新队列。没有这一步，只能说架构具备扩展接口，不能说已适用于任何病例。

## 8. 还未完成的 evidence 研究

1. 历史 179 个名称与当前 37 个运行指标的定义对应：按公式、单位、分母、算法和源事件逐项映射，不能靠名称匹配当成同一指标。
2. S01-S14 的 construct validity：S09 空缺，S13 单指标，S04-S06 仅辅助预测；这三种状态必须在报告里区分。
3. 来源家族、同指标跨状态、不同名称同生理来源的重叠；来源相同不必然完全冗余，应以训练内组选择检验。
4. 紧凑 evidence package 是否遗漏有效反证：比较固定覆盖策略与完整包，不能只检索支持当前最高风险的片段。
5. 不同语言的参考覆盖、短样本偏差、词典和 ASR 错误；有中文词库不等于中文构念有效。
6. 同人跨库、公开人物身份线索、任务模板、原始文件名和基础模型预训练污染；黑盒检查不能证明模型没见过公开数据库。
7. 人工可读路径与深层预测路径的覆盖差；不存在完整重算时必须显示解释范围。
8. 数据内分数与实际临床价值的区别；未来医生报告的可用性需独立盲评，当前不冒充医生参与已完成。

指标数量研究使用训练内来源组选择与嵌套验证画数量-性能-成本曲线，不预设“100 最优”。本轮先关闭阻断预测的架构缺口，后续再做高成本组选择，不同时更换全部指标以免无法归因。

## 9. 工程实施顺序与产物

| 顺序 | 现有落点 | 修改与验收 |
|---|---|---|
| 1 | authority_review_runtime / conditional_authority | 将证据资格、质量、增量效用分开；共享证据不全禁用；保留身份/来源/权限校验 |
| 2 | states / metrics / routing configs | 标清空缺、辅助、可报告状态；任务语言参考和 unknown 原因；不重造旧指标 |
| 3 | Agent schema / agent_runtime | 小问题批量结构化回答；有限工具动作；最多一次修复；记录失败与真实 usage |
| 4 | authority_joint_fusion / calibration | 新增可选低维 stacking 模式及 OOF 校准流程；旧路径保留为回归对照 |

| 6 | evaluation runners | 同患者配对臂、模型交互、失败计分、语言/任务/类别分层与配对 CI |

每个 run 保存 dataset/split hash、患者组 manifest、输入/模型/skill/schema/校准器版本、dirty diff hash、逐病例预测与组件贡献、操作/重放、调用 usage 与失败。数据和转录留本地，代码、配置、合成例子与无敏感信息协议留仓库。修改后按风险运行定向测试，不为同一文档变化反复跑全部训练。

## 10. 成本与停止机制

首轮默认一次判定调用；同一病例不同任务共享一个有索引的紧凑上下文。局部问题同批返回，程序计算统计量。实际 prompt token、输出和 reasoning token（供应商可提供时）、缓存命中、重试、费用、p50/p95 时延分别记录。字符数不是 token 数。

先用少量开发病例测 p95 输入大小；首版预算目标约 6k 输入、1k 可见输出 token/病例，属于工程目标而非当前实测。超出时保留反证与任务覆盖的摘要和可检索片段；记录未读范围，不能静默截断。调用次数与总 token 双重预算，后台无限重试禁止。

Agent 缓存键包含患者事实、task/language、模型精确版本、skill、schema 与状态版本。换模型必须新生成；换融合器可重用未变的 Agent 判断；换来源/StateCard 不能沿用旧答案。完整病例报告暂不批量生成，仅保留一个合成展示例和汇总结果。

独立复核意见已纳入：共享证据的相关性、pilot不足以证明交互、修订操作的封闭语义、opaque embedding干预范围。当前交付是该计划；现有历史分数不会被写成新架构结果。
