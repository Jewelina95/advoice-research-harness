## 1. 可以固定的架构与允许升级的内容

固定：患者/来源分组、任务路由、MetricEvidence、StateCard、单一 Agent、受约束修订与重算、开发集学习融合、版本锁、Layer A/B 输出。

固定：共享证据可进入 Agent 判断；合法性与预测增益分开；技术质量不是疾病证据；未知不是正常；分期与筛查分开；测试标签不进入推断、技能或训练；Agent 原始评分不是已校准概率。

可升级但必须重新验证：语言词典/参考、状态内聚合、有限 Agent 问题、模型版本、融合器参数、疾病适配器。升级这些部分改变版本和缓存键，不推翻架构。没有证据支持承诺一次修改就超过 SpeechCARE；可以承诺的是实施路径明确且失败可定位。

## 2. Training 与 post-training 的区别

| 部分 | 本轮是否训练 | 用什么监督/目标 | 本轮保留什么 |
|---|---|---|---|
| 预训练音频/文本编码器 | 不训练权重 | 无新增训练目标 | 核验模型与缓存来源后冻结 |
| 指标提取与 StateCard 定义 | 不自动学习全部定义 | 公式/任务适用性及可验证规则 | 既有正确映射；重建折内参考 |
| 模块 A：基础预测器 | 训练 | 数据集已有类别标签 | 相同编码器和既有低容量基线家族 |
| 单一 GPT Agent | 不更新 GPT 权重 | 推断时读取 skill、病例状态、原始证据 | 盲判、结构化输出、一次可选重算后判断 |
| 模块 B：融合与校准 | 训练 | 患者级标签与模块 A 的 OOF 输出、Agent 判断、状态变化 | 学习组合，不手填 Agent 百分比 |
| 医生报告 | 本轮不批量生成 | 无 | 决策后未来接入，同一决策版本 |

Training 是广义参数学习。Post-training 通常指预训练模型之后继续对该模型训练，例如 SFT、偏好优化或 RL；SFT 本身也属于监督学习。训练小型模块 B 不等于给 GPT 做 post-training。修改 prompt、skill 或缓存也不改变 GPT 权重。

本轮实际是“冻结表示 + 两个小型监督模块 + 推断期 Agent”。有生物/临床语义的 state 不应仅因预测标签拟合好就宣称已得到构念验证。未来如积累了高质量状态/操作标注，才另设 Agent 后训练研究；不作为此次落地前提。

## 4. 数据选择与 80/20 的精确定义

80/20 是内部 pilot 的约定，不强行替换已有官方划分。20% 一旦冻结不参与该版本的预处理拟合、提示设计、范例、训练、融合器或阈值选择。80% 内仍须生成 OOF 预测以训练模块 B。

| 通道 | 候选池 | pilot 总数 | 训练/开发 | pilot holdout | 本轮排除 |
|---|---|---:|---:|---:|---|
| 结构化多任务 | PREPARE 1622 名 historical train | 150 | 120 | 30 | 官方 412 测试病例 |
| 图片描述（英文） | ADReSS 81 名 historical train | 81 | 65 | 16 | 旧 27 人 holdout |
| 图片描述（中文） | NCMMSC 120 名 official train | 120 | 96 | 24 | 官方 53 人、全部 6 秒音频 |
| 临床访谈 | IAEAV 既有采集组隔离 | 不另建 80/20 | 保留209历史训练边界 | 14 压力病例 | 不随机拆散采集批次 |
| 公开讲话 | DementiaNet 既有人物隔离 | 不另建 80/20 | 保留14历史训练边界 | 6 压力人物 | 不按录音行随机拆分 |

前三个 pilot 351 名，另有 20 名压力病例。只在前三个 pilot 训练新的 A/B 并报告开发校准后的新框架分类效果。IAEAV/DementiaNet 本阶段提供 Agent 独立判断、证据行为、失败率及已有基础预测的描述性对照；没有适用且有效的校准器，不冒称新联合模型风险已校准。公开讲话现有 report-only 设置必须在结果中显式标示，不为凑非零贡献绕开。

PREPARE 的 150 名用预声明随机种子从 train pool 按类别和语言可行分层抽样，尽量保持原流行率。任务覆盖是检查项；稀有交叉单元不足时输出缺口，不复制患者或按结果换样。任务/语言/类别过稀则先按类别分层，不硬凑所有笛卡尔组合。120/30 每类覆盖和训练折可行性由数据管理员在运行前确认。

ADReSS 65/16 是约 80/20 的固定整数分配；NCMMSC 是 96/24。身份分组优先于人数完全相等，若来源重复组使目标人数不可达，则记录实际人数与原因，并在调用前冻结。患者 UID、语料目录和文件名在进入 Agent 前伪匿名化，不泄露 HC/MCI/AD 标签。

这些内部 holdout 是开发性 pilot，而非确认性外部证据。PREPARE 30 人中一个判断改变就相当于约 3.3 个百分点，ADReSS 16 人中为 6.25 个百分点，不足以证明与 SpeechCARE 的细小差异。

## 5. 单个 pilot 的完整训练顺序

以 PREPARE 的 150 人为例，其余两个 pilot 使用相同算法、分别拟合，不混合疾病标签或患者。

1. 数据管理员冻结 120 名 development 与 30 名 holdout、标签文件和来源清单。推断 runner 看不到标签；评估器在输出冻结后连接标签。
2. 只读取 120 名训练患者，核验原始音频/ASR与缓存。可复用的缓存只能是无本地测试标签适配的原始测量或冻结编码器输出；历史全数据归一化、参考范围、特征筛选、state数值、监督预测不能直接复用。
3. 在 120 名中生成固定的 5 个患者分组折，每次约 96 人 fit、24 人 OOF。每折重新拟合缺失值处理、尺度、正常参考与模块 A。采样不均时保持实际组数，保存失败原因。
4. 为每个 OOF 患者生成该折独有的 MetricEvidence/StateCard(v0) 和基础预测。Agent 看 v0、必要原文与 skill，不看基础概率、真值、类别目录。
5. Agent 首轮返回状态/关系判断、类别支持评分与可选修订。原版输出构成 J-A；合法修订执行后重算状态，构成 J-S 的输入。修改数值或引用语境影响原评分时，原评分失效。
6. 存在被接受的实质修订时，同一 Agent 最多再判断一次 v1，不允许第二次改证据、改提示或开启新循环。J-AS 使用 v1 的判断和对应版本的 state delta；无修订时可复用首轮判断。最多两次调用，没有隐式无限修复。
7. 合并 120 名 OOF 记录，拟合模块 B。第一版固定一种强正则低维模型，无超参搜索。为每个可用 head 学习基础分数、Agent类别对比与state delta的作用，配置在看 holdout 前冻结。
8. 在全部 120 人上重新拟合最终模块 A，模块 B 仍仅拟合 OOF 记录，不能用 A 的训练内预测替换 OOF 表。模块 B 的训练分数不作为实验效果。
9. 对 30 名 holdout 各运行一次冻结链路，保存 B、J-A、J-S、J-AS 的预测、失败与回退。证据处理与参考值均来自 development。只有此时连接 holdout 真值。
10. 输出患者级 help/harm、分类指标、区间、证据干预与调用成本。若据此修改设计，该30人从此属于开发反馈集；不能继续声称后续版本是在未见测试集上确认。

第一版模块 B 的明确起点：两个分开的二项 head，特征为 base log-odds、Agent 相对评分、state replay log-odds delta 和截距。base log-odds 保持原尺度，以使 `(1,0,0,0)` 确实恢复基础预测；其余连续特征只在训练数据中拟合尺度，保存转换参数。最小化平均交叉熵加系数向 `(1,0,0,0)` 收缩的 L2 项，初始 `lambda=1.0`，非截距系数约束为非负。此为预注册开发候选，不保证最优。若 Agent 不可用，先走声明的基础回退；不能简单把缺失当中性训练成疾病特征。训练中仅把可用决策记录用于相应融合 head，最终 holdout 指标仍包含全部分配患者与回退。

基础模型参数在看 holdout 前固定为现有通过测试的候选配置，输出其 resolved config。若要比较 lambda、温度、特征组合或状态算法，另启 inner-CV 协议，每个内层验证折的上游拟合与 Agent 上下文都必须重新隔离；不复用看过其标签的 meta 输入做选择。首版不做该搜索以控制成本。

## 6. Pilot 要比较什么

主对比：同一患者上的无 Agent 基础模型 B 与 J-AS。B 必须使用相同 OOF 开发数据和同等校准预算，只拟合基础分数的斜率与截距；原始未校准概率单列 B_raw。这样不会把普通校准增益误算为 Agent 增益。回退采用已经冻结的 B，无有效 Agent 时不能失去基线校准。另做一项训练病例完全匹配的敏感性比较，检查 Agent 失败导致的训练记录选择是否影响增益判断。J-A/J-S 用于识别判断贡献和修订贡献，避免把一条贡献累计两次。旧报告分数不能直接作此对照，因为新 pilot 训练人数与切分不同。

训练人数减少可能使分数低于历史全量模型，这不直接否定新设计。新设计的有效性先看同训练规模和划分下的配对变化；与 SpeechCARE 的性能竞争力须后续用完整 development 和匹配测试协议评价。

模型比较在第一个固定 pilot 版本通过后进行。预先选 24 名 development 患者，同事实/skill下运行 strong-flat、strong-structured、cheap-flat、cheap-structured。已有完全相同输入与版本的输出可复用；这24人仅用于可行性，正式模型×框架交互扩展到全部预声明配对样本后才做推断。

强弱是待测能力，不由型号名称保证。运行前记录可调用精确模型 ID、推理设置和预算；第一版用一个较强模型减少能力不足与接口缺陷混杂，工程与报告编写可交给更便宜的模型。框架升级后做一次参数再校准；将“直接替换”结果与“重新校准”结果分开。

## 7. 操作顺序与验收门槛

| 关口 | 具体工作 | 必须生成的文件 | 下一步条件 |
|---|---|---|---|
| G0 | 冻结代码快照、清点患者与协议、缓存资格 | source_manifest、split_manifest、cache_provenance、resolved_config | 身份/来源无跨分区泄漏；排除有凭据 |
| G1 | 资格/质量/增量分离、统一unknown、部署/研究边界 | schema契约、共享证据与冲突组合测试 | 不再结构性全禁用；不接受非法证据 |
| G2 | A 的折内拟合与 B 校准 runner | fold manifests、OOF表、calibrator、sanity results | OOF无训练内预测；回退可复算 |
| G3 | 24个缓存工程病例 + 每通道少量真实 canary | operation trace、usage、失败原因 | 身份/版本校验全通过；调用有上限 |
| G4 | 三个pilot的development拟合与固定holdout评估 | 全病例 predictions、help/harm、Layer A/B | 完整预定样本；失败病例不丢弃 |
| G5 | IAEAV与公开讲话20例压力检查 | stress outcomes、identity/confound audit | 仅按压力测试解释，无跨域校准冒称 |
| G6 | 普通/结构化与模型版本配对实验 | matched_model_matrix、cost曲线 | 输入、预算、病例和skill匹配 |
| G7 | 汇总与交接 | system_report.html、evaluation_report.html、handoff.md | 明确已完成/失败/未测，不把pilot写成正式超越 |

canary 只用 development 或已有工程病例。用于调整提示或代码的病例标记为 engineering-only，不进入该版本效应估计；抽样前预留备用开发病例，不从 holdout 借病例。若仅同一冻结版本测接口/时延且无任何据其结果修改，保留调用日志并声明是否计入研究样本。

G4 不逐例根据准确率决定继续与否。出现泄漏、损坏文件、不可追溯修订、无限重试立即暂停；普通误判按预定 pilot 完整记录。若结果无增益，输出原因分解，进入新版本开发；保留旧版本，不能恢复旧高分冒称新结果。

## 8. 并行模型/Agent 的工程任务卡

先冻结共享契约，再并行；每个任务使用独立分支/worktree和明确写入范围。数据仅本地挂载，默认只跑合成测试，不擅自启动付费病例批次。

| 任务 | 推荐执行角色 | 写入范围/交付 | 依赖 |
|---|---|---|---|
| W0 契约与编排 | 主审模型 | schema、字段语义、共享/未知/版本约束、acceptance清单 | 本计划 |
| W1 数据与split | Terra级工程模型 | manifest/去标识/抽样/缓存检查及测试；不改融合 | W0 |
| W2 融合学习 | 具备统计实现能力的模型，主审复核 | joint fusion、OOF校准、head与fallback；不改数据源 | W0 |
| W3 Agent执行与重放 | Terra级工程模型 | bounded工具、v0/v1、计费、缓存、失败状态；不改校准公式 | W0 |
| W4 测试与报告 | Luna级工程模型 | 冲突组合/统计测试、固定HTML模板、图表与handoff | W1-W3接口已固定 |
| W5 独立验收 | 不参与核心修改的审查模型 | 泄漏、未知、方向、失效传播、模型对照审查 | 集成提交 |

任何两名执行者不同时修改同一核心文件。主审负责冲突整合和确认真正使用的代码版本；所有AI生成测试都必须有独立预期行为，不以“代码能跑”替代方法正确。模型名不是权限：测试窗口不能读取 holdout 标签来修 Agent。

## 9. 自动执行与输出契约

实施目标是一个有阶段和断点的研究运行器，顺序为 `inventory -> freeze_split -> fit_oof -> agent_assess -> fit_fusion -> evaluate_holdout -> stress -> render`。这是待实现接口，不声称已有某条命令可直接跑完。

每个阶段只依赖版本化输入，已有合法缓存跳过计算。数据、skill、模型、问题定义或上游表示变化就失效相应下游；只改图表就仅 render。一次启动可以完成已授权阶段，但必须在G0/G1等失效时自动停下并留下诊断。

每次运行目录包含：

```text
.local/runs/<run_id>/
  protocol/{source_manifest,split_manifest,resolved_config,provenance}.*
  folds/<dataset>/<fold>/
  predictions/<dataset>/{base,agent_only,joint,failures}.*
  traces/<dataset>/
  usage/{calls,totals}.*
  reports/{system_report,evaluation_report}.html
  handoff.md
```

图表英文，解释文字可中文。Layer A显示各库配对结果与区间，Layer B显示证据有效性、干预、回退与成本；压力集独立标识。没有新训练/推断的图不得贴上新版本标签。测试失败照样计入 denominator，纯Agent与有基础回退的系统指标分开。

## 10. API预算、时长与完成定义

核心有351个拟合/评估患者和20个压力病例。若全部需要新调用，一次首轮为371次；最多每例增加一次必要的修订后判断，则核心硬上限742次。有效缓存可减少调用。canary/模型对照单独列账，不能以一个371掩盖额外重复。
