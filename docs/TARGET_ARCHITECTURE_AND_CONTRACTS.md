# 8.27 目标架构与数据契约

## 一条病例的完整顺序

1. **病例注册**：生成去标识病例、访视、任务、语言、角色、音频资产和转录资产清单；原始路径和测试标签留在隔离的数据/评估域。
2. **角色/任务路由**：确认患者发言、访谈者发言、任务边界和纵向访视关系。
3. **质量检查**：检测缺失、削波、低信噪比、角色覆盖不足、ASR/对齐失败和异常时长。
4. **双表示提取**：生成可解释指标、文本预训练表示和音频预训练表示。
5. **MetricEvidence**：把指标变成带参考、方向、可靠度、混杂和片段引用的证据对象。
6. **StateCard**：在任务可观察性约束下形成病例级和任务级认知状态。
7. **监督模块 A**：形成数据驱动的初始类别概率和分支贡献。
8. **单一诊断 Agent**：依据 Skill 调用证据工具，检查支持、反证、任务冲突和原始片段，形成候选判断。
9. **认知审查与回退**：按医学优先级检查候选判断，发现违规即撤销相关状态或结论并重做。
10. **监督模块 B**：根据折内学习到的修正边界和校准器，决定候选修正是否进入最终概率。
11. **决策锁定**：保存最终类别、概率、不确定性、贡献和完整 trace。
12. **医生报告**：只翻译锁定决策和允许报告的证据。

## 三种“权重”必须分开

### 可观察性

回答“这个任务能不能测到这个状态”。例如没有说话人角色的公开视频不能可靠测患者轮次占比；没有标准答案的自由讲话不能测任务完成度。它是规则掩码，不是训练权重。

### 可靠度

回答“本次病例的这个测量能不能信”。初始工程实现分解为：

`coverage × role_confidence × alignment_confidence × measurement_stability × reference_support × qc_penalty`

每一项保留单独值，不能只保存一个无法解释的总可靠度。直接乘积是保守的初始聚合器，不是医学金标准。第一次训练前必须把乘积、几何均值、最小项和折内校准可靠度作为预注册候选，用内层数据比较；外层测试不得用于选择聚合器。

### 预测贡献

回答“在训练数据中，这个状态对当前任务的类别判断贡献多少”。它由监督模块折内学习，受可观察性掩码、可靠度和辅助声学权重上限约束。

## MetricEvidence 契约

每条证据至少包含：

- `evidence_id`：稳定、唯一、可回溯。
- `metric_id` 与 `state_id`：测量和临床构念。
- `value`、`unit`、`reference_median`、`reference_scale`、`directional_z`。
- `reference_scope`：训练折总体参考或语言/任务参考。
- `reference_provenance`：训练折参考产物、fold 和参考人群；禁止 test/full-dataset 参考。
- `observability`：当前任务是否适用及原因。
- `reliability_components` 与 `reliability`。
- `missingness` 与 `confound_tags`。
- `session_id`、`task_id`、`speaker_role`、`segment_ids`。
- `evidence_role`：临床证据、模型辅助或 QC。
- `report_permission`：能否进入医生报告。
- `report_permission_basis`：权限为何通过或被阻断；按 `REPORT_PERMISSION_POLICY.md` 预先计算，Agent 无权修改。
- `metric_validation_id`：条件指标可报告时必须解析到任务、语言和方法一致的验证产物。

其中 `direction` 不是“越大越严重”的随意约定，而是该指标相对状态异常方向的预注册关系。例如长停顿率升高支持停顿负担升高，发声比例降低支持输出效率受损。方向为零的指标不得参与临床解释。

## StateCard 契约

每个状态输出：

- `state_id`、名称和任务范围。
- `observability` 与不可观察原因。
- `category`：normal / borderline / impaired / unreliable / unavailable。
- `severity`、`confidence`、折内参考、状态内方法和权重版本。
- `supporting_evidence_ids`、`counterevidence_ids`。
- `segment_ids` 与轨迹摘要。
- `confound_tags`、`report_permission`。
- `within_state_method` 和使用的权重版本。

同一构念的高度相关指标先去重复或收缩，再融合，避免 TTR 和 MATTR 之类重复投票。状态内部默认使用可靠度约束的稳健加权；只有样本量和稳定性门槛满足时，才允许学习状态内权重。

## 监督模块 A：证据感知统计先验

输入分为语言状态、言语行为状态、互动/任务状态、模型辅助预训练表示和 QC 可靠度。任务类型和语言选择适配器；数据集 ID 不参与预测。

模型候选按样本量分级：

- 小样本：正则化逻辑回归/有序逻辑模型，固定状态内权重。
- 中等样本：分支专家 + 低容量可靠度门控。
- 足量样本：冻结编码器表示 + 低容量任务条件化门控；不在当前数据规模下端到端微调大型编码器。

输出 `p_prior`、分支贡献、状态贡献、模型不确定性和适用域告警。全部由 OOF 或 held-out 推理产生。

`severity` 是相对训练折参考的有方向状态偏离，不是疾病概率；不可观察时为 null。`confidence` 是状态证据覆盖与可靠度的聚合，不是模型置信概率。分类 `uncertainty` 使用归一化预测熵并结合折间/集成分歧，连续终点使用预测区间宽度相对目标范围的归一化值。所有定义写入运行配置，不允许报告生成器自行解释。

## 单一诊断 Agent

Agent 不是多个角色互相聊天，也不是一次自由 prompt。它拥有一个诊断目标、一个 Skill 和一组只读工具：

- `inspect_quality()`
- `list_states()` / `inspect_state(state_id, task_id)`
- `inspect_metric(evidence_id)`
- `inspect_segment(segment_id)`
- `compare_tasks(task_ids)`
- `inspect_prior()`
- `submit_candidate_decision()`

Agent 的候选决策必须包含全部类别概率、支持证据、反证、质量限制、状态修正和停止理由。没有引用的判断不能提交。

## CooT 风格认知审查

每次候选决策提交后，审查器按以下顺序检查：

1. 是否使用测试标签或源诊断标识。
2. 是否把 QC/设备/低层谱学证据作为疾病依据。
3. 状态是否在当前任务可观察。
4. 引用是否存在、属于当前病例并有报告权限。
5. 是否检查了最高优先级反证和任务冲突。
6. 是否出现不受支持的确诊、病理分期或机制解释。
7. 候选概率是否超出允许修正区间。

违规时记录 `violation_code`、`rollback_to_step`、被撤销的证据/状态和重做结果。该过程是 CooT 思想的临床证据化实现，不等于复现原论文的模型内部神经结构。

## 监督模块 B：受限修正和校准

训练输入只来自外层训练集内部再交叉拟合得到的 OOF 先验、Agent 轨迹摘要、证据质量和状态冲突。对任一训练病例，模块 A prior 和用于训练模块 B 的 Agent 轨迹都必须来自未见过该病例的模型。外层测试标签不参与。模块学习：

- `correction_eligible`：是否允许 Agent 候选影响概率。
- `max_delta`：二分类 logit、多分类 centered-logit 向量或连续值标准化差异的最大修正幅度。
- `temperature/calibrator`：最终概率校准。

最终决策只有在以下条件同时满足时接受修正：证据 ID 全部有效、修正方向有非 QC 证据支持、反证已检查、可靠度达标、未越界、嵌套验证不劣于模块 A。否则回退到校准后的 `p_prior`。

病例包、模块 A、Agent 决策、验证器、模块 B、锁定决策和医生报告必须共享 `run_id`、配置哈希、数据快照哈希和 Skill 哈希。任一项不一致，运行不得发布，以防旧概率、新报告和不同规则版本被拼接。

训练折参考和条件指标验证不能由病例包自我声明。它们必须解析到同一 provenance 下的 trusted artifact registry；运行时验证器重新计算实际 artifact 哈希，只有 frozen training-only 产物可用。病例包中的显示字段与可信注册表不一致时直接失败。

## Agent 与“后训练”的边界

当前闭源 GPT 不在本地通过这些患者数据做参数微调。本阶段使用的是推理时工程：版本化 Skill、结构化病例包、工具调用、固定输出 schema、认知回退和确定性验证。

当前完整运行不包含 GPT 参数后训练。未来若积累了独立医生审核轨迹，可另立研究协议训练低容量动作策略：学习下一步检查哪个状态/片段、何时停止、何时保持或提出有限修正。它不是本轮流水线的遗留步骤；没有医生审核的轨迹也只能训练证据遵从性，不能证明临床正确性。

## 一个最小示例

以下是历史故障材料，用来定义 8.27 必须捕获的错误，不是 8.27 运行结果。某图片描述病例的模块 A 输出 `HC 0.82 / AD 0.18`。状态卡显示不流利负担升高，但语速出现 432 WPM 的异常值，且音频与转录对齐可靠度低。

正确流程不是让 Agent 直接把“不流利”解释为 AD。Agent 先检查该状态的证据，发现异常语速可能由切分或 ASR 造成；审查器将该指标标记为不可靠并回退状态融合。Agent 再查看其他可报告状态和反证。若剩余证据不足，候选动作应为 `hold/abstain`，模块 B 保留或收缩先验概率，报告建议复测，而不是通过语言表达制造更强结论。
