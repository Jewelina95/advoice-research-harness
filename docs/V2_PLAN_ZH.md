# ADvoice v2 方案：理论、框架修改与工程计划

日期：2026-10-08。状态：方案，未实现。数字来自仓库历史审计和 SpeechCARE 论文（PMC12623413）；文献综述见 `LITERATURE_AD_SPEECH_LLM_2026-10.md`。

## 1. 三个条件

| 条件 | 内容 |
| --- | --- |
| A 传统方法 | 手工声学特征（或声学 + 文本特征）+ 分类器 |
| B 传统 Agent | 同一个 LLM 直接读病例做判断，有通用医学常识，没有本框架 |
| C 本系统 | SSL 表示 + MetricEvidence/StateCard + 知识库与约束 + 监督学习 + Agent，联合训练与校准 |

## 2. 为什么 C 赢 A

A 的错误主要有两个来源。

**信息上限。** 声学特征只看到“怎么说”：停顿、语速、音高、音质。AD 早期最典型的变化在“说了什么”：信息量下降、具体名词被代词和泛化词替代、叙述偏题、回忆遗漏与侵入。声学只能间接捕捉这些。C 加入了语言指标、文本表示，以及 Agent 测出的内容单元和连贯性，信息集是 A 的严格超集。

**捷径。** 声学特征对设备、麦克风距离、噪声、录音机构非常敏感，而不同数据集的病例和对照经常来自不同的采集条件。A 会学到这些捷径，同分布测试分数好看，换数据集就退化。C 的治理约束规定 QC 和设备变量只能影响可靠度，不能当疾病证据；健康参考按任务和语言分开。

所以 C 对 A 的优势是“更多信息 + 更少捷径”。前者体现在同分布测试，后者体现在留一数据集外验证。历史证据：同一编码器下加入认知框架，Accuracy +0.075、Macro AUROC +0.060。

## 3. 为什么 C 赢 B

B 的 LLM 能读懂语义，这是它真正的优势。但它单独做判断有五个结构性缺陷，C 逐一补上：

| B 的缺陷 | 后果 | C 怎么补 |
| --- | --- | --- |
| 不知道人群基线和类别比例 | 输出是偏好不是概率；三分类时 MCI 尤其容易塌缩 | 监督层从标签学类别映射，OOF 校准 |
| 不知道“正常是多少” | 不知道普通话图片描述的正常停顿率、70 岁人群的正常词汇量，只能凭常识猜 | 训练折内按任务、语言的健康参考，把原始值变成方向化标准分 |
| 感知不到时间和声学 | 只读转录时，停顿、语速、犹豫全部丢失 | 确定性测量先把它们测出来，作为证据给 Agent |
| 判断不稳定 | 换措辞、换采样就变；同一病例多次运行结论不同 | 固定 schema、多次采样一致性作为可靠度、确定性重放 |
| 理由可以编造 | 给出的解释不一定对应任何测量 | 每个主张必须引用证据 ID，权限和撤销由执行器检查 |

历史证据：通用 LLM 读状态的判别力接近随机（AUROC 0.48–0.53）。外部文献方向一致：ADReSS 上 GPT-4 零样本 AUROC 0.827，低于传统特征 + RF 的 0.885（Heitz 等，COLING 2025）；临床预测任务上 GPT-4 AUROC 0.63/0.60，GBM 0.85/0.89（Brown 等，JAMIA 2025）；只有精心挑选示例的上下文学习才在 ADReSS 上与 SVM/BERT 持平（Li 等，ACL 2025）。B 的问题不在“不够聪明”，而在于缺校准、缺常模、缺感知。

反过来，给 LLM 配上携带领域信息的工具后提升很大：肿瘤决策中 GPT-4 从 30.3% 升到 87.2%（Ferber 等，Nature Cancer 2025，20 个模拟病例）。这是“框架 + Agent”优于“纯 Agent”的外部旁证，但不是 AD 语音上的直接证据。

## 4. 为什么 Agent 单独没有增益，放进系统里才有

这是整个项目最需要讲清楚的一点。一个明确的判据是：

> 设监督部分已有的输入为 X，Agent 的输出为 a，标签为 Y。Agent 能带来增益的必要条件是 I(Y; a | X) > 0，即在已知 X 的前提下，a 仍然包含关于 Y 的信息。

这条判据同时解释了三件事。

**为什么 Agent 单独（B）没有增益。** a 里确实有语义信息，但 LLM 不知道 a 与 Y 在这个人群里的对应关系（缺校准、缺常模），信息被浪费在错误的映射上。

**为什么旧版 C 里的 Agent 也没有增益。** 旧版 Agent 读的是监督模型已经用过的停顿、发声状态，a 基本是 X 的函数，I(Y; a | X) ≈ 0。融合系数学到 0 是正确的。历史数字：改了 178/412 例的概率，只改变 2 个类别，一对一错。

**新版 C 里 Agent 的增益从哪来。** 把 Agent 放到它独有能力的位置上：读懂内容并按评分键测量。这些测量不在 X 里（内容单元、连贯性、回忆遗漏与侵入、任务完成度），满足 I(Y; a | X) > 0 的前提。同时 Agent 自己不做最终映射，由监督层从标签学 a 到 Y 的关系，补上 B 缺的校准和常模。

一句话：B 有信息但不会用，旧 C 会用但没有新信息，新 C 两者都有。

这条判据还给出了可直接检验的预测：Agent 测量与已有文本 embedding 的重合度越低，C 相对 S（无 Agent 的系统）的增益越大。

文献给出的一个重要限制：LLM 提取的语言特征叠加到有监督模型上，人工转录时 AUROC +0.046（0.885→0.931），换成 ASR 转录只有 +0.007 到 +0.012（Heitz 等）。PREPARE 和以后的真实使用都依赖 ASR，所以 Agent 测量的增益很可能被转录错误吃掉大半。这带来两个设计结论：一是 Agent 的质量审计角色（识别 ASR 错误、标记不可靠片段、降低其可靠度）和测量角色同样重要；二是测量要尽量对 ASR 错误鲁棒，例如按语义而不是字面匹配内容单元，并把 ASR 置信度并入可靠度。Agent 增益是否成立，必须以 ASR 转录上的消融为准。

## 5. 怎么超过 SpeechCARE

同一协议：PREPARE 官方划分（1,646 训练 / 412 测试），同指标（Accuracy / micro-F1、micro AUC、macro-F1、各类召回），10 个随机种子取均值；同时报告 PREPARE 官方排名指标 log-loss，它直接奖励校准，正是本框架 OOF 校准的强项。

| 差距来源 | 证据 | 措施 | 预期 |
| --- | --- | --- | --- |
| 编码器未微调 | 独立 ADvoice Accuracy 0.672 vs SpeechCARE 0.721；SpeechCARE 输出 + 我们的认知残差可到 0.735（回顾性） | 在训练折内微调 mHuBERT（分段 + 可学习 CLS）和文本编码器（LoRA），作为残差分支 | 追平主干是超越的前提，这一步与 Agent 无关 |
| 图片描述占 72% | PREPARE 2,058 例中 1,486 例是图片描述 | Agent 按评分键测内容单元、信息密度、偏题 | 这是 Agent 增益最可能出现的地方 |
| MCI 是 SpeechCARE 最弱的类 | 单个检查点 MCI 召回 43%（阈值优化后 55%）；我们 9.2 曾到 0.686（同时 HC、AD 召回下降） | 两头结构（HC/受损，MCI/AD）+ 认知状态 + 按类代价校准 | macro-F1 和 MCI 召回是最现实的超越点 |
| 任务异质 | 7 类任务 | 任务条件化的状态权重与可观察性掩码 | 减少不同任务间的互相干扰 |
| 人口学未进入常模 | SpeechCARE 消融：换融合方式差异 < 0.5 F1，加入年龄 +1.6 F1 | 健康参考按年龄段、教育、语言、任务分层，z 分数相对“同龄同任务健康人” | 投入产出比最高的一项，且与“相对健康参考”的框架天然一致 |
| 主干选择 | PREPARE Phase 2 按 log-loss 排名，前两名（0.6299、0.6343）均基于 Whisper 编码器，SpeechCARE 为 0.6460–0.6553，排第 4 | 残差分支候选同时比较 mHuBERT 与 Whisper 编码器，嵌套交叉验证里选 | 主干差距可能比想象的更容易弥补 |

注意：PREPARE 官方测试集已被多次查看，只能做回顾性比较。所有选择在训练集嵌套交叉验证里冻结后，测试集只评估一次，并在论文中如实说明。

## 6. 我们的融合与 SpeechCARE 的门控有什么本质不同

我们的目标不是照抄门控，而是做 SpeechCARE 结构上做不到的事。SpeechCARE 自己的消融也说明，融合方式之间的差异不到 0.5 F1，在门控结构上继续投入的回报很低。

| 维度 | SpeechCARE | ADvoice v2 |
| --- | --- | --- |
| 融合对象 | 三路模态（声学 / 语言 / 人口学） | 十几个临床状态 + 一个 SSL 残差 |
| 权重怎么来 | 门控网络从隐藏表示算出每个样本的模态权重 | 状态权重按任务学习，并在数据集之间部分共享（层级收缩） |
| 跨数据集 | 合并成一个模型训练 | 状态是跨数据集、跨语言共享的坐标系；共享部分从所有数据学，任务和数据集特异部分向共享值收缩 |
| 缺失与不适用 | 门控隐式处理 | 可观察性掩码显式处理，不可观察的状态不算正常 |
| 解释粒度 | “这个病例更依赖语言模态” | “这个病例因内容单元覆盖低和指代泛化而支持受损，残差占 30%” |
| LLM 角色 | 离线预处理 | 测量仪器 + 质量审计 + 受约束的报告 |

层级收缩是这里的核心创新点。每个数据集只有几十到一千多例，单独学状态权重方差很大。但“停顿负担”“内容单元覆盖”在 ADReSS、NCMMSC、PREPARE 里是同一个临床构念，所以可以让十个数据集共同估计一个共享权重，各数据集只学一个向共享值收缩的偏差。embedding 做不到这一点，因为不同语言、不同编码器的 embedding 维度没有共同含义。这不违反“不混库训练”的规则：混的是状态层的参数先验，不是把病例混成一个训练集。是否真的优于独立训练，需要用留一数据集外验证来检验。

## 7. 框架：原来怎么设计，现在怎么改

| 层 | 原设计 | 新设计 | 理由 |
| --- | --- | --- | --- |
| 音频与转录 | soundfile 读取；无响度归一化；无说话人分离；词级时间戳被丢弃 | ffmpeg 统一解码；LUFS 归一化；说话人分离；保留词级时间戳和 ASR 置信度 | 停顿和转录必须在同一时间轴上；角色错误会污染互动指标 |
| Metric | 声学 + 表层词汇 | 增加 Agent 测量的认知语言学指标（内容单元、连贯、偏题、回忆遗漏与侵入、流畅性聚类与转换、句法） | 满足 I(Y; a | X) > 0 |
| State | 手工固定权重；S09/S10/S11/S14 在主要通道多数未启用 | 启用这些状态；权重改为“手工先验 + 按任务学习 + 跨数据集层级收缩” | 信息与估计误差两方面都改善 |
| 可观察性 | 两处定义（observability yaml 为空，channel yaml 各自列表） | 单一 task × state 矩阵 | 避免两处不一致 |
| SSL | 冻结，只取最后一层，只看前 30 s | 折内微调或逐层选择，覆盖全长；只作为残差分支 | 追平 SpeechCARE 主干 |
| 监督模型 | 各分支逻辑回归 + 静态 stacking；动态门控未胜出 | 可分解模型：状态贡献 + SSL 残差，两头；Agent 独立判断作为堆叠候选 | 依据可信；保证 C 不劣于 B |
| Agent | 读同一批状态给类别分；融合系数 ≈ 0 | 三个角色：测量（主）、独立判断（堆叠候选）、审计与报告 | 让增益有来源 |
| 校准 | OOF 校准 | 不变，加按类代价，报告 MCI 召回 | 不变 |
| 报告 | 状态描述与概率来源脱节 | 按状态贡献排序“主要表现”，标明可解释占比 | 目标第 2 点 |
| 评估 | 小 holdout；Agent 作为融合系数检验 | A / A+ / S / B / B′ / C 六臂；主分析在训练集 OOF；测试集一次；留一数据集外 | 能说清赢在哪 |

## 8. Agent 的具体设计

**测量任务（第一批）**

1. 图片描述内容单元：输入带时间戳转录 + 该图片的信息单元表；输出每个单元是否提到、引用片段；派生覆盖率、单位时间信息量、不正确或泛化指代比例。PREPARE 中图片可能不止一张，需要先确认每张图片的评分键来源（未核实）。
2. 偏题与连贯：逐句判断是否与任务相关、与上一句是否连贯；派生偏题比例、局部连贯度。
3. 语义流畅性：分类聚类与转换次数、重复、侵入。
4. 故事回忆：要点命中、遗漏、侵入。

每项测量多次采样，把不一致程度作为可靠度。先在 50–100 例上做人工标注，测一致性，一致性不过门槛的测量不进入模型。

**独立判断**：与 B 同样的类别判断，但输入为框架证据包。作为堆叠候选进入监督层；学不到增益时系数为 0。

**审计**：只在“监督估计不确定 + Agent 测量与之冲突”的病例上触发，检查 ASR 错误、角色错配；修改后确定性重算。

**报告**：读锁定的贡献表写报告，不改数字。

**跨模型**：GPT / Claude / DeepSeek 只替换 Agent，评分键、队列、预算不变；记录测量一致性与下游增益两条曲线。

### 9.1 目标结构

```
src/advoice/
  io/        音频解码、响度、VAD、说话人分离、ASR（词级时间戳）
```

## 10. 不同数据集、不同数据类型分别学什么

### 10.1 现在已经决定的

- 每个数据集单独训练，不混库（交接文档的规则）。
- 每个数据集通过 `channel_profile` 选定可观察的状态集合（`configs/channels/*.yaml`），例如 ADReSS 启用 9 个状态，纯音频通道只有 5 个。
- Condition C 按样本量开关分支：文本 embedding 需要 ≥100 名训练受试者，音频 embedding 配置为 ≥80（代码默认值是 300，二者不一致）。
- HC/MCI/AD 用两个头：受损头和 MCI/AD 分期头。

没有决定的：哪些参数跨数据集共享、哪些按任务学、哪些按数据集学；按样本量选择模型容量的规则；按任务的 Agent 评分键。另有一处配置不一致：数据集同时有 `channel`（路由用，例如 NCMMSC 的 `structured_task_audio` 被路由到多任务家族）和 `channel_profile`（状态用，NCMMSC 是 `picture_description_asr`），两者对 NCMMSC 的任务类型说法不同，需要统一。

| ADReSS 2020 | 英 | Cookie Theft 图片描述 | HC/AD | 人工（CHAT） | 有 |

### 10.3 三层学习规则

**全局共享（所有数据集相同，不训练或只学先验）**：状态定义与异常方向、治理规则、权限、Agent 技能；状态权重的共享先验（层级收缩的中心）。

**按任务和语言（由数据类型决定）**：
- 可观察状态集合：单一 task × state 矩阵。
- 健康参考：按任务 × 语言 × 年龄段（× 教育，若有）分层的中位数与尺度。
- Agent 评分键：图片描述用信息单元表（每张图一份），流畅性用语义类别表，故事回忆用要点表，访谈用问题—回答对；自由讲话和公众人物讲话没有评分键，只测连贯性与偏题。
- Agent 的侧重点：人工转录的数据集以测量为主；仅 ASR 的数据集审计（ASR 错误、不可靠片段）同等重要；无角色的数据集先做说话人分离，互动状态在角色不可靠时不可观察。

**按数据集训练（容量随样本量分级）**：

| 档位 | 数据集 | 学什么 |
| --- | --- | --- |
| 大（≈2,000） | PREPARE | 编码器折内微调；状态权重可自由学习；可尝试样本级门控；两头完整训练 |
| 中（约一百到数百） | ADReSS、ADReSSo、Pitt、NCMMSC、TAUKADIAL、PROCESS-2 | 编码器冻结，逐层线性探针；状态权重向共享先验收缩，只学偏差；分类头 + 校准 |
| 小（几十以内） | IAEAV、DementiaNet | 不训练新模型；用共享状态权重 + 本数据集健康参考 + Agent；只做压力测试和描述性报告 |

标签不同的处理：受损头在所有诊断数据集上训练；分期头只在同时有 MCI 和 AD 的数据集上训练（PREPARE、NCMMSC、PROCESS-2）；TAUKADIAL 只有 HC/MCI，只训练受损头；ADReSSo 进展是不同终点，单独一个头，不与诊断混合。

各数据集准确样本量以 `raw data/_manifests` 的清单和冻结的数据清单为准，上表的档位需在阶段 1 中按实际清单核对。

## 11. 与旧工作相比升级了什么、需要多久

### 11.1 保留不动的

证据对象和 StateCard 合同、治理不变量、受试者分组与 OOF 收据、校准与锁定、报告权限、预算与遥测、1,305 个测试。旧代码不删除，迁入 `legacy/`，历史报告可复现；新工作在独立分支，main 不受影响。没有需要“恢复”的东西，阶段 1 的验收标准就是用新结构重跑 ADReSS 2020，数字与历史一致。

### 11.2 新增或改变的

1. Agent 角色：从“读同一批状态给类别分”改为测量 + 审计 + 堆叠候选。
2. 可分解预测：报告依据与概率来源一致。
3. 分层健康参考（年龄、教育、语言、任务）。
4. 编码器微调或 Whisper 主干比较。
5. 状态权重的跨数据集层级收缩；按样本量分级的容量规则。
6. 输入层：统一解码、响度、说话人分离、词级时间戳。
7. 六臂评估和三家模型比较。
8. 代码收敛为一条主线。

### 11.3 时间估计

按“代码由 Agent 编写、你负责审查和决定”估算。工作日是编码与验证时间，日历时间包含计算、API 运行和人工标注的等待。

| 阶段 | 工作日 | 主要等待 | 日历时间 |
| --- | --- | --- | --- |
| 1 结构收敛 + 配置统一 + 样本量核对 | 3–4 | 无 | 1 周 |
| 2 输入层 + 10 个数据集重新提取（带词级时间戳的 ASR） | 2 | 约 60 GB 音频在 M2 Max 上重新转写，1–3 天 | 1 周 |
| 3 可分解模型 + 分层参考 + 层级收缩 | 3–4 | 无 | 1 周 |
| 4 编码器微调（PREPARE） | 2 | 每折每种子的训练时间未实测；先跑 1 折测时，再定种子数 | 1–2 周 |
| 5 Agent 测量（图片内容单元、偏题/连贯）+ 评分键 + 一致性标注 | 3 | 评分键来源确认；50–100 例人工标注 | 1–2 周 |
| 6 六臂评估 × 三家模型 | 2 | API 运行与费用审批 | 1 周 |
| 7 冻结与一次性测试 | 1 | 无 | 2–3 天 |

合计：编码约 16–18 个工作日，日历时间约 6–8 周。阶段 1–4 不需要 API，可以立刻开始；阶段 3 和 4、阶段 2 和 5 的评分键准备可以并行，最快约 5 周。最不确定的两项是阶段 4 的计算时间和阶段 5 的人工标注。
