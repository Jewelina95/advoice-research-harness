# ADvoice v2：原理复核与单音频端到端设计

日期：2026-10-08。状态：设计稿，未实现、未跑真实数据。本文基于仓库文档与历史审计数字，不新增实验结论。

## 0. 目标

输入一段患者语音（MP3/WAV，可无转录），输出两样东西：

1. 一个校准过的筛查估计：HC / MCI / AD（或数据集定义的类别）概率和不确定性。
2. 一份医生端报告：本次筛查结论、支持这一结论的主要表现（具体测量与同任务健康参考的比较）、同时保留的能力、解释范围与待补资料、建议的下一步。

第 2 点的硬约束：报告里列为“支持结论的主要表现”的东西，必须真的是推动这个估计的东西。

## 1. 现有原理是什么

仓库的理论核心是 Evidence Governance（`docs/EVIDENCE_GOVERNANCE_THEORETICAL_FRAMEWORK_ZH.md`）：原始观察 → 测量 → 带来源、语境、可靠度、权限的证据对象（MetricEvidence）→ 任务可观察性约束下的认知状态（StateCard）→ 预测 → 主张 → 报告；并用 G1–G9 不变量（来源完整、语境适用、重复幂等、缺失中性、权限不升级、修订闭包、冲突保留、轨迹完整、发布一致）约束全过程。

框架自己的命题 5 写得很清楚：治理不蕴含准确率提升。它保证的是可追溯、可撤销、不越权，不保证分得更准。

历史数字（`docs/PREPARE_SPEECHCARE_GAP_ROOT_CAUSE_2026-09-03.md`）给出的事实：

| 观察 | 数字 | 含义 |
| --- | --- | --- |
| 同编码器下加 MetricEvidence/StateCard/路由 | Accuracy +0.075，Macro AUROC +0.060 | 结构化认知证据本身有增量信息 |
| 训练折内状态原型，开发集 OOF n=1,622 | HC/受损 AUROC 0.627 | 状态有弱但真实的判别力 |
| Agent 独立证据似然 | Macro AUROC ≈ 0.48–0.53 | 通用 LLM 读同一批状态，接近随机 |
| Agent 改概率 178/412 例 | 只改变 2 个类别，1 对 1 错 | Agent 净增益 ≈ 0 |
| 独立 ADvoice vs SpeechCARE | Accuracy 0.672 vs 0.721 | 主干落后，SpeechCARE 端到端微调 mHuBERT+mGTE |

由此得到三条原理层面的结论。

**结论 1：Agent 没有增益，是因为它没有新信息。** 当前 Agent 读的是监督模型已经用过的同一批停顿/发声/韵律状态，再加转录。监督模型已经从这些数里学到了统计关系，一个没有见过标签的通用 LLM 只能凭常识重新估计一次，自然打不过训练过的模型。融合层再加先验 `[1,0,0,0]` 和非负约束，Agent 系数被压到 0 是正确行为，不是 bug。

**结论 2：认知语言学层几乎是空的。** 实际计算的语言指标是词数、语速、TTR/MATTR/MTLD、填充词、修正、重复、代词比例、实义词比例，加一个基于关键词组的图片内容单元覆盖率（`transcripts.py:230-257`），但 S10 在图片描述通道里没有启用。S09 语义连贯、S10 信息密度与内容单元、S11 句法复杂度、S14 任务表现在主要通道里都被标为不可用。AD 语言学研究里最常被报告的信号恰恰在这几类：图片描述的信息单元、语义流畅性的聚类与转换、故事回忆的遗漏与侵入、叙事连贯性。系统最该有的证据，正好没有。

**结论 3：预测和解释来自不同来源。** 医生端 demo（`127.0.0.1:8765`）病例 05（`MCI_F_122608`，NCMMSC）显示 MCI 81.7%，但三条主要表现中两条“接近同任务健康参考”、一条轻度偏离；病例库中的 `AD_F_040102` 显示 AD/ADRD 49.0%，列出的状态全部接近健康参考。概率主要来自 mHuBERT/文本 embedding 分支，报告只能讲状态，而状态不支持这个结论。按目标第 2 点，这份报告不合格。这是当前设计最核心的缺陷，比代码冗余更重要。

## 2. v2 的原理：可分解预测 + Agent 作为测量仪器

### 2.1 可分解预测（解决结论 3）

最终 logit 写成两部分之和：

```
logit_k(x) = Σ_s β_{k,s} · z_s(x)          # 可解释部分：状态贡献
           + γ_k · r_k(x)                    # 残差部分：SSL embedding 分支
           + b_k
```

- `z_s` 是状态 s 的方向化标准分（训练折内健康参考），不可观察时为 0（缺失中性，G4）。
- `r_k` 是 embedding 分支对“状态没解释掉的部分”的预测（在训练折内对状态部分做残差拟合，或作为单独头再做 stacking）。
- 报告直接用 `β·z` 排序“支持这一结论的主要表现”，并显示残差占比：`|γ r| / (|Σβz| + |γ r|)`。
- 残差占比超过预注册阈值（例如 0.5）时，报告必须写“本次估计主要来自整体声学/语言模式，具体可解释表现支持不足”，并降低报告置信等级。这正好是上述两个 demo 病例应该出现的文字。

这是带侧通道的概念瓶颈思路：可解释部分负责“为什么”，残差负责“分得准”，两者的比例对医生透明。它把“要不要用 mHuBERT”的问题变成一个可测量的权衡：残差带来的 AUROC 增量 vs 报告可解释占比的下降。

### 2.2 Agent 的位置（解决结论 1、2）

Agent 从“第二个分类器”改为“测量仪器 + 质量审计员 + 受约束的报告撰写者”。

| 角色 | 输入 | 输出 | 如何验证 |
| --- | --- | --- | --- |
| 测量仪器（主角色） | 带时间戳的转录、任务说明、知识库里的任务评分键（如 Cookie Theft 信息单元表） | 新 MetricEvidence：内容单元覆盖、语义连贯、偏题、回忆遗漏/侵入、流畅性聚类与转换、句法复杂度；每项引用片段 ID | 与人工标注的一致性（小样本即可）；进入状态模型后的折内消融 ΔAUROC |
| 质量审计员 | 转录 + ASR 置信度 + 角色切分 + 声学 QC | 标记 ASR 错误、角色错配、不可靠片段 → 可靠度下降或证据撤销（已有 executor/replay 机制） | 注入错误的忠实性实验（理论文档 9.3） |
| 报告撰写者 | 锁定的决策、`β·z` 贡献表、残差占比、权限过滤后的证据 | 医生报告文本 | 报告结构审计 + 医生评分；不得改数字 |

关键变化：Agent 不再直接输出类别概率参与融合。它产生的是监督模型以前没有的新特征。Agent 的价值通过普通的特征消融来测量：同一折、同一监督模型，有/无 Agent 派生状态的 OOF 对比。

这同时回答“为什么要用 Agent”：

1. 内容单元、连贯性、任务完成度这类指标，传统做法要么需要人工标注，要么需要针对每个任务、每种语言单独写规则。LLM 按评分键在零样本下完成，跨英文/中文/西班牙语使用同一套接口。这是十个数据集、多通道、多语言场景下的实际工程收益。
2. 小样本数据集（IAEAV、DementiaNet、ADReSS）没法训练好的语言模型分支，但 LLM 测量不需要训练。
3. “模型越强、结果越好”的论点有了干净的检验方式：固定框架和评分键，换 GPT/Claude/DeepSeek，测（a）与人工标注的一致性，（b）下游 ΔAUROC。这比“Agent 系数随模型变大”更可测。
4. 可审计报告本身是临床可用性价值，但不算准确率增益。

### 2.3 为什么现在的评估测不出 Agent 增益，以及怎么改

| 问题 | 现状 | 改法 |
| --- | --- | --- |
| 样本量 | 内部 holdout 16–30 例；30 例下配对比较能检出的差异约在十几个百分点量级 | 主终点放在完整开发集 OOF 上（PREPARE 开发集 n≈1,600），用重复分组嵌套交叉验证；holdout 只做确认 |
| 增益的位置 | Agent 作为融合层的一个系数，先验向 0 收缩、λ 固定 1.0、无超参搜索 | Agent 输出作为特征进入状态模型，增益 = 有/无 Agent 特征的 ΔAUROC / Δlog loss，内层折选正则 |
| 多数据集 | 每个数据集单独判断，各自都太小 | 按数据集分层的配对 bootstrap 合并 Δ，同时报告每个数据集的方向；只训练不混库，合并的是效应量 |
| 主终点 | 多个指标并列 | 预注册一个主终点（建议 Macro AUROC 或 log loss 的配对差），其余为次要 |
| 模型比较 | 未定义 | 同队列、同评分键、同预算，模型是唯一变量 |

## 3. 单个 MP3 进来时的完整流程（v2）

```
MP3/WAV
 → [1] 解码与标准化：ffmpeg 解码，单声道 16 kHz，保存原始哈希；削波、信噪比、时长 QC
 → [2] 分段与角色：VAD；若有访谈者则说话人分离并标注 patient/interviewer；角色置信度进入可靠度
 → [3] ASR：Whisper 系（本地，转录不出机器），保留词级时间戳和置信度；语言自动识别 + 任务配置校验
 → [4] 任务路由：任务类型决定可观察状态集合（一份 task_state_matrix，唯一来源）
 → [5] 确定性测量：停顿/发声/语速/韵律（声学）；词汇/不流利（文本）
 → [6] Agent 测量（可选，需外发授权）：内容单元、连贯性、回忆、流畅性聚类、句法 → 新 MetricEvidence
 → [7] Agent 质量审计：ASR/角色问题 → 可靠度下调或撤销 → 确定性重算
 → [8] StateCard：训练折内健康参考的方向化标准分
 → [9] 可分解预测：Σβz + γr，两头（HC vs 受损；MCI vs AD），OOF 校准
 → [10] 锁定：概率、贡献表、残差占比、所有哈希
 → [11] 报告：Agent 按锁定内容写医生报告，权限过滤，不改数字
```

mHuBERT/文本 embedding 只进入 [9] 的残差分支，不进入 Agent 窗口：embedding 对 LLM 不可读，放进去只会增加 token 和伪解释风险。

### 3.1 SSL（mHuBERT 等）要不要用

要用，但位置要对：

- 作为残差分支：它是目前与 SpeechCARE 差距的主要来源（对方端到端微调）。PREPARE 规模（约 1,600 开发例）可以在折内做轻量微调（最后几层或 LoRA）；ADReSS、NCMMSC 这类小数据集保持冻结，用逐层线性探针选层。
- 作为测量工具：SSL 表示可以用来提升 VAD、强制对齐、音素级停顿定位的质量，这时它服务于可解释指标，而不是直接预测。
- 不作为 Agent 输入。

### 3.2 安全与数据合规

- 外发 API 之前：去标识化（姓名、地点、日期、机构）；音频永不外发，只发转录片段和数值。
- 每个数据集的使用协议需要逐一核对是否允许发送给第三方模型服务；无法确认的数据集只用本地模型或不跑 Agent 测量。这一点目前未核实。
- 转录内容视为不可信输入（提示注入隔离，现有 transcript quarantine 保留）。
- 拒答、超时、schema 不合格一律记为失败并留在分母；不开模型级自动 fallback。
- 每次调用记录模型 ID、日期、prompt/skill 哈希、token 与费用。

## 5. 工程整合方案

目标是一条主线、一个单例入口、一份可观察性定义。

1. **单例入口** `advoice screen <audio> --task <task> --bundle <model_bundle>`：解码 → ASR → 测量 →（可选）Agent 测量/审计 → 状态 → 加载冻结模型包预测 → 锁定 → 报告。模型包由训练命令导出，包含状态参考、β、残差分支、校准器和全部哈希。demo 改为调用它。
2. **主线收敛**：`pilot/` 的 contracts/learning/runtime/reporting 作为唯一主线。B2/B3/report/scoring 四个旧 Agent、`authority_*`、`conditional_authority*` 在 pilot 复现历史 B/J 数字后移入 `advoice/legacy/`，只保留复现历史报告所需的入口。`report_agent.py` 现在即可删除（仅测试引用）。
3. **一份可观察性**：`configs/observability/default.yaml` 的 `task_state_matrix` 与各 channel yaml 的 `enabled_states` 合并为单一来源，代码只读这一份。
4. **一个 provider 层**：pilot 的 `AssessmentProvider` 协议用 `agent_runtime.run_api_batch` 实现真实适配器（已支持 OpenAI/Claude/DeepSeek）；所有外发统一经过 pilot 去标识与注入隔离，B2 的未去标识外发路径关闭。
5. **配置与代码默认值一致**：门槛、模型 ID、窗口长度只从配置读。

## 6. 落地顺序

1. 单例入口 + 模型包导出（不改模型，先让现有 Condition C 能对一个新 MP3 出概率）。
2. 可分解预测：在现有分支专家上改为“状态线性头 + embedding 残差头”，报告显示贡献表和残差占比。用 PREPARE 开发集 OOF 比较与现有主干的 AUROC 差。
3. Agent 测量仪器：先做图片描述内容单元和语义流畅性两项，带评分键；在小规模人工标注上测一致性，再做折内消融。
4. 跨模型比较：同评分键、同队列，GPT / Claude / DeepSeek。
5. 工程收敛与 legacy 迁移穿插在 1–4 之间，每一步全量测试保持通过。

## 7. 未核实、需作者输入

- 各数据集使用协议是否允许把转录发给第三方模型 API。
- 内容单元评分键的来源与授权（Cookie Theft 等标准图片的信息单元表）。
- 残差占比阈值、主终点的预注册取值。
- 医生端报告是否需要显示残差占比这种技术量，还是只显示“可解释依据充分/不足”。
