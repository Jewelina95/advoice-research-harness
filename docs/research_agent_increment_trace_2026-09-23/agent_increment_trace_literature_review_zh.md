# Agent 增量、解释性与证据链回溯：文献定位与 ADvoice 研究设计

日期：2026-09-23

性质：聚焦方法定位的叙述性综述与当前实现核对，不是临床有效性结论。

## 核心结论

Agent 可以产生增量，但这个增量不能用“报告写得更完整”或“展示了思考过程”来证明。对 ADvoice 而言，Agent 的潜在增量只有三类：

1. **证据增量**：发现监督模型未正确处理的遗漏、冲突、任务不适用、说话人错误或测量污染，并对证据状态提出有类型的修订。
2. **决策增量**：在相同输入、相同编码器和相同数据划分下，经过证据审查与重放后，净纠正的病例多于新引入的错误，并改善校准或临床净获益。
3. **工作流增量**：把最终判断组织为医生能够检查的主张、证据、反证、限制和下一步建议。它改善可审查性和使用价值，但本身不等于预测性能提升。

其中前两类才能支持“Agent 改善诊断”；第三类只能支持“Agent 改善交付与审查”。现有代码已具备较强的来源约束和重放基础，但 Agent 的预测净增量与证据链忠实性仍未被完整实验验证。

## 1. 什么是解释性

“解释性”至少包含五个不同层级，不能混写成一个指标。

| 层级 | 要回答的问题 | ADvoice 可对应的对象 | 当前状态 |
| --- | --- | --- | --- |
| 来源可追溯性 | 这条信息来自哪个病例、任务、片段和算法？ | `source asset -> segment -> MetricEvidence` | 已有结构和校验 |
| 临床语义可读性 | 原始测量被映射到哪个认知状态，方向为何？ | `MetricEvidence -> StateCard` | 已有，但状态构念仍需医学与跨语言验证 |
| 决策贡献 | 哪些状态真正改变了预测？ | 状态贡献、修订前后概率差 | 部分具备，尚未形成完整病例级贡献验证 |
| 忠实性 | 系统声明依赖的证据被删除或反转时，判断是否按预期变化？ | evidence revision + replay + counterfactual test | 有重放机制，缺完整干预实验 |
| 临床有用性 | 医生能否更快、更准确、更安全地理解和使用？ | 医生报告与用户研究 | 尚未建立临床用户实验 |

[W3C PROV](https://www.w3.org/TR/prov-overview/)解决的是来源与责任链，不保证医学判断正确；[Concept Bottleneck Models](https://proceedings.mlr.press/v119/koh20a.html)证明了中间概念可以被人为修改并传播到预测，但要求概念本身有效；临床论证系统使用支持、反驳和 proof graph 解释推荐为何成立，但多为规则驱动。ADvoice 应把三者结合为“可执行证据链”，而不是泛称“可解释 AI”。

## 2. 不能把自由思考链当成科学解释

大模型输出的 chain-of-thought 看起来有顺序，不代表这些文字真实决定了答案。[Lanham 等](https://arxiv.org/abs/2307.13702)发现 CoT 的忠实性随任务和模型变化，模型规模增大也不保证更忠实；[NLP 忠实解释综述](https://aclanthology.org/2024.cl-2.6/)把反事实干预、自解释模型和内部分析与普通自然语言理由明确区分。

因此论文中不应写“我们回溯了 Agent 的真实思考过程”。可成立的表述是：

> 系统保存并验证了一个可重放的决策来源链，记录 Agent 查看了哪些证据、执行了什么受约束操作、这些操作如何改变认知状态和预测，以及最终报告引用了哪些仍有效的对象。

这是一条 **executable evidence-decision trace**，不是对模型隐藏思维的读取。

## 3. 证据回溯是否已有传统基础

有，而且分属不同研究传统。

### 3.1 数据来源与审计日志

W3C PROV 用 Entity、Activity 和 Agent 描述对象、处理过程与责任主体。它适合表达：某个 MetricEvidence 由哪个音频片段和算法版本生成，某次 Agent 修订使用了哪些对象，哪个报告由哪次锁定决策产生。它支持完整性和责任审计，但不证明因果相关性。

### 3.2 临床论证与 proof graph

[Xiao、Zhou 与 Fox](https://pubmed.ncbi.nlm.nih.gov/36032002/)用 RDF/SWRL 和 proof knowledge graph 表达证据为何支持推荐；[Sassoon 等](https://doi.org/10.3233/AAC-200550)用 argumentation scheme 处理支持、冲突与偏好。它们证明“支持什么、反对什么、规则如何落到结论”可以被形式化保存。与 ADvoice 的差异是，这些系统主要从结构化临床知识和规则出发，不处理从语音片段、测量误差和任务差异形成动态认知状态的过程。

### 3.3 可干预中间概念

Concept Bottleneck Model 先预测人类可理解的概念，再由概念预测结果；修正概念后可以重新计算最终判断。ADvoice 的 StateCard 与概念瓶颈有亲缘关系，但当前 ADvoice 仍保留直接监督路径，因此不能自称纯 concept-bottleneck model。更准确的名称是 **具有可干预认知状态层的混合预测系统**。

### 3.4 临床 Agent 的顺序行动

[AgentClinic](https://doi.org/10.1038/s41746-026-02674-7)把诊断建模为顺序问诊、检查和工具调用；MedAgentBench 检验 EHR 中的计划与操作。它们证明 Agent 的价值应在行动轨迹和工具结果上评价，而不只是最终文本。但它们通常没有把底层语音事件、指标、认知状态、病例级修订、概率变化和报告主张连成一个统一可重放对象。

## 4. 与语音认知筛查工作的区别

| 路线 | 核心对象 | 已解决的内容 | 尚未解决的内容 |
| --- | --- | --- | --- |
| SpeechCARE | 声学、文本、年龄表示与动态门控权重 | 多模态表示、任务与语言条件下的预测 | 不提供片段到认知状态再到报告主张的可执行回溯 |
| 常见 SHAP/LIME/attention XAI | 特征或 token 的事后重要性 | 指出模型对哪些输入敏感 | 解释可能不稳定；通常不能修改证据后重放完整系统 |
| WATCH-SS 等模块化语音方法 | 少量可解释声学/语言指标与患者画像 | 临床可读的指标级表示 | Agent 不参与证据审查，状态修订和发布权限较弱 |
| LLM 叙事解释 | 特征归因加医学文字说明 | 把模型结果翻译成临床语言 | LLM 常位于预测之后，可能只是事后叙述 |
| ADvoice 目标方法 | 片段、MetricEvidence、StateCard、Agent 操作、重放预测、报告主张 | 联合管理来源、语境、权限、修订和发布 | 必须证明 Agent 操作真实改变正确病例，而非只增加结构复杂度 |

[2025 年语音认知筛查 XAI 系统综述](https://doi.org/10.1038/s41746-025-02105-z)只纳入 13 项研究，方法以 SHAP、LIME、注意力和特征重要性为主；仅少数工作检查解释稳定性，真实临床验证和标准化评价仍不足。这为 ADvoice 留出的空间不是“解释更多”，而是“让解释对象成为预测系统中的可执行、可撤销、可测试中间变量”。

## 5. ADvoice 当前实现到底已有多少

代码核对显示，当前系统不是只有文字化方案。

- `build_case_workspace` 生成去标签的 Agent 工作区，区分可报告状态、仅推断状态、质量证据、支持证据和反证，并创建受约束的检查计划。
- `replay_evidence` 对 EvidenceRevision 执行状态图重建，调用冻结的 Module A 重新计算，并绑定 evidence hash、state hash、model hash、packet hash 和 revision hash。
- `validate_report_trace` 验证 `claim -> StateCard -> MetricEvidence -> task/segment -> source asset`，拒绝未知 ID、跨病例、跨任务、过期修订、不可报告和质量控制证据。
- 决策锁与哈希提供完整性保证，使旧报告不能在证据修订后继续冒充当前结果。

这些实现已经超过普通“日志记录”，因为修订可以进入状态图并触发计算重放。但仍有三个边界：

1. `validate_agent_trace` 当前主要验证 Evidence ID 是否存在，尚未证明 Agent 查看这些证据是其诊断变化的原因。
2. 哈希能证明对象未被静默替换，不能证明医学解释正确。
3. 现有 pilot 没有稳定证明 Agent 在匹配协议下带来正的净纠正；近期架构审查还发现融合与评估实现问题，因此不能把结构完整性写成性能优势。

## 6. Agent 在系统中应完成什么

Agent 的角色不应是复制监督概率，也不应直接自由阅读所有转录后给出一个无法验证的结论。它应完成一个受约束的病例级审查循环：

1. 读取任务、语言、角色、质量和可观察性，不先看到测试标签。
2. 检查高影响 StateCard 及其支持、反证和源片段。
3. 识别结构化错误：证据不适用、方向错误、同源重复、测量污染、任务间矛盾或关键缺失。
4. 只能发出有类型的操作：保留、降权、标记不可用、请求重新测量或提出冲突。
5. 系统执行操作并重新计算 MetricEvidence、StateCard 和预测；Agent 不能手工改写概率。
6. Agent 在修订后的对象上提交最终病例判断及其 Evidence IDs。
7. 发布层生成医生报告，任何主张都必须回到当前修订版本的状态、指标和片段。

这使 Agent 的核心能力从“生成理由”变成“发现可修正错误并触发可验证重算”。

## 7. 如何证明 Agent 确实有增量

必须在同一编码器、同一数据、同一划分、同一标签映射下比较，否则测到的是输入或协议差异。

建议固定五个实验臂：

| 实验臂 | 内容 | 回答的问题 |
| --- | --- | --- |
| A | 冻结监督模型 | 没有 Agent 时的基准 |
| B | 监督模型 + Agent 证据审查与重放 | Agent 能否修复证据和状态错误 |
| C | Agent 独立盲判 | Agent 自身读取证据包的诊断能力 |
| D | 监督候选 + Agent 独立判断 + 验证集联合校准 | 两种判断能否形成稳定互补 |
| E | 监督模型 + 仅生成报告的 Agent | 把预测增量与报告增量分开 |

病例级必须报告：

- `help`: A 错、B/D 对；
- `harm`: A 对、B/D 错；
- `net correction = help - harm`；
- HC、MCI、AD 分层的转移矩阵；
- AUROC、macro-F1、balanced accuracy、log loss、Brier、校准曲线和 decision-curve net benefit；
- 不同任务、语言、数据通道和证据质量分层结果。

Agent 有预测增量的最低条件是：净纠正为正，并且不是通过牺牲 HC 或 AD 两端来偶然增加 MCI；概率指标和临床净获益不能系统性变坏。

## 8. 如何证明证据链是忠实的

论文需要把“证据链存在”升级为“证据链对结果有约束”。最关键的测试不是询问 Agent 为什么，而是干预它引用的对象。

1. 删除被引用的关键证据：对应 StateCard 和类别支持应下降。
2. 反转指标方向：状态方向和预测变化应按预设规则改变。
3. 复制同一来源证据：结果不应因重复行而增强。
4. 改写文字但保持数值与来源不变：结果应基本稳定。
5. 注入未知或跨病例 Evidence ID：校验器必须拒绝。
6. 把 QC 信号包装成疾病证据：发布层必须拒绝。
7. 修订源证据后重放：旧状态、旧概率和旧报告必须失效。
8. 删除 Agent 声称无关的证据：结果应比删除关键证据更稳定。

只有这些测试通过，才能称为 **faithful evidence trace**。仅有 trace presence rate 或完整哈希不足以证明忠实性。[Evidence over explanations](https://doi.org/10.1038/s44387-026-00092-4)提出的原则与此一致：医疗 AI 更应接受因果对齐、无关扰动、不变性和外部审计，而不是依赖漂亮的事后解释。

### 8.1 三种“回放”必须分开

1. **确定性系统回放**：从已保存的 EvidenceRevision 或 AgentOperation 开始，用冻结版本重算 StateCard、概率和报告。它能验证系统过程是否可复现。
2. **重新执行 Agent**：重新调用 GPT 选择证据和操作。模型版本、采样和上下文变化可能导致不同结果，因此它不是确定性回放。
3. **反事实证据回放**：删除、替换或反转证据后重新执行下游链，观察状态和预测是否按预期变化。它用于检验解释忠实性。

论文应主张第一和第三种能力，不应把第二种描述成对模型内部思维的复原。

## 9. 可以成立的新颖性表述

现阶段最稳妥的方法定位是：

> ADvoice 是一个面向任务条件化语音认知筛查的、保留来源并支持干预的证据状态 Agent 框架。系统将音频片段转化为具有语境、可靠度和权限的 MetricEvidence，再形成可修订 StateCard；Agent 通过受约束工具审查证据，系统重放修订后的预测，并将报告主张绑定到当前证据版本。

它相对于现有工作的潜在差异是：

- 不把模态权重当作临床证据；
- 不把自由 CoT 当作真实推理；
- 不把 LLM 仅放在预测之后写报告；
- 把 Agent 操作限制为可执行、可撤销和可重放的状态修改；
- 把预测链与报告主张链绑定到同一证据版本。

当前不能成立的表述包括：“系统回溯了大模型真实思维”“Agent 已证明提高诊断准确率”“证据链证明了医学因果机制”“哈希保证了解释正确”。

## 10. 对未来扩展的意义

可持续的部分不是某个 GPT 版本，而是证据契约：稳定 ID、任务可观察性、状态本体、权限、修订、重放和发布校验。未来模型能力增强时，可以替换 Agent，让它更好地选择证据、发现冲突和调用工具；只要所有操作仍通过同一证据协议，系统就能比较新旧 Agent 的净增量，并复现每次决策如何产生。

因此“系统回溯”的正确含义是：**可重放的决策来源与状态演化**。它可以跨模型、跨任务和跨数据通道延伸；自由思考文本则不能承担这个长期接口。
