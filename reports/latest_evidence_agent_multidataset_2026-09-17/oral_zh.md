# 最新版 Evidence Agent 多数据集分析：口语稿

这次不再使用旧版 B2，而是直接读取最新版系统保存的真实 case audit。每个病例都包含监督概率、Agent 审查前后的 StateCard、盲态 Agent 判断、Evidence ID 和门控结果。五组之间唯一变化是状态、Agent screening 和 staging 是否获得预测权限。

PREPARE 的九个病例最能展示联合框架的作用。监督模型准确率是 0.778。状态修正单独加入后提高到 0.889，Agent 独立判断单独加入后也提高到 0.889。完整联合模型修正了两个监督错误，没有破坏原本正确的病例，因此准确率和 Macro-F1 都达到 1.000，log loss 也从 0.712 降到 0.549。状态门控只触发 22%，Agent screening 只触发 11%，说明提升不是来自普遍放大 Agent，而是来自少数病例的有条件修正。

ADReSS 2020 的六个病例中，完整联合没有改变任何预测，结果与监督模型一致。这里不是 Agent 没有参与，而是状态和 Agent 都没有通过预测权限门控。系统保留监督模型 0.833 的准确率，没有因为加入 Agent 而下降。这体现了联合框架的回退能力。

ADReSSo diagnosis 只有三个病例。状态门控触发一个病例，分类准确率没有变化，但 log loss 从 0.611 降到 0.300，说明状态证据改善了概率置信度。Agent screening 没有通过门控，所以完整联合在这里主要表现为监督加状态。

NCMMSC 的三个中文病例是当前失败模式。完整联合没有提高准确率，状态和 Agent 冲突率达到 66.7%。这说明中文词汇、MCI 边界和状态方向还没有完成可靠校准。这个通道不能用三例结果证明有效，也不能强制提高 Agent 权重。

因此完整联合仍然是下一阶段应选择的架构，但理由不是它在每个小数据集上都获胜，而是它同时具备三种能力：在 PREPARE 中利用互补证据修正错误；在 ADReSS 中没有净增益时保持监督结果；在中文通道中把冲突暴露为明确的校准任务。正式性能结论仍需要扩大真实 Evidence Agent 样本，并在锁定测试集上验证。
