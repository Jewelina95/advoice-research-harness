# 中文口语汇报（约 4 分钟）

今天汇报的重点不是再增加一个语音分类器，而是把我们原来的监督模型升级成一个证据约束的 Voice Agent 系统。

整个系统有六步。语音进入后，先根据任务、说话角色、语言和数据来源完成路由。第二步把声学、语言和对话指标写成 MetricEvidence，每条证据不仅有数值，还有方向、可靠性、混杂因素和源片段。第三步把相关证据组合成 StateCard，例如词汇提取、信息密度、输出效率、停顿连续性和声音韵律。第四步用折内训练和 OOF 校准得到监督基础预测。第五步才让 Agent 独立阅读结构化证据包。它看不到基础概率和真实标签，但可以给出类别支持、检查状态冲突，并提出有限的、可执行的证据修订。第六步用验证集学习监督预测、Agent 判断和状态回放之间的联合关系，再生成预测、证据链和临床建议。

本次更新最关键的变化，是 Agent 不再只是把监督概率翻译成报告，也不允许它无限制覆盖基础模型。我们设置了五个比较臂：原始基础模型、校准后的基础模型、基础模型加 Agent 判断、基础模型加状态回放，以及 Agent 与状态回放共同参与的完整系统。这样可以分别回答 Agent 是否有独立增益、证据修订是否有增益，以及二者联合是否真正改善预测。

第二个变化是 trace back。报告里的每一个发现都可以回到对应的 StateCard，再回到 MetricEvidence，最后回到具体语音片段。状态发生变化以后，系统必须重新计算，不能拿修改前的判断继续使用。因此这里的可解释性不是事后生成一段文字，而是解释对象真正参与了计算，并且可以被重放和审计。

第三个变化是安全和工程边界。Agent 最多进行两轮语义评估和三项修订操作；不能创建不存在的测量、参考范围或诊断标签。HC、MCI 和 AD 分别统计帮助与伤害，调用失败、回退、token 和费用都进入正式分母，不能只报告成功病例。

现在能够确定的是，软件验证已经有一千二百六十项测试通过，五个比较臂、证据修订、回放、回退和成本记录都已经实现。页面里的跨数据集性能图属于已经锁定的历史评估快照，它说明系统在不同数据通道上能够运行，但不能拿来宣称这次新的 Agent 架构已经超过 SpeechCARE。

当前真实 pilot 暂时没有启动，因为独立审查发现 runner、OOF 收据绑定、完整评分和预算记账仍有阻断项。这个决定是必要的：如果在这些问题解决前运行，即使数字提高，也不能排除数据泄漏、样本缺失或不完整成本统计。修复通过后，我们会先做同分割的小型 pilot，再进行 PREPARE 与 SpeechCARE 的同协议比较。最终判定标准不是只看总体 accuracy，而是同时要求 Agent 相对匹配基础模型有净增益、HC/MCI/AD 不出现系统性牺牲，并且更强模型能在同一证据框架下带来稳定提升。

## 追加汇报：Agent 增益和 evidence trace 到底解决到什么程度

这里必须把两个问题分开。证据回溯链路已经在系统实现层面基本解决，但 Agent 的预测增益还没有被真实实验解决。

先说旧版本为什么没有 Agent 增益。旧版本先由监督模型给出概率，再把这个概率和证据一起交给 Agent。Agent 很容易围绕已有概率组织语言，而不是形成独立判断。同时，安全门控又拒绝了大部分 Agent 修正，所以最终预测仍等于监督模型。结果是 Agent 可以改善报告结构，却没有真正增加分类信息。这不是说明 Agent 一定无效，而是旧实验没有把 Agent 的独立信息和监督概率分离出来。

新版通过五个设计解决这个识别问题。第一，Agent 在第一轮判断时看不到监督概率和真实标签，只能阅读 MetricEvidence、StateCard、转录片段、反证、任务条件和质量限制。第二，Agent 输出的是 HC、MCI、AD 的有序证据支持和证据引用，不是直接复制一个概率。第三，Agent 只能提出有限操作，例如重新测量、修正说话角色或片段、标记混杂和撤销不受支持的解释；真正的数据修改由确定性的 executor 执行。第四，任何有效修改都会生成新的 evidence snapshot，受影响的 metric 和 state 必须重新计算，Agent 也必须重新判断，不能继续使用修改前的结论。第五，监督基础、Agent 判断和状态变化不是手工设权重，而是在完整 OOF 验证数据上联合校准。

五个比较臂让增益来源可以被拆开。B-raw 是未校准监督基础，B 是校准后的监督基础，J-A 是基础加 Agent 独立判断，J-S 是基础加状态回放变化，J-AS 是完整系统。只有 J-A 或 J-AS 在同一批有效病例上稳定高于匹配的 B，才能说 Agent 有预测增益。普通校准造成的提高、缺失病例改变分母、或者重复使用测试集，都不能算 Agent 增益。

Agent 在这里更接近一个相关残差专家，而不是第二套完全独立的诊断系统。原因是 Agent、StateCard 和监督模型可能读取了部分相同证据。如果直接平均几个概率，同一条词汇或停顿证据会被重复计算。新版只学习 Agent 相对监督基础新增的部分，并通过收缩约束让没有稳定增量的 Agent 系数回到零。这样既给 Agent 真实的判断权，也防止弱 Agent 在基础模型不确定时被错误放大。

接下来说明 trace evidence。现在一条结论的路径是：原始音频资产和转录，进入具体时间片段；片段产生带版本和来源的 MetricEvidence；相关指标形成 StateCard；StateCard 和反证进入 Agent assessment；Agent 操作生成父子 snapshot；最终预测绑定 assessment、snapshot、模型版本和 OOF 收据；报告只能引用允许报告的 evidence ID。医生看到“词汇提取困难”时，可以依次返回状态分数、支持和反对指标，再返回具体语音片段。这条链路不是模型生成的思维过程文本，而是系统保存的计算依赖关系。

这个 trace 设计解决了三个旧问题。它防止模型把录音设备、音量或 ASR 错误写成疾病机制；它允许状态修订真正触发重算，而不是只修改报告措辞；它使失败和回退同样可审计，包括证据缺失、引用错误、预算耗尽、超时和重新评估失败。还没有解决的是临床有效性：证据链完整不代表每个 StateCard 的医学定义已经得到医生验证，也不代表 Agent 的类别映射一定正确。

## 追加汇报：论文现在怎么写

论文摘要已经改成两个层次。第一层是已经完成的历史跨数据集评估，它证明这套 MetricEvidence 和 StateCard 架构能够覆盖多任务、多语言和多数据通道，但在 PREPARE 上仍低于 SpeechCARE，而且旧版没有 Agent 预测增益。第二层是本次重新设计的 blind-Agent pilot，它是新的方法和待验证协议，不能提前写成已经提高准确率。

Introduction 现在强调的 research gap 不是缺少另一个多模态分类器，而是现有方法没有一个同时约束预测和报告的、可机器验证的患者证据接口。SpeechCARE解决的是音频、文本和人口学表示如何动态加权；我们的重点是任务可观察性、MetricEvidence、认知状态、混杂、源片段和可修订证据链。MEDRF证明语言模型可以结合临床证据推理，但它使用更丰富的临床和影像资料；我们解决的是仅有语音时，如何先建立可靠的测量证据，再允许 Agent 判断。

Methods 按实际计算顺序写。数据部分写患者级隔离、任务和语言路由，以及 NCMMSC 只使用长语音。Evidence 部分写 raw value、direction、reference、reliability、confound、permission 和 segment provenance。State 部分写任务可观察性、支持与反证以及覆盖度。Learning 部分写折内预处理、完整 OOF、监督基础和冻结校准。Agent 部分写盲判、最多三项操作、父子 snapshot、重新评估和回退。Fusion 部分写五个臂、匹配基础和联合校准。Evaluation 同时报告区分度、校准、每类帮助与伤害、证据完整性、回退、token 和费用。

Results 目前明确标记为 historical locked evaluation。历史结果可以说明跨数据集可运行性、之前的强项和 failure modes，但不能冒充新版 Agent pilot 结果。等真实 pilot 通过后，Results 才增加三项核心结论：Agent 相对匹配基础的净增益；HC、MCI、AD 每一类的帮助和伤害；以及 Sol、Astra 等不同能力模型在同一结构化框架下的增益曲线。与 SpeechCARE 的比较只使用相同 PREPARE 测试身份、相同指标定义和冻结协议。

Discussion 不把 evidence trace 等同于临床解释。我们可以主张系统实现了可重放、可修订和可审计的计算证据链；暂时不能主张它已经获得临床因果解释，也不能主张已经超过 SpeechCARE。只有真实 pilot 给出稳定净增益，并通过每类安全和外部数据检查以后，论文才能把 Agent 写成预测贡献者，而不是方法设计。
