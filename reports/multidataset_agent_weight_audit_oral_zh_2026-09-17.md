# Agent 权重多数据集审计：中文口语汇报

上一轮只使用 ADReSS 2020，而且 Agent 是旧版只读转录的 B2。它可以检验 Agent 的独立判断是否与监督模型互补，但不能检验 Evidence ID、角色完整性和状态方向一致性。所以，上一轮得到 Agent 权重为零并不是计算错误，而是输入并没有满足提高 Agent 权重的条件。

这次增加了三组数据。ADReSS 2020 是英文图片描述，ADReSSo 是纵向进展任务，NCMMSC2021-AD 是中文 HC、MCI、AD 三分类。三组都复用缓存，不调用模型。每次只在校准病例上选择权重，再在分离病例上评价，重复五十次。

ADReSS 2020 中，仅监督模型 Accuracy 是 0.924，加入 Agent 后仍为 0.924，联合模型降到 0.916。NCMMSC 中，仅监督模型 Accuracy 是 0.792，监督加 Agent 是 0.791，完整联合模型是 0.767。这两组都把 Agent 中位权重选为零。ADReSSo progression 的 Agent-only Macro-F1 较高，但数据只有十二例，而且 decline 只有三例；加入监督模型后性能反而下降，因此不是稳定互补信号。

用户提出的六个提高 Agent 权重条件是正确的，但当前 B2 缓存只完整满足“任务类型明确”。它没有结构化角色完整性，没有合法 Evidence ID，没有读取 StateCard，也没有病例级状态方向一致性检查。在这种输入下，验证集拒绝 Agent 进入最终概率是合理结果。

因此当前部署边界应该是：监督模型权重固定为一；Agent 预测权重默认为零；Agent 仍然负责证据审查和医生报告。只有病例通过转录、角色、Evidence ID、状态一致性和语言任务校准门控，并且独立验证证明错误与监督模型互补，Agent 权重才可以提高。监督模型不确定只能触发复核，不能直接增加 Agent 权重。

这次验证可以用于排除不合适的权重，但不能证明超过 SpeechCARE。正式实验需要先把这六项条件编码成病例级门控函数，再冻结规则，在 PREPARE 同协议测试或新的外部数据集上一次性评估。
